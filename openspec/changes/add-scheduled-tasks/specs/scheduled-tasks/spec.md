# Spec Delta

## Purpose

为 JchTools 提供简洁易用的个人定时任务工具，由后台按分钟或小时周期执行用户命令，关闭界面后继续运行；支持必要的任务管理、执行控制和最近执行日志，不引入 Cron、补跑队列或其他企业级调度能力。

## ADDED Requirements

### Requirement: ST-01

JchTools MUST 采用与截图服务一致的后台运行方式，由后台负责调度和执行。关闭 GUI 不影响任务，重新打开 GUI 不重复启动调度。任务配置、启用状态和执行历史 MUST 持久保存。

#### Scenario: ST-01 关窗及重开
- **WHEN** 用户关闭 GUI，之后重新打开
- **THEN** 后台继续按计划执行任务；重开显示原配置、启用状态和历史，不重复启动调度或多执行一次

#### Scenario: ST-01 服务重启
- **WHEN** 后台服务重新启动
- **THEN** 恢复已保存的任务配置、启用状态和历史，漏跑和未完成执行按 ST-04 处理

### Requirement: ST-02

JchTools MUST 提供任务名称、执行命令、工作目录，以及「每 [正整数] [分钟／小时] 执行一次」的配置，不使用 Cron 表达式。工作目录支持手工输入和「浏览」选择文件夹，选中后显示完整路径。高级设置 MUST 包含执行 Shell、任务环境变量和超时时间，不增加额外配置项。

#### Scenario: ST-02 配置与目录选择
- **WHEN** 用户新增或编辑任务，并点击工作目录的「浏览」
- **THEN** 打开文件夹选择窗口，选中后显示完整路径；允许手工输入；选择窗口沿用 U-07 的当前目录起点，取消选择保留原值；周期仅接受正整数及分钟／小时单位

#### Scenario: ST-02 高级设置与执行
- **WHEN** 用户保存 Shell、环境变量和超时设置后执行任务
- **THEN** 后台按当次命令、工作目录和高级设置执行；任务环境变量仅作用于该任务，不修改系统环境；用户命令允许按 P-03 的限定例外联网，调度服务自身不因此联网或上传日志

### Requirement: ST-03

JchTools MUST 提供独立「定时任务」管理页面。列表显示名称、执行周期、启用状态、当前状态、上次结果和下次执行时间；支持新增、编辑、删除、启用／禁用、立即执行、停止本次执行和查看日志。运行中 MUST 禁止删除，提示先停止本次执行。

#### Scenario: ST-03 查看与管理
- **WHEN** 用户打开定时任务页面并操作任务
- **THEN** 可查看上述列表字段并使用相应管理操作；启用状态与当前执行状态分别显示，不能把禁用但仍在执行的任务显示为已停止；管理界面保持响应

#### Scenario: ST-03 删除运行中任务
- **WHEN** 用户尝试删除正在执行的任务
- **THEN** 拒绝删除并提示先停止本次执行，不通过删除暗中停止命令；本次结束后方可删除

### Requirement: ST-04

JchTools MUST 按固定周期触发，首次启用等待一个周期，支持手动立即执行。同一任务不并发，上次未结束则跳过本次，不积压；服务停机期间漏跑不补跑。禁用只停止后续调度，编辑从下一次执行生效；修改周期保留已排定的下一次触发时间，此后使用新周期。停止或超时 MUST 终止本次命令及关联子进程；服务异常退出后的未完成记录标记为「中断」。

#### Scenario: ST-04 周期与立即执行
- **WHEN** 用户启用任务或手动立即执行
- **THEN** 启用后等待一个周期再首次触发，之后按固定周期而非上次结束时间计时；空闲时可立即执行，手动执行不重置原周期计划

#### Scenario: ST-04 忙时跳过与停机漏跑
- **WHEN** 周期到点但同任务仍在执行，或服务停机期间错过触发
- **THEN** 跳过相应周期，不排队、不积压、不在结束或恢复后补跑；运行中再次手动执行同任务也不启动第二份

#### Scenario: ST-04 禁用与编辑
- **WHEN** 用户在任务运行中禁用或编辑任务，或修改已启用任务的周期
- **THEN** 禁用不停止本次执行；编辑不改变本次执行的配置和日志快照，下一次执行使用新配置；周期修改不改变已排定的下一次触发时间，从该触发点起使用新周期

#### Scenario: ST-04 停止及超时
- **WHEN** 用户停止本次执行或达到配置的超时时间
- **THEN** 终止本次命令及关联子进程后记录「已停止」或「超时」，不能只修改界面状态而留下进程；不隐式禁用后续周期调度

#### Scenario: ST-04 异常中断
- **WHEN** 服务异常退出后重新启动，发现未完成执行记录
- **THEN** 将其标记为「中断」，保留已保存的日志，不重放该次执行；无法取得的结束时间或退出码不伪造成成功结果

### Requirement: ST-05

JchTools MUST 为每个任务保留最近 100 次实际执行记录，包含手动执行。记录开始／结束时间、耗时、触发方式、状态、退出码、标准输出和错误输出，以及当次命令和工作目录。日志支持运行中查看、复制和导出；单次输出日志默认合计最多 1 MB，超限保留尾部并提示截断；淘汰旧记录时同步清理日志文件。完整命令和输出不得混入 P-10 应用诊断日志。

#### Scenario: ST-05 查看复制与导出
- **WHEN** 用户查看正在运行或已经结束的执行
- **THEN** 可查看上述信息，区分标准输出和错误输出，并复制或主动导出已保留日志；运行中持续更新已接收输出，尚未产生的结束信息不显示为最终结果；当次命令和工作目录不被之后的任务编辑覆盖

#### Scenario: ST-05 日志超限
- **WHEN** 单次输出日志超过 1 MB
- **THEN** 保留最新尾部并明确提示截断，运行中和结束后均受上限约束；复制和导出同样标明截断，不把保留内容冒充完整输出

#### Scenario: ST-05 历史淘汰
- **WHEN** 某任务实际执行超过 100 次，包含周期和手动执行
- **THEN** 只保留最近 100 次及其对应日志，旧记录与日志文件同步清理；忙时跳过和停机漏跑不算实际执行记录
