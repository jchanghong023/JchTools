# Proposal

## Why

现行影响范围门对非 Rust、未知输入或分析失败允许直接扩大至全仓，导致普通说明文档、资源或脚本变化也可能无证据触发全量，掩盖实际依赖和分析缺口。用户已明确要求修改需求和实现，以原生影响分析为先，避免随意全量。

## What Changes

- 默认直接使用未修改的上游 cargo-delta 原生发现与 Cargo 依赖图分析可信 Git 差异，按包选择并执行全部适用测试；不人为定义文件归属或全局全量规则，也不按文件后缀一概全量。
- 原生合法空范围明确报告未选出相关测试而非测试通过；分析失败、基线不可信或工具缺失明确报告失败或未验证，继续无依赖静态检查，不自动运行全仓测试或其他依赖选测结果的阶段。
- 原生合法结果可以是零包、部分包或全包；仅原生返回全包或独立显式完整验收时全量，前者报告原生证据及具体原因或路径，后者报告显式完整验收原因；不将正常原生全量误称兜底。保留现有离线、授权、真实资产和测试执行约束。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `application-contract`：更新 P-12 的影响分析、全量范围和失败结果语义，保留其余验收约束。

## Impact

影响本地三级门的范围选择、诊断和相关文档；不改变 Rust 产品功能、已有测试断言、独立完整验收、发布或网络授权边界。不引入覆盖率选测、结果缓存、私有 cargo-delta 补丁或第二套依赖分析算法。原生发现是尽力分析，对根外动态输入等不承诺完全覆盖；未选中范围不能视为其行为已经测试验证，已知缺口应如实指出，不作为每轮全量的默认理由。

## Acceptance Boundaries

可验收受影响包少于全仓、合法零包、原生确认的真实全局影响和分析失败四种结果；每种结果须如实报告，完整验收与影响范围通过不得混淆。无待决问题。
