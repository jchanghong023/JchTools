# Proposal

## Why

用户明确要求 fulltest 不联网、使用本地引擎，并相应修改需求和实现。现有测试引擎准备会查询最新发布并可能下载，媒体夹具缓存缺失时也会下载；这与离线执行目标冲突。

## What Changes

- fulltest 的选测、构建、测试及前置准备均不访问外网、不查询最新发布、不下载或安装依赖，只使用离线 Cargo 元数据和缓存及已校验的本地测试引擎、媒体资产；缺失或损坏如实报告失败或未验证。
- 保持影响范围选测、真实产品链路与断言、独立授权、资源隔离、失败后继续和聚合报告，不恢复覆盖率选测或结果缓存。本机回环、命名管道和本地 Git 协议测试仍可执行。
- 从 fulltest 移出的真实外网测试、官方最新发布查询及下载或在线准备迁入 slowtest，保留原断言和失败判据，不删除或弱化联网验证；已有在线供应链审计保持不变。
- 打包时选取最新正式引擎、slowtest 在线供应链审计和发布资产获取，以及独立授权的最新发布对照仍按原规则执行；最新对照不再是每轮 fulltest 的前置条件。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `application-contract`：明确 fulltest 离线边界、资产校验及缺失时报告，同时保持三级门与交付验收边界。
- `shared-inference`：明确 fulltest 使用固定本地测试引擎的离线例外，保留打包与独立最新发布对照规则。

## Impact

影响本地测试门、影响分析和测试引擎及媒体夹具准备的需求与实现，不改变 Rust 产品行为或测试断言。fulltest 的通过仅证明本轮已执行的受影响非打包范围；未具备本地前置条件不得冒报通过。slowtest 的在线审计和实际交付以及门外独立授权验收不因本变更取消或并入 fulltest。批准依据为用户本次明确指令；无待决问题。
