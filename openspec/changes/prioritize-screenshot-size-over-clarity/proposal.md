# Proposal

## Why

当前截图复制在有限减色和宽高缩至原来的 50% 后，仍受每边至少为原边长与 64 像素较小值的可读性底线约束；无法满足设置上限时提示「图片在可读性底线内仍超过大小上限」。用户明确要求优先满足大小上限，允许影响文字清晰度，不再因该底线而失败。

## What Changes

- 保留原尺寸无损、有限减色以及逐步等比缩图的优先顺序；已有候选达标时不额外降质。
- 仍超限时允许继续缩小，取消原有 50% 比例和 64 像素可读性底线；文字变糊不作为终止条件。
- 降质过程必须有界且支持取消，最多缩至 1×1 像素；成功仍以完整可解码 PNG 的精确编码字节数不超过上限为准。
- 不再出现因可读性底线而要求提高上限或缩小截图区域的错误。只有连最小尺寸有效 PNG 都无法容纳的极低上限，才按无法容纳有效图片明确失败；编码、捕获、剪贴板失败和取消仍如实反馈。
- 不增加设置项，不自动改变用户上限，不发布超限图片，不切换格式，不默认转灰度或裁剪内容。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `screenshot-ocr`：修改 O-40，将可读性底线改为优先满足大小的有界降质；保留 O-38/O-39/O-41～O-44 的有效 PNG、精确大小、后台取消、剪贴板和隐私边界。

## Impact

- 需求影响：`openspec/specs/screenshot-ocr/spec.md` 的 O-40 与既有「达到降质底线仍超限则失败」语义冲突，需批准后替换该语义。
- 后续产品影响：`optional/snap-ocr-worker/src/image_copy.rs` 及相关压缩回归用例，README 图片复制策略说明；无新增依赖或外部服务。
- 验收边界：原先因 50%/64 像素底线失败但更小有效 PNG 能达标的输入应成功，输出可解码且不超限；原尺寸已达标时仍保持原尺寸原色；极低上限不得伪造成功；取消不得发布旧结果。
- 未决问题：无。允许清晰度下降不等于承诺任意正字节上限都可容纳有效 PNG。
- 当前仅形成需求提案和增量规格，不修改产品实现或已批准需求基线；需求变更等待用户确认。
