# Spec Delta

## MODIFIED Requirements

### Requirement: O-40

JchTools MUST 优先保持原分辨率及颜色，先尝试较高等级无损 PNG；超限后尝试有限减色，再在仍超限时保持宽高比逐步缩小。每个候选实际编码后检查字节数，在达标候选中优先可读性，尽量保留文字、数字、细线和彩色标记；不得改写内容或默认转为灰度。仍超限时 MUST 优先满足设置大小，允许影响文字清晰度，继续缩小至达标或 1×1 像素，不得因原有 50% 比例、64 像素或可读性底线停止。处理必须有明确迭代限制并支持取消，不返回或发布超限图片；极低上限无法容纳最小尺寸有效 PNG 时明确失败。

#### Scenario: O-40 原尺寸与颜色优先
- **WHEN** 原分辨率、原颜色的高等级无损 PNG 候选已经满足上限
- **THEN** 保留原尺寸及像素颜色，不为追求更小体积继续减色或缩图；不要求恰好用满设置上限，也不通过裁掉选区内容满足上限。

#### Scenario: O-40 逐级处理与可读性
- **WHEN** 原尺寸无损编码超限，有限减色后仍可能超限
- **THEN** 先评估有限减色候选，仍无达标候选时才逐步降低分辨率；每个候选重新编码并按实际 PNG 长度判断。缩放覆盖完整选区、保持宽高比，仅允许整数像素取整误差及每边至少为 1 像素的取整，不拉伸或裁剪；选择优先保留文字、数字、细线和彩色标记可读性的达标候选，不凭最小文件或最低颜色数作为质量更好的证据。

#### Scenario: O-40 允许突破原可读性底线
- **WHEN** 原尺寸减色以及原宽高 50% 以内的既有缩图候选仍超限，或继续缩小会使某边低于原边长与 64 像素中的较小值，而更小候选能够满足上限
- **THEN** 自动继续缩小直至得到达标候选，允许文字模糊，不要求用户提高上限或重新框选；结果必须为完整可解码 PNG，编码字节数小于或等于用户设置，返回尺寸与解码结果一致。不得仅删除错误提示、发布超限图片或伪造成功。

#### Scenario: O-40 极低上限和降质底线
- **WHEN** 有效正上限过低，已经缩至 1×1 像素并尝试允许的编码候选，仍无法容纳有效 PNG
- **THEN** 有限结束并明确提示「设置的大小上限无法容纳最小 PNG 图片」等真实原因，不显示因可读性底线而失败的提示，不无限尝试，不返回或发布超限图片；编码失败仍明确报错，不以空字节或不完整 PNG 作为成功。迭代上限、最小尺寸和减色边界必须在实施交付中明确；迭代预算须足以从有效输入尺寸继续缩至 1×1 像素，而非以预算用尽恢复原有可读性限制。

#### Scenario: O-40 深度缩图期间取消
- **WHEN** 图片处理进入突破原可读性底线的缩图阶段，用户取消任务或任务失效
- **THEN** 沿用 O-41 的后台取消及迟到结果隔离，不发布本次图片，不覆盖后续剪贴板内容，不显示复制成功。
