# Spec Delta

## MODIFIED Requirements

### Requirement: O-01

JchTools MUST 遵守本条行为：在 JchTools 统一工具注册表与左侧导航保留第六个独立工具「截图 OCR」，提供真实 Slint 功能页；按 XB-24 提供 OCR 与「截图并复制图片」快捷键、最大图片大小设置及后台服务状态。随包资产自动发现，离线检查和故障恢复集中到设置页，不要求用户下载或手动配置截图组件；热键截图与托盘仍可独立使用，不要求主窗口或该页面保持打开。

#### Scenario: O-01 完整行为与适用边界
- **WHEN** 用户使用截图 OCR、截图复制、其后台、结果窗口或 jchocr 图片识别入口，且涉及本条规定的条件
- **THEN** 在统一工具注册表与左侧导航保留独立「截图 OCR」工具及真实 Slint 页面，按 XB-24 提供两种用途的快捷键、最大图片大小设置和后台状态；离线检查及故障恢复仍集中到设置页，不新增另一个截图工具或要求主窗口保持打开。OCR 输出仍只是一份布局保真纯文本；图片复制仅按 O-38～O-45 输出普通 PNG 图片剪贴板。两者均不增加 Markdown 转换、阅读顺序模式、翻译、润色、截图历史或自动保存结果，随包资产仍自动发现且不要求用户下载或手动配置。

### Requirement: O-14

JchTools MUST 保留截图 OCR 默认全局热键 `Ctrl+Alt+O`，并为「截图并复制图片」提供独立可设置的全局热键；两者均在现有截图设置区域通过按键录制修改。替换热键时先成功注册新组合，再释放旧组合；冲突时保留原设置和旧热键并明确提示，不让同一组合同时触发两个用途。

#### Scenario: O-14 完整行为与适用边界
- **WHEN** 用户使用截图 OCR、其后台、结果窗口或 jchocr 图片识别入口，且涉及本条规定的条件
- **THEN** OCR 默认全局热键仍为 `Ctrl+Alt+O`，可在设置中通过按键录制修改；先成功注册新组合，再释放旧组合，冲突时保留原设置和旧热键并明确提示。每个当前用户会话仅一个截图服务实例；重复启动截图服务通知已有实例打开设置，不加载第二套模型。此行为不改变 JchTools 其他工具自身的启动规则。

#### Scenario: O-14 图片复制独立热键与冲突保护
- **WHEN** 用户保存「截图并复制图片」快捷键，组合与 OCR 热键相同、被其他程序占用或注册失败
- **THEN** 明确指出冲突或失败，不声称新快捷键已生效，不丢失原有效热键或持久设置；OCR 热键继续触发识别，已生效的复制热键只触发图片复制。成功注册并保存后显示实际生效组合，不能把尚未收到注册确认的组合显示为已生效。

### Requirement: O-15

JchTools MUST 遵守本条行为：登录自启默认关闭，由用户显式启用或关闭，仅管理当前用户本功能启动项，关闭不删除其他应用的值；启用后登录时后台启动，无需主窗口。现有截图设置增加「截图并复制图片」快捷键及「最大图片大小」，仅在用户保存时持久化，保存成功后立即用于后续截图并在重启后恢复；界面明确 `1 KB = 1000 字节`，内部统一以最终 PNG 字节数判断上限。

#### Scenario: O-15 完整行为与适用边界
- **WHEN** 用户使用截图 OCR、其后台、结果窗口或 jchocr 图片识别入口，且涉及本条规定的条件
- **THEN** 登录自启默认关闭，由用户显式启用或关闭，仅管理当前用户本功能启动项，关闭不删除其他应用的值；启用后登录时后台启动，无需主窗口。服务位置改变后重新运行时更新本功能已启用路径，移动或删除前应关闭自启。快捷键在截图页面配置并显示后台状态；登录自启、离线资产检查与模型重试在统一设置页管理，托盘保留对应入口，不开放 OCR 阈值等高级参数。截图设置仅在用户保存时持久化，损坏时使用内存默认值并提示，不静默覆盖原文件；共享 Xberg 目录、FFmpeg 与音频模型等可选资产状态及相关设置的持久化与恢复统一遵循 XB-18 / XB-20 / XB-21，资产边界与路径事务按 XB-27，不保留三功能勾选。新装或解包后无 SQLite、无旧配置也必须自动发现包内目录，不以已下载 FFmpeg 和音频模型为前提；旧配置读取或安全迁移遵循 XB-21，不删除用户目录及有效资料，不以旧目录、旧缓存或既往功能选择作为使用随包截图资产的前提。

#### Scenario: O-15 大小设置即时生效与跨进程恢复
- **WHEN** 用户在截图页面保存有效「最大图片大小」及图片复制快捷键，之后发起新截图，或完全退出后台并由新进程启动
- **THEN** 后续截图采用新生效设置，新进程恢复相同上限及快捷键；不能只用当前进程缓存证明持久化。在途任务使用触发时已生效的设置，不随设置编辑改变判定口径。界面显示当前生效值及 `1 KB = 1000 字节`；例如用户主动设置 200 KB 时按 200000 字节判断，该示例不确定产品默认值。

#### Scenario: O-15 无效输入及保存失败
- **WHEN** 用户输入空值、非数值、非正数、无法精确转换为有效字节数的值或导致内部字节数溢出的值，或保存设置失败
- **THEN** 明确提示具体输入或保存问题，不把无效值用于截图，不把未成功保存的值显示为已保存，不覆盖原有效设置；旧版本缺少新增字段时保留已有 OCR 设置，损坏配置的读取继续不静默覆盖原文件。可表示但极小的正上限若无法产出达标 PNG，按 O-40 明确失败，而不是输出超限图。

#### Scenario: O-15 隐藏图像编码细节
- **WHEN** 用户配置或日常使用截图复制
- **THEN** 用户只需设置复制快捷键与最大图片大小，不要求理解或选择 PNG 压缩等级、调色板、缩放算法，也不要求每次选择格式或质量；新复制热键及上限的实际初始值必须明确显示，不能把需求示例冒称为用户已确定的默认值。

### Requirement: O-19

JchTools MUST 保持截图请求串行：同一时刻只允许一个截图任务，OCR 与图片复制在有效选区完成后按用途分流；图片复制不依赖 OCR 模型就绪、不提交识别请求或进入 OCR 推理队列。忙时再次触发只提示当前阶段，不排队、不取消已有任务。OCR 的识别、取消及与转换并用的原有边界不变。

#### Scenario: O-19 完整行为与适用边界
- **WHEN** 用户使用截图 OCR、其后台、结果窗口或 jchocr 图片识别入口，且涉及本条规定的条件
- **THEN** 同一时刻只允许一个截图任务；识别中再次按热键只提示「正在识别」，不排队、不取消已有任务。识别时显示「正在识别…」和取消按钮，Esc 同样取消；取消在当前不可中断 ONNX 调用返回后的瓦片或识别批次检查点生效，用户主动取消不作为错误，不伪造百分比。该单任务限制只约束截图请求；与转换并用及取消隔离分别见 XB-15 / XB-17。

#### Scenario: O-19 图片复制绕过模型状态与推理队列
- **WHEN** 复制用途取得有效选区，OCR 模型未加载、加载中、加载失败或已经就绪
- **THEN** 选区直接交给图片处理分支，不在 OCR 模型状态判断中等待或失败，不提交 Xberg 或 `Work::Recognize` 请求；模型不就绪不影响复制分支的压缩和剪贴板能力。后续 OCR 任务仍使用未经复制分支减色、缩放的原始选区，不因图片上限改变检测、识别或布局结果。

#### Scenario: O-19 图片处理忙态与取消
- **WHEN** 用户在框选或图片后台处理中再次触发任一截图热键，或取消当前复制任务
- **THEN** 重复触发仅提示「正在框选」或「正在处理图片」等真实阶段，不增加队列、不启动第二个框选或覆盖已有任务；图片处理中有可操作的取消入口并支持 Esc，取消反馈与错误区分，后续迟到结果按 O-41 丢弃，不误报复制成功。

### Requirement: O-20

JchTools MUST 遵守本条行为：新截图前隐藏旧 OCR 结果并仅在内存中暂存；新 OCR 任务取消、识别为空或失败时恢复旧结果，OCR 成功后才替换。图片复制不生成、清空或替换 OCR 正文；为截图隐藏的旧 OCR 结果在复制任务结束或取消后恢复。

#### Scenario: O-20 完整行为与适用边界
- **WHEN** 用户使用截图 OCR、其后台、结果窗口或 jchocr 图片识别入口，且涉及本条规定的条件
- **THEN** 新截图前隐藏旧结果并仅在内存中暂存；新 OCR 任务取消、识别为空或失败时恢复旧结果，OCR 成功后才替换。无文字、截图失败和 OCR 失败分别给出简短明确提示，不打开空白结果窗；失败状态不得携带原图或识别正文作为诊断内容。

#### Scenario: O-20 图片复制不占用 OCR 结果
- **WHEN** 已有 OCR 结果后执行截图复制，复制成功、失败或被用户取消
- **THEN** 不用图片处理结果替换 OCR 文字，不打开新的 OCR 结果窗，不因复制任务清空旧正文；仅为捕获而隐藏的旧结果在任务结束后恢复，仍只在内存暂存，不形成截图历史。

## ADDED Requirements

### Requirement: O-38

JchTools MUST 提供「截图并复制图片」快捷键入口，复用 O-17 的 GDI 捕获和 O-18 的冻结框选。有效框选完成后自动压缩并复制，无需额外保存、压缩或复制按钮；只有最终 PNG 达标且剪贴板写入成功才显示包含实际大小和上限的简短成功提示。取消与各类失败必须明确反馈，不得误报成功。

#### Scenario: O-38 快捷键框选后自动复制
- **WHEN** 用户按已生效的复制快捷键，拖动框选并松开左键提交有效选区
- **THEN** 使用鼠标所在显示器的冻结物理像素和原有坐标、DPI、隐藏窗口规则；自动后台处理并写入普通图片剪贴板，用户无需选择格式、质量或点击额外按钮。成功时显示例如「已复制，187 KB，上限 200 KB」的简短提示，展示值来自实际最终 PNG 字节数，是否成功始终按精确字节判定，不按显示舍入值判定。

#### Scenario: O-38 框选取消与捕获失败
- **WHEN** 用户按 Esc、右键取消、选区任一边小于 8 像素，或 GDI 捕获 / 裁剪失败
- **THEN** 沿用冻结框选的取消及失败边界，明确显示已取消或截图失败，不进入图片发布、不修改剪贴板，也不显示成功提示；底层桌面变化不能改变被冻结的选区内容。

#### Scenario: O-38 普通图片粘贴
- **WHEN** 复制任务成功后用户切到支持普通图片粘贴的浏览器网页并按 Ctrl+V
- **THEN** 粘贴得到图片而非路径、文件粘贴条目或 Base64 文本，不要求浏览器扩展、上传动作或额外文件；浏览器及网页的重新编码和大小边界按 O-44 记录，不以本地成功提示宣称上传大小达标。

### Requirement: O-39

JchTools MUST 新增独立 Rust 图像处理模块，接收选区像素和本次生效设置，成功返回最终 PNG 字节、宽高及实际字节数。成功输出必须可解码，返回尺寸与解码结果一致、返回字节数与 PNG 编码长度一致，且编码长度小于或等于设置上限；上限不指分辨率、位图大小或剪贴板总内存。

#### Scenario: O-39 不同图像的成功合同
- **WHEN** 使用小图、大图、文字表格、细线图和彩色复杂图分别进行图片处理且返回成功
- **THEN** 每张输出均是可解码的完整 PNG，返回宽高与解码宽高一致、实际字节数等于最终编码长度，实际字节数不超过本次设置；不能仅修改 PNG 压缩参数而略过最终长度校验。

#### Scenario: O-39 精确字节边界
- **WHEN** 候选 PNG 长度恰好等于设置上限，或仅超过上限一字节，即使两者显示为相同 KB 值
- **THEN** 等于上限的候选符合体积条件，超出一字节的候选仍不合格，必须继续有界处理或明确失败；不能用 PNG 压缩等级、缩放比例、显示舍入值、CF_DIB 大小或剪贴板总内存替代编码长度。

#### Scenario: O-39 编码失败
- **WHEN** 图像处理或 PNG 编码发生错误
- **THEN** 返回明确失败而非部分 PNG 或成功占位结果，不写入剪贴板、不误报已复制；错误反馈与日志不得附带图像、Base64 或截图正文。

### Requirement: O-40

JchTools MUST 优先保持原分辨率及颜色，先尝试较高等级无损 PNG；超限后尝试有限减色，再在仍超限时保持宽高比逐步缩小。每个候选实际编码后检查字节数，在达标候选中优先可读性，尽量保留文字、数字、细线和彩色标记；不得改写内容或默认转为灰度。处理必须设置明确迭代限制与最低允许尺寸，达到降质底线仍超限则失败。

#### Scenario: O-40 原尺寸与颜色优先
- **WHEN** 原分辨率、原颜色的高等级无损 PNG 候选已经满足上限
- **THEN** 保留原尺寸及像素颜色，不为追求更小体积继续减色或缩图；不要求恰好用满设置上限，也不通过裁掉选区内容满足上限。

#### Scenario: O-40 逐级处理与可读性
- **WHEN** 原尺寸无损编码超限，有限减色后仍可能超限
- **THEN** 先评估有限减色候选，仍无达标候选时才逐步降低分辨率；每个候选重新编码并按实际 PNG 长度判断。缩放覆盖完整选区、保持宽高比，仅允许整数像素取整误差，不拉伸或裁剪；选择优先保留文字、数字、细线和彩色标记可读性的达标候选，不凭最小文件或最低颜色数作为质量更好的证据。

#### Scenario: O-40 极低上限和降质底线
- **WHEN** 有效正上限过低，或已经达到明确规定的迭代上限、减色底线或最低允许尺寸仍没有达标 PNG
- **THEN** 有限结束并提示「请提高上限或缩小截图区域」等明确反馈，不无限尝试、无限缩小，不越过已规定的降质底线，也不静默返回或发布超限图片。迭代上限、最低允许尺寸及减色边界必须在实施交付中明确，不能留作运行期无限探索。

### Requirement: O-41

JchTools MUST 将图片压缩放在后台执行，不长时间阻塞窗口、托盘或消息循环。任务取消、失效或结束后，迟到结果不能发布；处理及剪贴板有界重试期间用户复制了新内容时，不得由旧任务覆盖。发布前必须确认任务仍有效且没有用户后续复制取代本次操作；迟到回执不得覆盖后续任务状态或伪造成功。

#### Scenario: O-41 后台处理保持响应
- **WHEN** 大选区正在压缩或等待有界剪贴板重试
- **THEN** 主窗口、托盘及消息循环保持可交互，取消请求可被接受，不以 UI 线程等待整个编码或长时间持有剪贴板实现同步；不可中断的当前处理返回后在安全检查点丢弃已取消结果。

#### Scenario: O-41 取消及新任务的迟到保护
- **WHEN** 任务 A 已取消或失效，之后任务 B 被接受，而 A 的处理结果或复制回执迟到
- **THEN** 丢弃 A 的图像结果和旧状态回执，不清空或覆盖 B 的状态、成功提示或剪贴板，不把 A 显示为复制成功。

#### Scenario: O-41 用户新复制内容优先
- **WHEN** 本次截图处理开始后、发布前用户在其他程序或本应用中复制了新内容，包括剪贴板占用重试期间
- **THEN** 旧截图任务不得清空或替换这些新内容，结束本次发布并给予明确的已失效 / 未复制反馈，不显示已复制；不能只检查任务取消标志而忽略用户后续剪贴板变更。

### Requirement: O-42

JchTools MUST 通过 Windows 注册剪贴板格式 `PNG` 写入已完成压缩和体积校验的最终 PNG 字节，不得只发布解码位图。可选 CF_DIB / CF_DIBV5 必须来自同一最终处理图像，其内存不受 PNG 上限约束。完成编码、校验和全部待发布内存准备后才短暂打开剪贴板；占用采用有界重试，正确处理所有句柄的所有权移交及失败释放，不提前发布未压缩原图。

#### Scenario: O-42 读取 PNG 原始编码
- **WHEN** 接收程序读取工具注册的 `PNG` 剪贴板格式
- **THEN** 取得本次已达标的完整最终 PNG 编码字节，内容与图像模块成功返回的 PNG 一致，不是 CF_DIB 包装、普通位图或原图重新编码的替代结果；该编码长度仍满足本次上限。

#### Scenario: O-42 可选位图格式一致性
- **WHEN** 工具同时发布 CF_DIB 或 CF_DIBV5 以兼容桌面软件
- **THEN** 位图的尺寸及像素来自同一最终处理后的图像，不提供原始大图作为兼容版本；这些位图格式可占用比 PNG 更多内存，不因此判定 PNG 超限，也不把它们的大小报告为 PNG 大小。

#### Scenario: O-42 短暂占用及有限失败
- **WHEN** PNG 已编码达标且待发布内存准备完成，工具尝试打开剪贴板但遇到占用
- **THEN** 仅在此时尝试打开，按明确的有限重试次数或期限重试，重试前继续检查任务及用户后续复制有效性；耗尽后明确提示占用或复制失败，不无限等待、不持有剪贴板进行编码或缩放，不误报成功。成功打开前不清空现有内容，不先发布原图再异步替换。

#### Scenario: O-42 句柄移交及原生失败
- **WHEN** 格式注册、内存分配 / 锁定、打开 / 清空剪贴板或数据写入失败，或某个待发布格式未写入成功
- **THEN** 关闭已打开的剪贴板，释放仍归本应用所有的内存及窗口资源，不重复释放已成功移交系统的句柄；明确反馈失败，不把失败或部分写入冒充完整成功，不发布超限 PNG 或原始大图。不得假称 Windows 剪贴板支持失败事务回滚或承诺一定恢复被清空的旧内容。

### Requirement: O-43

JchTools MUST 使截图复制的捕获、裁剪、压缩及编码全程驻留内存，不生成临时截图文件，不把图片、Base64 或截图正文写入日志、数据库、错误报告或历史；任务结束或取消后释放本次图像引用。产品处理逻辑使用 Rust，优先复用现有 GDI、Slint 和 Rust 图像依赖，不引入 Python 或外部图片压缩命令，不增加文件粘贴、扩展、自动上传、截图历史或水印处理。

#### Scenario: O-43 成功失败均不落盘
- **WHEN** 截图复制成功、失败、取消或诊断错误
- **THEN** 不创建临时图片或内容缓存，不把图像、Base64、截图正文写入应用日志、设置文件、任务数据库或历史；只记录 P-10 允许的去敏运行元信息。图片仅在当前任务内存与成功移交的系统剪贴板中使用，结束后释放应用持有的引用，不借错误路径保留截图。

#### Scenario: O-43 系统剪贴板边界
- **WHEN** 图片成功交给 Windows 剪贴板，之后任务结束或应用退出
- **THEN** 不主动清空系统剪贴板，不声称控制 Windows 剪贴板历史、分页文件或原生库释放内存的安全擦除；该边界不允许应用自身增加内容落盘或截图历史。

### Requirement: O-44

JchTools MUST 仅承诺本工具生成的最终 PNG 字节不超过设置上限，并支持普通 Ctrl+V 图片粘贴；不得承诺任意浏览器、任意网页最终上传均受该上限约束。兼容性验收必须区分工具生成 PNG、浏览器粘贴事件接收图片、网页实际上传图片三种字节数，记录目标浏览器版本、网页组合和重新编码结果，不以本地达标代替后两项达标。

#### Scenario: O-44 三种大小与 multipart
- **WHEN** 在目标浏览器及网页验证截图图片粘贴和用户发起的上传
- **THEN** 分别记录生成 PNG 的字节数、粘贴事件收到的图片字节数、实际上传图片部分的字节数；若请求使用 multipart，同时区分图片部分与整个请求的封装开销，不把总请求长度当作图片长度，也不把浏览器中一个大小推算成另两个大小。

#### Scenario: O-44 Chromium 与 Firefox 重新编码
- **WHEN** 分别在 Chromium 系浏览器、Firefox 与目标网页组合中进行获授权的兼容性验收
- **THEN** 依据实际版本记录普通 Ctrl+V 是否正常、是否保留原 PNG 编码或发生解码再编码、三种大小是否分别达标；Chromium 优先读取 PNG 及 Firefox 可能重新编码作为待核验兼容性关注点，不作为永远不变的保证。Firefox 或网页重新编码后超限时如实记录限制，不暗中改用文件粘贴或浏览器扩展，不将本地成功提示解释成上传达标。

#### Scenario: O-44 未执行或无法观察上传
- **WHEN** 缺少目标浏览器、网页、上传观察条件或当次桌面 / 浏览器授权
- **THEN** 对相应浏览器 / 网页组合及不可观察的大小分别标为「未验证」，不以编译、单元测试、隔离剪贴板测试或其他网页的成功冒充端到端通过；产品不为验证边界新增自动上传。

### Requirement: O-45

JchTools 的本功能交付 MUST 按仓库当次授权执行最小充分的相关验证，并报告实际修改模块、最终压缩策略及有限边界、用户设置与截图粘贴入口、执行命令和结果、浏览器 / 网页组合及限制。成功、关键失败、设置恢复、OCR 隔离与内存隐私的验收要求不得被仅编译通过或独立演示程序代替，未执行部分明确为「未验证」。

#### Scenario: O-45 行为覆盖与证据边界
- **WHEN** 实施完成后进行本功能验收和交付
- **THEN** 覆盖设置修改及跨进程恢复、输入错误与热键冲突，O-39 的五类图像与字节边界，极低上限、取消、编码错误、剪贴板占用及迟到保护，真实框选后自动复制和 Ctrl+V，模型未就绪下的复制与 OCR 原始输入不变，以及全程内存隐私；使用隔离环境及合成数据，临时验收数据遵守仓库 `.tmp/` 规则。按实际执行记录命令、退出码、关键结果和未验证范围，自动化结果不代替真实桌面、模型或浏览器证据。

#### Scenario: O-45 授权与交付说明
- **WHEN** 验收涉及 fulltest / slowtest、真实桌面、浏览器、真实模型、远程流水线或发布等受限操作
