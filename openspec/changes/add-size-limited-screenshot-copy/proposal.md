# Proposal

## Why

用户需要一次设置图片大小上限，之后通过「快捷键 → 冻结框选 → 浏览器 Ctrl+V」完成截图粘贴，无需保存图片或手动选择压缩参数。现有截图能力面向 OCR：框选产物进入模型状态判断和识别队列，剪贴板接口仅复制识别文本；现有内存 PNG 编码没有最终字节数上限，也没有普通图片剪贴板输出。

本变更新增独立于 OCR 推理的截图复制分支，严格控制本工具生成的最终 PNG 字节数，不把本地编码结果误当作浏览器收到或网页上传的图片大小。

## What Changes

- 在现有「截图 OCR」页面的截图设置区域增加「截图并复制图片」独立快捷键和可输入、持久保存的「最大图片大小」，显示 `1 KB = 1000 字节`。有效设置保存后立即用于后续任务；每次任务使用触发时的生效设置。无效输入、热键冲突和保存失败有明确反馈，不破坏已有有效设置及 OCR 快捷键。
- 复用现有 GDI 捕获、冻结框选和 Slint 页面。松开左键完成有效框选后自动后台压缩并复制，取消方式和选区最小边长沿用 O-18；不增加保存、压缩、复制确认步骤，不弹出 OCR 结果窗。
- 新增独立 Rust 图像处理模块：输入选区像素与本次设置，成功返回最终 PNG 字节、宽高及实际字节数。按高等级无损 PNG、有限减色、保持宽高比逐步缩小的顺序处理；每个候选均以实际编码字节判断，优先可读性，不默认灰度化、不改写内容。处理有明确迭代上限和最低允许尺寸，达到底线仍超限则失败并提示提高上限或缩小选区。
- 在 Windows 注册剪贴板格式 `PNG`，直接发布已达标的最终编码字节，而非仅发布解码后的位图。可选的 CF_DIB / CF_DIBV5 必须来自同一最终处理图像，其内存大小不受 PNG 字节上限约束。编码、校验及内存准备完成后才短暂打开剪贴板，以有界重试处理占用；正确处理句柄所有权及失败释放，不提前发布原图。
- 仅当最终 PNG 达标且剪贴板写入成功后显示简短成功提示，包含实际大小及上限；取消、编码失败、无法达到上限和剪贴板占用等情况不得误报成功。取消、失效或被后续操作取代的任务不得用迟到结果覆盖新任务或用户新复制的内容。
- 保留截图 OCR 入口、默认热键、模型和原始图像输入。图片复制不等待 OCR 模型就绪、不提交 Xberg 请求、不进入 OCR 推理队列；模型失败不能把图片复制显示为不可用。沿用既有截图请求串行交互，不增加任务队列；忙态明确区分框选、识别和图片处理。
- 产品截图、压缩及复制全程内存处理，最终格式固定为 PNG；不生成临时截图文件，不把图像、Base64 或截图正文写入日志、数据库或历史。不增加文件粘贴模式、浏览器扩展、自动上传、截图历史或水印处理。

## Capabilities

### New Capabilities

无。复用已有截图功能域，不创建另一个工具、独立截图后端或宽泛的新能力目录。

### Modified Capabilities

- `screenshot-ocr`：扩展 O-01 的页面与输出范围、O-14 的双热键、O-15 的截图设置、O-19 的截图任务分流、O-20 的 OCR 结果保留边界；新增截图复制、按 PNG 字节限额处理、普通图片剪贴板、取消及迟到结果保护、内存隐私和浏览器验收要求。保留未修改的 OCR 行为与既有编号。
- `shared-inference`：收窄 XB-05 的「全部功能」为推理请求，明确图片复制不经过 Xberg；调整 XB-22 的截图复制可用性与模型就绪隔离，以及 XB-24 的页面设置范围。共享引擎的唯一性、OCR 模型隔离、随包交付、统一设置和后台退出边界不变。

## Impact

### 现有依据与涉及范围

已只读核对：

- `optional/snap-ocr-worker/src/capture_win.rs` 的 `BgrImage` 和内存 PNG 编码，以及 `capture_win/overlay.rs` 的冻结框选、取消与 BGR 裁剪；无需更换 GDI 后端。
- `optional/snap-ocr-worker/src/service/tasks.rs` 的 `Command::Image` / `handle_image`：目前按模型状态等待、分派 `Work::Recognize` 或报模型未就绪；新复制用途必须在该模型判断之前分流。
- `optional/snap-ocr-worker/src/service/clipboard.rs`：目前只写 CF_UNICODETEXT，已有 message-only owner 窗口及 Win32 内存所有权处理，但没有 PNG 发布和占用重试。
- `optional/snap-ocr-worker/src/service/settings.rs`、截图热键测试、独立 window station 剪贴板测试，以及 `crates/gui/src/gui/snap_ocr.rs`、`ui/pages/snap.slint`、`ui/pages/settings.slint`、`ui/app.slint`：现有截图热键经显式保存和后台回执生效，截图设置使用独立 JSON 文件；共享 Xberg 配置的 SQLite 规则不变。
- `optional/snap-ocr-worker/Cargo.toml` 已使用 `image` 的 PNG 功能、Slint 和 `windows-sys`。优先复用现有依赖；确需新增 Rust 依赖须在实施交付中说明现有依赖不能满足的需求，不引入 Python 或外部图片压缩命令。
- `openspec/specs/screenshot-ocr/spec.md`、`shared-inference/spec.md` 和应用全局的 R-01 / P-10 / U-10：现有「只输出纯文本」「页面仅快捷键与状态」「全部功能经 Xberg」与新增行为存在文字冲突，由本变更的 delta 显式调整，不以实现覆盖已批准要求。全局持久化例外及不记录截图内容的边界无需放宽。

### 验收边界

以下为未来实施的验收要求，不是本轮执行结果：

- 设置：有效修改用于后续截图，完全退出并由新进程恢复相同设置；无效输入、整数换算溢出、保存失败、与 OCR 或外部程序的快捷键冲突均不损坏原有效值。
- 编码：小图、大图、文字表格、细线图和彩色复杂图的成功结果均能解码为 PNG，返回宽高及字节数与实际输出一致，实际 PNG 字节数不超过本次上限；验证恰好等于上限和仅超出一字节的判断边界。
- 失败与隔离：极低上限、取消、编码错误、剪贴板占用、任务失效和处理期间用户重新复制的情形不误报成功、不发布不合格结果；模型未加载、加载中或失败不阻止图片复制，OCR 原始选区不被减色或缩放。
- 真实交互：冻结框选后自动复制，普通 Ctrl+V 可取得图片，无额外按钮；应用不生成临时截图文件或内容历史。合成数据、临时验收产物与隔离方式遵循仓库规则。
- 浏览器：分别记录本工具生成的 PNG 字节数、粘贴事件收到的图片字节数、网页实际上传的图片字节数；multipart 的整个请求大小与图片部分分别记录。记录浏览器版本、网页组合及是否重新编码，不把第一项替代后两项。
- Chromium 优先使用现有 PNG、Firefox 可能解码再编码是本次兼容性关注点，不是已核验的当前版本事实。实施时应以实际目标版本和网页验证；网页也可能重编码。不承诺任意浏览器和网页最终上传始终达标，不能暗中转为文件模式。
- 所有验证继续遵守当次授权：真实桌面、浏览器、模型及其他受限路径不由提案自动授权；缺环境或未执行项标为「未验证」，编译与单元测试不能替代桌面 / 浏览器端到端验收。

### 未固定参数与非目标

- `200 KB` 只是示例，不是已批准默认值。本提案不固定新复制快捷键的默认组合或最大图片大小的数值默认值；实施审阅需明确实际初始值及其 UI 展示，不能把示例冒充用户选择。现有 OCR 默认 `Ctrl+Alt+O` 不变。
- 具体量化库、缩放算法、迭代次数、最低允许尺寸及剪贴板重试次数不在需求阶段指定；实现必须明确给出有限边界，并证明底线失败不会发布超限图，不以无限缩小换取表面成功。
- CF_DIB / CF_DIBV5 为可选兼容格式，不要求引入；提供时受同图一致性约束。
- 本提案在需求阶段仅创建 `proposal.md` 与两个 capability delta specs；用户于 2026-11-05 批准按提案实施。已批准需求同步回对应能力基线，产品实现与可信基按仓库规则独立提交；不创建设计或任务文档，不自动归档。实施交付另行报告实际模块、最终压缩策略、设置与操作入口、执行证据和浏览器 / 网页限制。
