# Spec Delta

## ADDED Requirements

### Requirement: 模型服务完整移除

JchTools MUST 完整删除模型服务的产品代码及所有调用，包括 GUI 接入、ACP 客户端与回调、HTTP/SSE 与会话、独立后台、发现和维护协议、配置读写、环境处理、工作目录创建、状态与专属诊断。不保留不可达实现、隐藏开关、空页面、兼容别名、协议占位或替代服务。

#### Scenario: 启动与导航不再提供模型服务
- **WHEN** 用户启动新版本、切换工具、打开设置或关于，或关闭主窗口
- **THEN** 不启动或连接模型服务与外部 ACP Agent，不出现该功能入口、配置、状态或退出确认；保留的七个工具仍可正常访问。

#### Scenario: 旧入口不再实现服务协议
- **WHEN** 外部调用方尝试使用旧模型服务 HTTP、控制发现或 `--acp-http-service` 及其停止入口
- **THEN** 新版本不实现这些协议，不返回兼容模型、伪造就绪或模拟结果，不为兼容旧调用额外保留参数分支、管道或监听器；不额外规定通用未知参数的处理方式。

#### Scenario: 安装维护取消 ACP 调用
- **WHEN** 新版本安装器升级或卸载
- **THEN** 不调用 ACP 维护命令或显示 ACP 维护状态；CodeAgent 仍遵守 CA-08，其他既有交付保护不变。旧版模型服务仍在运行时由用户先通过旧版正常退出，不新增兼容控制器、不强杀或绕过文件占用覆盖。

### Requirement: 模型服务专属依赖与合规材料移除

JchTools MUST 删除模型服务 crate、全部 Cargo 接入、专属直接依赖及 feature，并清除仅因该功能保留的传递依赖、vendor 源码、来源和许可登记。裁减范围以其余生产、构建、测试目标及适用配置仍需要的依赖闭包为准，保留剩余依赖的精确来源、必要修改记录和许可证，不借移除升级或重构无关依赖。

#### Scenario: 专属依赖不再留在构建与交付中
- **WHEN** 模型服务调用和测试均已移除，且某包或 feature 无任何保留目标需要
- **THEN** 根与各 crate 清单、workspace 成员、feature 转发、锁文件、vendor、来源清单及交付许可不再为模型服务保留该内容；不能只断开调用而保留整套专属依赖。

#### Scenario: 共享依赖不能误删
- **WHEN** 原模型服务使用的 Tokio、tokio-util、SQLite、Windows API、日志或其他依赖仍被保留目标需要
- **THEN** 保留其必要声明、feature、源码、来源和许可，不按包名、HTTP/异步归类或曾被 ACP 使用一概删除。

### Requirement: 模型服务测试与文档完整退役

JchTools MUST 删除模型服务全部专属测试、夹具、验收目标、配置及脚本分支，并同步清理基线、需求映射和文档。专属文档整体移除，共用文档仅删除相关内容，保留其他能力的说明和测试断言；退役变更自身仅记录移除依据，不构成继续提供该功能的要求。

#### Scenario: 专属测试与验收链路退出
- **WHEN** 生成当前产品测试目标、nextest 选择规则、门计划、桌面驱动、测试基线和需求引用清单
- **THEN** 不再包含模型服务单元、GUI、HTTP、断连、回调、发现、生命周期或真实 OpenCode 验收及专属 Agent/消费者夹具，不构建 `jchtools-acp-fixture`，不保留服务专属环境配置、过滤规则或阶段；删除不改为 ignored、恒真测试、空阶段或伪造 PASS/NOT RUN 项。

#### Scenario: 混合测试与门保留其余行为
- **WHEN** 一个 GUI、日志、安装、布局或门脚本同时涉及模型服务和其他能力
- **THEN** 仅删除模型服务部分及其已无消费者的准备逻辑，更新实际范围与统计；其余有效断言、独立桌面授权、离线要求及既有门层级不变，不借退役跳过保留能力。

#### Scenario: 当前文档不再承诺旧功能
- **WHEN** 阅读仓库内需求、README、使用与工程指引、日志约定、E2E、合规说明或审查交接文档
- **THEN** 不再含模型服务专属章节、AH-01～AH-17 及 AH-A01～AH-A16 的当前交付/验收承诺、操作命令、安装说明、联网例外、引用和失效链接；工具清单与关于信息反映七个保留工具。CodeAgent Purpose 中相关对比文字同步移除，CA-01～CA-08 不变；不重写 Git 历史。

### Requirement: 模型服务退役不改变保留能力与用户数据

JchTools MUST 保留递归解压、目录整理、MD 整理、转 Markdown、Git 工具、截图 OCR、CodeAgent 及设置、关于的既有功能。共享 Xberg、推理模型资产、SQLite、日志和后台基础能力仅移除模型服务专属接入；不新增旧服务兼容、运行期数据清理或外部系统修改。

#### Scenario: 旧配置和目录不影响新版本
- **WHEN** 已有应用数据含 `acp_http_config` 或旧 `acp-workspace`
- **THEN** 新版本不再读取或应用服务配置，也不因这些残留启动服务、报配置错误或影响其他设置；不删除共用数据库、历史日志或用户资料，不为移除新增清理与迁移逻辑。

#### Scenario: 其他后台与模型仍独立运行
- **WHEN** 用户截图、转换文档或媒体，或使用 CodeAgent 维护 Token
- **THEN** 保留 Xberg、OCR/转录模型、托盘、热键、自启与凭据维护的原有行为及退出边界，不把这些能力视为模型服务的一部分，不修改外部 OMP/OpenCode、Agent 安装、账号或用户环境。

### Requirement: P-03

JchTools MUST 遵守本条行为：离线处理：所有文件处理功能离线可用，程序自身不得发起网络请求，不得上传文件、日志或路径。

#### Scenario: P-03 完整行为与适用边界
- **WHEN** 用户启动或使用 JchTools、执行文件任务或进行相应交付验收，且涉及本条规定的条件
- **THEN** 离线处理：所有文件处理功能离线可用，程序自身不得发起网络请求，不得上传文件、日志或路径。用户主动点击关于页官网链接时，允许交由系统浏览器打开，不附加用户文件、路径或日志信息；该例外不允许后台联网或自动打开网页。
  - 关于页外开仅允许发布时确定的项目官网 `https://` 或 `http://` URL，不接受文件内容、路径或日志拼成 URL，不调用 `file:`、脚本或自定义协议。目标网址须在关于页可辨识；具体域名是发布身份信息，不影响离线处理规则。
  - Git 工具例外（仅限 G 分区）：用户在 Git 工具页主动启动任务后，允许通过 git 命令访问所选仓库当前分支已配置的 upstream 远端（fetch / push 及其合并所需网络访问由 git 自身完成，见 G-08 / G-10）；不向 upstream 之外的任何地址发起请求，不上传本工具的日志、配置或用户路径。任务未启动或停止后不发起任何网络访问。该例外不放宽其他工具与其他分区的离线要求。
  - 音频转写可选资产下载例外（仅限 T-05 / T-06 / T-21 / XB 分区）：仅用户在统一设置页明确发起后，允许下载随包 Xberg 引擎清单声明匹配的 FFmpeg 及其必要 DLL / 许可、SenseVoice INT8、Silero VAD 及配套模型数据，装入同一共享运行目录；不下载或替换共享 Xberg 引擎，不替换已有有效的随包 DLL，不将 sherpa-onnx、共享 ONNX Runtime 等其他既定随包运行依赖改为下载。来源、选版、精确版本、大小与摘要校验按 XB-10，下载进度、失败、取消、重试及有效资产和配置保护按 XB-20 / XB-21，资产边界、路径安全及事务保护按 XB-27，网络出口与 TLS 按 P-09。媒体所需可选资产未就绪时提示用户到设置页主动下载，不因处理媒体文件静默下载。录音、会议视频仅指既有音轨转写，不增加录音采集、会议功能、视频画面理解或 T-08 / T-19 之外的格式。
  - 截图 OCR、文档与图片转换所需引擎、两套独立 OCR 模型与字典及运行依赖按 P-05 / XB-27 随包提供，结果窗字体和许可证仍按 O-05 内置于随包截图服务程序；安装或解包后自动定位同一共享运行目录，无需另行下载或手填目录。普通启动、切换 tab、截图及转换均不得自动联网下载或更新，不上传截图、文字、用户文件、路径或日志；未下载 FFmpeg 和音频模型不影响共享 worker、截图服务的正常启动以及截图、文档/图片 OCR、jchocr 或旧工具。缺失或损坏的随包文件须提示从安装包修复、重装或重新解包，不引导另行下载截图或文档组件。
  - jchocr 图片 URL 例外仅按 O-34：调用方显式提供 HTTP(S) 图片 URL 时允许下载该图片及其 HTTP(S) 重定向目标，下载内容只驻内存并交本地 OCR；不上传图片、文字或日志，不自动下载 Xberg，不放宽其他工具的联网权限。

### Requirement: P-10

JchTools MUST 遵守本条行为：关键步骤的诊断日志必须写入磁盘文件：进程间通信（共享 Xberg 代理与引擎的启动、退出、通信断裂与重建、请求失败）、网络出口（可选组件下载与初始化的失败与重试）、关键功能（转换 / 整理 / 解压等任务的开始、结束统计与逐文件失败原因）以及进程 panic，都记录到状态目录 `logs/` 下按天轮转的日志文件，并在达到大小上限前分段；单文件最多 1 MiB（1,048,576 字节，含 UTF-8 编码和换行），每个日志落点的自有诊断日志总数最多 10 个（含所有活动文件与历史文件），14 天为最长保留期。

#### Scenario: P-10 完整行为与适用边界
- **WHEN** 用户启动或使用 JchTools、执行文件任务或进行相应交付验收，且涉及本条规定的条件
- **THEN** 关键步骤的诊断日志必须写入磁盘文件：进程间通信（共享 Xberg 代理与引擎的启动、退出、通信断裂与重建、请求失败）、网络出口（可选组件下载与初始化的失败与重试）、关键功能（转换 / 整理 / 解压等任务的开始、结束统计与逐文件失败原因）以及进程 panic，都记录到状态目录 `logs/` 下按天轮转的日志文件，并在达到大小上限前分段；单文件最多 1 MiB（1,048,576 字节，含 UTF-8 编码和换行），每个日志落点的自有诊断日志总数最多 10 个（含所有活动文件与历史文件），14 天为最长保留期。达到数量上限时可以提前淘汰 14 天内最旧的自有日志；不清理归属未确认的文件，不为迁移直接截断或删除已有超大日志。（容量与保留策略于 2026-10-11 用户选择确认）日志只写本地磁盘，不联网上传、不包含截图、识别文字或文件正文；界面运行日志（S-07）保持不变，两者互不影响。日志初始化失败时先尝试用户级备用日志目录；仍失败时向 stderr 输出去敏原因，不弹窗、不终止业务。（日志补充及失败策略于 2026-10-10 用户确认）
  - 诊断日志的主要用途是运行期问题定位及 Agent 故障分析。文件必须以 `.log` 结尾；每个逻辑事件对应一条物理行，换行必须转义；每条事件包含至少毫秒精度的带时区时间戳、级别、PID、线程、组件及稳定事件名。默认运行配置保留关键诊断，`DEBUG` 仅用于额外细节；`INFO` 记录关键开始、成功结果和状态切换，`WARN` 记录可继续的异常、重试和回退，`ERROR` 记录导致当前操作失败的最终错误。
  - 初始化尽早于业务、网络、IPC 和子进程；启动记录应用名、版本、进程角色、实际日志路径、级别及构建模式，不倾倒环境变量。正常退出记录停止；异常退出记录去敏原因和可用退出码，主动退出前刷盘。日志写入失败不得递归写日志或改变业务结果。
  - 业务诊断日志和性能数据均按每次真实进程启动隔离（2026-10-17 用户确认）：GUI、内部后台服务、共享代理、截图 worker 和 jchocr 的本轮文件由单次进程运行独占，进程重启或 PID 被复用时必须创建新文件，不能向前一进程的文件追加或覆盖；同日运行及日志轮转也不得跨进程混写。唯一运行标识须独立于 PID，文件名或所在目录能区分各次启动；由本程序配置落点的 Xberg 性能数据也须按每次引擎启动使用独占目录。此规则不改变诊断日志的大小、数量、保留期、去敏和失败退化策略，不改变性能打点默认关闭、字段口径、按日轮转及原有采集范围。
  - 配置与存储、整理、解压、MD、转换、下载与 Git、共享 Xberg 及截图 OCR 的关键调用必须记录开始和最终结果、耗时及安全结果摘要；已处理的异常记录具体阶段、可用错误类型和错误码，不要求纯透传层重复输出同一异常堆栈。网络记录安全目标、调用类型、状态及尝试编号；IPC 和子进程记录操作、可用对端 PID、返回分类、超时、取消及退出结果。现有重试和回退过程必须能由日志还原，不为日志改变重试次数、超时或业务控制流。
