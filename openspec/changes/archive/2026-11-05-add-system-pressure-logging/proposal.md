# Proposal

## Why

需要一个简单、独立的系统压力记录功能，每 2 秒输出当前 CPU、内存及每块磁盘的负载，便于回看最近一段时间的系统状态。记录不能依赖 GUI 保持打开，也不能无限增长或生成多个历史文件。

现有工具注册表尚无该功能；`src/main.rs` 已有 CodeAgent 和定时任务的独立后台入口，可作为现有后台运行方式的参考，不把新增后台当作另一套 GUI 产品。

## What Changes

- 新增独立「系统压力记录」页面，归入「开发」类别，仅提供开始、停止及实际运行状态，展示实际输出路径。
- 手动开始后每 2 秒采集整机 CPU 使用率、物理内存使用率，以及每块物理磁盘的活动时间百分比、读取速度和写入速度；每次采集附带时间戳及磁盘标识。
- 优先写入 `D:\JchTools-performance.csv`；D 盘不存在时使用系统临时目录下同名文件。仅使用一个循环更新的数据文件，保留最近 20 分钟；运行不足 20 分钟时输出已有数据，达到时长后继续记录并淘汰过期数据。
- 关闭 GUI 不停止采集；重开 GUI 可查看真实状态并停止记录，不重复启动采集。
- 保持最小功能边界：手动启停，不增加开机自启、图表、采集周期设置、输出路径设置、保留时长设置或进程级统计。

### 验收边界与约定

- 本提案将前述含混的时长描述按最小方案明确为「滚动保留最近 20 分钟」，不是记录 20 分钟后停止。
- 「磁盘压力」指每块物理磁盘的 I/O 繁忙程度和读写速度，不是剩余空间；同一物理磁盘上的多个分区不重复计为多块磁盘。
- CPU 和磁盘使用最近采样间隔的负载，内存使用采样时的状态；无法取得的指标不得伪造成零。
- 验收需覆盖真实采集与 CSV 更新、超出 20 分钟后的旧数据淘汰、关闭并重开 GUI 后继续记录且不重复采集、主动停止后不再写入、D 盘存在与不存在时的路径选择，以及选定路径不可写时的明确错误。这里定义验收要求，不代表已经执行或通过。
- 普通启动 GUI 不自动开始；Windows 重启后不自动恢复。停止记录保留已输出文件。
- 只有 D 盘不存在时才使用系统临时目录；D 盘存在但无写入权限或文件无法更新时明确报错，不因写入失败切换目录，不自动提权。
- 本提案采用以上最小方案供需求审阅；不引入额外设计决策或待办实现计划。

## Capabilities

### New Capabilities

- `system-pressure-logging`：独立启停、后台持续采集、D 盘优先且无 D 盘时系统临时目录的 CSV 输出及最近 20 分钟的单文件循环保留。

### Modified Capabilities

- `application-contract`：扩展 P-02 工具登记，将「系统压力记录」加入独立工具及「开发」类别，保留其他工具及既有约束。

## Impact

- 实施时涉及工具注册表、GUI 页面与装配、后台生命周期及 Windows 本地性能指标读取，不改变其他工具行为，不新增网络访问。
- 正式交付新增能力时需同步 README 功能与需求入口、AGENTS.md 权威分工及需求登记；本轮仅创建提案和增量规格，不修改这些文件或已批准基线。
- `D:\JchTools-performance.csv` 或无 D 盘时系统临时目录下的同名文件是用户要求的产品数据输出，不替代现有应用诊断日志，也不改变其位置及规则。
- 本轮不修改产品实现、不创建设计或任务产物、不构建、不运行软件验收；提案不因写入而自动成为已批准需求。
