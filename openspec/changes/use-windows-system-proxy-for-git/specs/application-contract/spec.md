# Spec Delta

## MODIFIED Requirements

### Requirement: P-09

JchTools MUST 遵守本条行为：应用自身下载走 Windows 系统代理：应用读取 Windows 当前用户的手动系统代理（Internet 设置的 `ProxyEnable` / `ProxyServer`，支持整体与按协议（http / https / socks）形式及 `ProxyOverride` 例外表；PAC / WPAD 自动配置不支持，并在音频转写可选资产下载指引中如实说明）。

#### Scenario: P-09 完整行为与适用边界
- **WHEN** 用户启动或使用 JchTools、执行文件任务或进行相应交付验收，且涉及本条规定的条件
- **THEN** 应用自身下载走 Windows 系统代理：应用读取 Windows 当前用户的手动系统代理（Internet 设置的 `ProxyEnable` / `ProxyServer`，支持整体与按协议（http / https / socks）形式及 `ProxyOverride` 例外表；PAC / WPAD 自动配置不支持，并在音频转写可选资产下载指引中如实说明）。系统代理开启且目标未命中例外表时，应用自身全部下载（P-03 的 FFmpeg 及音频模型下载例外，匹配包内引擎的资产清单按 XB-10，设置保护按 XB-20 / XB-21，资产边界及路径事务按 XB-27）必须经系统代理发起；经代理连接失败时自动回退直连重试一次，直连同样失败才按原有失败口径报错。系统代理关闭时应用自身下载直连。Git 工具按 G-17 优先保留系统 Git 原有配置与继承环境中适用于当前目标的显式代理或直连策略；未显式配置时，其 HTTP(S) 网络操作必须使用 Windows 当前用户已启用的手动系统代理并遵守例外表，不限定代理服务器域名、IP 或端口，不由 JchTools 在代理失败后强制直连回退。本条不新增联网来源，不改变 P-03 的固定清单、upstream 限制与关于页交系统浏览器打开的行为。
  - 音频转写可选资产下载及其发布元数据查询的 TLS 策略（2026-10-15 用户进一步确认最终下载成功，并要求直接忽略证书）：从第一次 HTTPS 请求开始跳过服务端证书的信任链、颁发者、域名和有效期校验，重定向后的 HTTPS 目标沿用同一策略，不先执行严格证书校验或为证书失败增加一轮代理/直连重试。该策略不保障服务器身份，界面进度与诊断记录须明确证书校验已跳过；保留 TLS 加密和握手签名校验，以及固定来源、文件大小/摘要校验、取消和已有下载重试上限。网络出口仍按本条优先使用 Windows 手动系统代理（服务器域名或 IP，不限回环地址），代理传输失败仅直连重试一次；不改 Windows 全局证书设置，不扩大 Git 或 jchocr 的网络策略。

#### Scenario: P-09 Git 代理与组件下载策略分别适用
- **WHEN** 用户主动启动 Git HTTP(S) 网络任务，且需选择代理或处理代理失败
- **THEN** JchTools MUST 按 G-17 的显式配置优先、缺省使用 Windows 手动系统代理规则执行；组件下载的代理失败直连回退及跳过服务端证书检查不得套用到 Git。
