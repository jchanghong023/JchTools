# Spec Delta

## MODIFIED Requirements

### Requirement: P-12

JchTools MUST 遵守本条行为：自动化验收须覆盖已确认的必验需求范围，按需求编号建立可核对的需求与测试映射。

#### Scenario: P-12 完整行为与适用边界
- **WHEN** 用户启动或使用 JchTools、执行文件任务或进行相应交付验收，且涉及本条规定的条件
- **THEN** 自动化验收须覆盖已确认的必验需求范围，按需求编号建立可核对的需求与测试映射。完整功能验收以实际 Windows 全量测试及对应矩阵证据为准；本地增量门通过仅证明所选用例通过，不得冒报完整验收，相关输入未变的有效本地验证可复用。CI 仅编译、打包、发布，不运行功能测试或质量门；CI 成功不代表功能验收，也不替代独立桌面、模型或交付验收。转 Markdown 的默认格式范围按 openspec/specs/markdown-conversion/spec.md 附录 A 的常用新老 Office、PDF、MP4 执行；已有扩展格式测试保留为可选，不计为通过，也不阻塞常用格式验收及发布。GUI 测试从真实公开入口覆盖全部可经界面触发或观察的需求及跨功能、设置链路，断言实际业务结果、状态和相关产物，覆盖核心成功与相关失败、停止和取消路径；内部逻辑、协议、资产及交付约束由关联的 UT、集成和交付验证共同覆盖，不遗漏非 GUI 约束。底层单测、模拟、仅完成点击或没有崩溃不能代替对应真实 GUI E2E 与可观察结果断言，未覆盖或未执行项不得报告通过。
  - 只测试本项目 Rust 产品，不测试 Python、PowerShell 脚本或选测工具自身；保留以 Python 驱动的 Rust 产品验收，静态检查和类型检查不受此限制。
  - 本地三级门分离日常功能回归与发布交付验收：fastcheck 保持静态检查、格式与编译，不运行测试；fulltest 的全量模式包含 fastcheck 及全部适用的 Windows 非打包 Rust 产品 UT / integration / doc / e2e，保留可选组件、真实 7-Zip / Xberg / 媒体及隔离 GUI 覆盖，但不要求 ISCC、不生成安装包或便携 ZIP、不执行 `package-windows.ps1`、仅为发布验证的 `release-target-build` 或在线全量供应链审计 `pyquality-pip-audit`。fulltest 通过不证明 P-05 / E 分区的打包交付验收或实时漏洞库审计通过。slowtest 将相应 fulltest 覆盖执行一次，并保留原在线供应链审计及 P-15 的完整本地发布构建与双产物校验；不先执行 fulltest 再重复同一功能覆盖。在线审计依赖实时外部漏洞库，归 slowtest，原命令及失败判据不变。
  - 按用户最新批准策略，本地门默认增量，`--full` 仅在独立明确的全量验收时选择，不常规用于本地或 CI；CI 不安装测试或质量依赖及 cargo-nextest，不准备本地测试引擎目录，不运行功能测试、lint/质量门、真实模型或桌面，保留生产依赖和交付资产，以 `package-windows.ps1 -SkipTests` 打包。`check.yml` 手动编译打包并保留构建产物，`release.yml` 手动编译打包发布；发布仍须单独授权。本地静态检查和编译仍执行，业务实现、断言和 feature / profile / target 维度不变；正常保留 Cargo target 与增量编译缓存，不建立自有成功账本。fulltest / slowtest 使用 [cargo-nextest](https://nexte.st/)（至少 0.9.116，采集需要 `NEXTEST_BINARY_ID`）；普通 Rust 阶段默认实验性 [cargo-affected](https://github.com/max-sixty/cargo-affected/tree/v0.4.1) `run` 选择受影响测试，`--full` 和依赖真实引擎、媒体等外部状态的阶段使用 `cargo nextest run` 全量执行；文档测试始终使用 `cargo test --doc`。统一根 `.config/nextest.toml`、零重试及原生非 fail-fast；默认过滤真实桌面，另获授权的桌面验收可显式忽略默认过滤，不运行 ignored 模型测试。PowerShell 验收与未使用 `-SkipTests` 的打包使用全量 nextest 和 Cargo 文档测试。cargo-affected 0.4.1 官方称极早期且支持 Windows MSVC；增量通过不证明完整覆盖。
  - 默认增量门用原生 `cargo affected status --report-json` 检查 coverage 基线；缺失或失效且 Git 工作树干净时，原生 `cargo affected collect` 一次采集整个 workspace（含两个 optional 包），真实执行测试，之后仍运行三个普通 affected 阶段：原生工具跳过已有有效覆盖且未变化的测试，无 coverage 或不适合插桩的测试保守普通执行，不重复已有效覆盖测试。jchocr 的 `review_remediation_url_{content_length,chunked,without_length}_budget_plus_one_is_network_error` 三个 384 MiB 容量边界用例仅从插桩 collect/status 排除，普通 affected 和 `--full` 仍执行，保留 30 秒上限和断言；子进程损坏的 profraw 不伪造 coverage，缺覆盖的测试由原生工具保守重跑。真实引擎、媒体及文档测试仍全量执行。有效基线随已提交 HEAD 前移而无当前 equal 锚且工作树干净时，使用原生 `collect --diff` 更新；脏源码按采集 SHA 差异选择，不保证任意脏树重复运行均零选中，dirty 不使用 `--allow-dirty`，基线缺失或失效时明确提示并保守回退全量。原生 SHA / DB 是唯一选测状态，不自建成功账本；工具使用隔离插桩构建目录，不清正常 target、不全局更改 RUSTFLAGS；`--full` 不自动采集，仍为显式全量路径。基线采集和零选中均不证明本轮全部功能覆盖。本次用户授权本会话变更仅本地提交，不推送、不触发 CI 或发布。
  - 本地开发使用 `python scripts/native_test_tools.py` 安装 `.tmp/native-tools/cargo-affected/bin` 私有工具，固定上游 SHA `08000ff968eebb238a26a3a4de38fe314e8ca05e` 加兼容补丁的 `0.4.1+jchtools.2`，兼容 nextest 默认过滤和显式 filter 的最小筛选，并包含 Windows LLVM profile 路径、上游 Windows 源码暂存目录碰撞及过长路径兼容补丁。缺失或版本不符时提示安装，不静默使用旧版；工具不进入 CI 或产品包，不修改全局 Cargo bin 或正常 target。
  - 根 `Cargo.toml` 的 cargo-affected metadata 对非 Rust 输入、`build.rs`、vendor、脚本、夹具及 `.cargo` 配置等保守选择全部测试。该工具仍处于早期，不保证选择绝对精确，增量通过不证明完整覆盖。
  - 普通测试并行度按 `min(28, 可用逻辑核心数)` 动态计算，核心数不可用或为零时取 1。门计划器为 nextest 和 cargo-affected 转发显式 `--test-threads`，PowerShell 验收及未使用 `-SkipTests` 的打包同样计算并传参；根 nextest 配置的 `test-threads = 'num-cpus'` 本身不能表达 28 上限，手工运行若需相同上限必须显式传参。物理共享引擎组最多一个测试；jchocr 仅 `engine_asset_failure_is_an_explained_xberg_error` 和 `review_remediation_small_url_preserves_successful_ocr_text` 使用该 engine-session 组，三个 `review_remediation_url_{content_length,chunked,without_length}_budget_plus_one_is_network_error` 容量用例使用独立单并发组，独立 jchocr CLI 测试可并行；worker 既有隔离不变。Cargo 编译 jobs=16 不因测试并行度改变。
  - 仓库当前无自有 TypeScript 工程，不安装 Bun 或创建空任务。
  - 阶段顺序执行，保留共享 Xberg / 媒体和真实 / 随包 7-Zip 的安全隔离，编译及产物生产者有序；实际高风险 `trusted-` / `test-gate-` / `static-` 检查与测试先于普通组执行，失败不阻止无依赖的后续阶段。清单发现不执行测试体，不代替测试通过；保留编译、产物、发现与执行的真实依赖。
  - 本次用户明确批准取消三级门的脚本硬时间限制、编译观测扣时及自研失败监督。记录阶段和总墙钟作为观测，不以耗时阈值判败。连续两轮默认 `python scripts/test_gate.py fulltest --authorized` 须在代码和环境不变下均通过，以真实输出分别汇报选测、运行情况及实际耗时，证明第二轮大幅减少；增量 PASS 不代表全量覆盖。
  - 用户最新批准要求替代旧首错停止：本地 fastcheck、fulltest 和 slowtest 失败后继续其余可运行阶段及用例，最终完整汇总并返回非零；必要前置缺失导致依赖项不可运行时明确报告 FAIL、UNVERIFIED 或 NOT RUN，不能冒报通过。用户主动中断不强制继续。使用 Nextest 原生非 fail-fast 行为，不自研失败监控或强杀。每轮和独立命令使用包含进程标识及唯一运行标识的独占日志目录，仅错误时输出保留的日志路径；阶段日志、测试结果与打包计时不得跨轮复用、追加或覆盖；未执行项如实报告，不以历史记录代替本轮证据。
  - 用户最新明确批准三级门仅展示和保存失败 / 错误用例明细：成功及正常 skip 的用例名称、输出和逐条耗时既不输出到控制台，也不持久保留；失败 / 错误用例保留名称、诊断和耗时。整轮状态、阶段及总墙钟、实际执行与选测 / 缓存数量等不含成功用例身份的真实聚合汇总仍须保留；不可运行项如实报告 UNVERIFIED / NOT RUN。stdout 可临时捕获供诊断或 metadata 消费，成功后不持久保留；LLVM coverage / 依赖数据库是原生选测所需状态，不作为日志删除或伪造。产品业务诊断日志按 P-10 不变。
  - fulltest 和 slowtest 每次运行须获当次明确授权，入口声明不创造授权，不静默重跑到绿；Windows-only 边界不引入 WSL。CI / 发布、抢占焦点的真实桌面 driver 及真实模型调用仍须门外独立授权；门外项目未执行不冒报通过，不因其独立授权边界而判门失败。环境或工具缺失的覆盖缺口如实标注，不能以编译或门通过代替未执行项的验收。
