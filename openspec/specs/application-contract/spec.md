# 应用全局与共用约束

## Purpose

定义 JchTools 的应用全局与共用约束及其可观察结果、约束、例外和验收边界。H 高于其他分区，其余冲突时 S 优先；各功能域须同时满足适用的全局条目与规范性附录，示例不得覆盖明文规则。附录 B～E 为跨工具共用定义与验收期望；普通文件大类映射仅由目录整理规格附录 A 维护。

各能力同时遵守[应用全局与共用规格](../application-contract/spec.md)，工程纪律见[AGENTS.md](../../../AGENTS.md)。本文为已批准需求，不记录实现状态或测试通过状态；未实现不撤销要求，历史授权不授予当前执行权限。

## Requirements

<a id="最高优先级需求h"></a>

**最高优先级需求（H）**

### Requirement: H-01

JchTools MUST 遵守本条行为：个人工具，性能优先：JchTools 用于用户个人资料整理，处理性能是首要要求。

#### Scenario: H-01 完整行为与适用边界
- **WHEN** 用户启动或使用 JchTools、执行文件任务或进行相应交付验收，且涉及本条规定的条件
- **THEN** 个人工具，性能优先：JchTools 用于用户个人资料整理，处理性能是首要要求。避免无必要的重复扫描、重复读取文件内容、重复计算和复制；不为企业级、多人协作、处理期间外部改动等非目标场景增加负担。性能优化不得通过漏处理、错误删除或暗中缩小处理范围来实现。

### Requirement: H-02

JchTools MUST 遵守本条行为：易用与流畅优先：界面方便好用、操作流畅是首要体验要求。

#### Scenario: H-02 完整行为与适用边界
- **WHEN** 用户启动或使用 JchTools、执行文件任务或进行相应交付验收，且涉及本条规定的条件
- **THEN** 易用与流畅优先：界面方便好用、操作流畅是首要体验要求。扫描、解压、哈希和整理期间界面必须保持响应，处理状态可见、取消入口可用；常用操作直接可达，低频配置不妨碍日常使用。不以阻塞界面换取后台吞吐，不为方便而强制用户执行另一个工具。

### Requirement: H-03

JchTools MUST 遵守本条行为：递归解压、目录整理、MD 整理、转 Markdown、Git 工具和截图 OCR 均为独立工具，具有正常可见的独立入口，不互相自动调用、串联、隐藏或降级。

#### Scenario: H-03 完整行为与适用边界
- **WHEN** 用户启动或使用 JchTools、执行文件任务或进行相应交付验收，且涉及本条规定的条件
- **THEN** 递归解压、目录整理、MD 整理、转 Markdown、Git 工具和截图 OCR 均为独立工具，具有正常可见的独立入口，不互相自动调用、串联、隐藏或降级。需要完整资料整理时，由用户先使用递归解压，再手动使用目录整理；解压完成只按 X-05 清理成功原包，不自动去重、归类或清理其他文件，目录整理不自动解压。截图与转换共用推理组件只按 XB 分区共享引擎，不改变工具独立性、输入输出或各自停止语义。

### Requirement: H-04

JchTools MUST 遵守本条行为：递归解压结果：在明确的处理范围内，X-01 白名单内、能够由捆绑引擎成功解开的压缩包及本次解出的嵌套包都应完成解压；H-06、S-04 和 X-07 排除的范围除外，白名单外容器不被解压、也不计为未完成。

#### Scenario: H-04 完整行为与适用边界
- **WHEN** 用户启动或使用 JchTools、执行文件任务或进行相应交付验收，且涉及本条规定的条件
- **THEN** 递归解压结果：在明确的处理范围内，X-01 白名单内、能够由捆绑引擎成功解开的压缩包及本次解出的嵌套包都应完成解压；H-06、S-04 和 X-07 排除的范围除外，白名单外容器不被解压、也不计为未完成。每个包完整成功后按 X-05 永久删除原包及实际分卷，不把删除职责留给目录整理。确实无法解开的包按 X-06 隔离保留并说明原因；取消或空间不足时原地保留当前源包并停止。防护上限、范围限制或失败导致内容未解开时，不得宣称已全部解压。同次任务已处理的包不得反复入队；目录整理不补做解压、不无条件删除压缩包。

### Requirement: H-05

JchTools MUST 遵守本条行为：整理后没有空目录：目录整理成功完成后，处理范围内除用户选定的根目录外，不得残留空目录，包括解压、去重、归类、删除后新产生的空目录。

#### Scenario: H-05 完整行为与适用边界
- **WHEN** 用户启动或使用 JchTools、执行文件任务或进行相应交付验收，且涉及本条规定的条件
- **THEN** 整理后没有空目录：目录整理成功完成后，处理范围内除用户选定的根目录外，不得残留空目录，包括解压、去重、归类、删除后新产生的空目录。自底向上清理实际为空的目录及空目录链，不得递归删除有内容的目录；H-06 排除的目录树不参与清理。取消或清理失败时如实显示未完成，不得为了清空目录而在取消后继续删除。本条属于目录整理，不要求仅使用递归解压时额外清理目录。
  - 「处理范围」按 S-04 / R-03 确定：用户明确排除的目录树、关闭递归后未纳入的后代及链接边界不参与空目录清理。分类操作为已纳入文件新建的目标目录仍参与最终空目录清理；仅因处理范围缩小而留下的目录不算清理失败，但必须显示范围限制。

### Requirement: H-06

JchTools MUST 遵守本条行为：Git 目录整树忽略：任一目录直接含有名为 `.git` 的目录或文件时（一个 Git 项目取其最外层，内部再出现的 `.git` 不单独划分项目），该目录及全部后代整树排除：不解压、不读取内容参与哈希或去重、不改名、不删除、不清理内部空目录。

#### Scenario: H-06 完整行为与适用边界
- **WHEN** 用户启动或使用 JchTools、执行文件任务或进行相应交付验收，且涉及本条规定的条件
- **THEN** Git 目录整树忽略：任一目录直接含有名为 `.git` 的目录或文件时（一个 Git 项目取其最外层，内部再出现的 `.git` 不单独划分项目），该目录及全部后代整树排除：不解压、不读取内容参与哈希或去重、不改名、不删除、不清理内部空目录。唯一例外是目录整理的归类——整个项目目录作为一个整体移入「Git项目集合」目录，除此之外不进入树内做任何处理（去重、附属文件清理、改名、空目录清理、解压都不进行），见 C-14。只允许为识别边界进行必要的目录项检查，识别后不继续遍历内部；除该整体归类移动外，不得通过移动、改名或删除祖先目录间接改变该树。该排除不受隐藏文件、递归或清理开关影响，不提供关闭选项，整体归类移动同样是固定行为、无开关。选定根目录直接含 `.git` 时，整次处理不执行并明确提示；只有子目录含 `.git` 时，只排除该子树。新解出的目录含 `.git` 时，后续处理同样排除；界面明确提示 Git 目录的处置结果。
  - `.git` 名称按不区分大小写识别，`.GIT` 同样保护，不要求读取标记内容或验证仓库有效性。开始扫描前沿所选根及其祖先到卷根检查直接目录项；任一祖先直接含 `.git`，说明所选根位于 Git 项目内，两工具均拒绝整次处理。不能完成必要边界检查时不猜测为普通目录，报错且不开始处理。
  - 固定整体归类只适用于本次扫描范围内识别到、且不在用户排除或隔离容器内的项目；不以“归类固定开启”为由进入缩小范围之外查找项目。
  - 新增转 Markdown 工具只读扫描按 T-09 执行，不套用本条的 Git 整树排除；此限定仅适用于新增工具，不改变任何既有工具的扫描、保护或处理行为。

### Requirement: H-07

JchTools MUST 遵守本条行为：递归解压不去重、不删除无关文件：只允许按 X-05 永久删除完整成功解开的源压缩包及其实际分卷，不得删除既有用户文件或已落盘的普通解压结果，不得以内容相同为由跳过正常落盘。

#### Scenario: H-07 完整行为与适用边界
- **WHEN** 用户启动或使用 JchTools、执行文件任务或进行相应交付验收，且涉及本条规定的条件
- **THEN** 递归解压不去重、不删除无关文件：只允许按 X-05 永久删除完整成功解开的源压缩包及其实际分卷，不得删除既有用户文件或已落盘的普通解压结果，不得以内容相同为由跳过正常落盘。目标冲突时保留已有文件，只为新解出的文件自动选择未占用的文件名，不覆盖、不淘汰、不询问冲突策略。只改文件名主体，原扩展名及复合扩展名保持不变，例如 `资料.txt` → `资料 (1).txt`、`资料.tar.gz` → `资料 (1).tar.gz`；不得通过更换或追加扩展名规避冲突。工具自身临时工作区只按本次所有权标记清理，不得删除用户目录。目录整理的去重、删除职责不受本条取消。
  - 「普通解压结果」不含已作为独立嵌套源包、随后满足 X-05 删除条件的归档；普通文件不会因为扩展名相似而被删。嵌套包是否删源逐包决定，不要求其所有后代包也成功。复合扩展名切分见附录 B，卷集改名另按 X-10 保持整组关系。

<a id="附录-b名称比较与扩展名定义c-02--c-03--c-08--c-16c-21--h-07"></a>

**附录 B：名称、比较与扩展名定义（C-02 / C-03 / C-08 / C-16～C-21 / H-07）**

<a id="文件名切分"></a>

**文件名切分**

- 普通扩展名为最后一个点及其后非空部分；点在首位且之后无其他点的名称（如 `.gitignore`）整体为主体，无扩展名。`.DS_Store` 按 C-08 完整名匹配，不依赖扩展名切分。
- `.tar.gz`、`.tar.bz2`、`.tar.xz`、`.tar.zst`、`.tar.lzma`、`.tar.z` 为复合扩展名，整体保留；匹配不区分大小写、输出保留原后缀大小写。其他多点名称只将最后一段视为扩展名，除下条分卷模式外不猜复合后缀。
- X-10 数字尾卷的「白名单扩展名 + 编号后缀」（如 `.7z.001`、`.7z.1000`、`.tar.gz.1001`；编号规则唯一见 X-10）、part rar 的 `.partN.rar`、老式 `.rNN` / `.zNN` 在改名时均为不可拆分后缀。隔离用 X-10 的整组改名，整理只对每个普通文件主体按 C 规则命名，不改变编号串。
- 项目目录名整体为主体，含点也不拆扩展名；不对 Git 项目名执行文件副本后缀清理或内容签名修正。

<a id="比较与稳定决胜"></a>

**比较与稳定决胜**

- Windows 同名关系使用不依赖界面语言的序数忽略大小写比较（Windows ordinal ignore-case 语义），不是按拼音、自然数字或当前区域排序；操作系统实际报告的目标占用同样必须避开，即使其等价规则更严格。
- 稳定升序：将相对路径的目录分隔符统一 `/`，先按上述忽略大小写的序数比较，仍相同则按原始 UTF-16 单元序列逐单元升序决胜。长度为同样路径表示的 UTF-16 单元数，包括 `/`，不含根路径。保留者使用分析时原路径，不使用将生成的目标名。
- C-02 同名键是原完整文件名的忽略大小写比较键；副本名键按下面副本标记规则剥除后，连同未改变的扩展名一起比较。副本名键只用于候选判定，不能替代 C-08 的输出名，也不决定删除；删除仍以完整内容哈希为依据。

<a id="副本标记和名称规范化"></a>

**副本标记和名称规范化**

- 副本标记仅识别主体末尾连续出现的标记序列：ASCII 圆括号包围的一个或多个十进制数字 `(N)`、ASCII 连字符加 `Copy`（忽略大小写）、中文 `副本`。标记前允许零个或多个 ASCII 空格，连字符与 Copy 之间允许零个或多个 ASCII 空格；不把主体中间的同样字串当作后缀。`report(1)`、`report (01)`、`report-Copy`、`report - copy`、`报告副本` 都识别。
- 从右往左收集整段末尾标记，剥除后保留原先从左往右的数字顺序。用于去重名称键时全部标记移除；用于输出名时每个 `(N)` 转为 `_N`，十进制前导零去掉、全零保留 `0`，其他标记移除。已有 `_1` 不视为待剥除副本标记，避免再次整理继续变化。
- 例：`报告 (1) (02).pdf` → `报告_1_2.pdf`；`report - Copy (1).tar.gz` → `report_1.tar.gz`；`报告副本.pdf` → `报告.pdf`；`报告副本说明.pdf` 不因含「副本」改名。`(1).pdf` 的基础主体为空时使用 `_` 作基础主体，得到 `__1.pdf`；不剥掉 `.pdf`。
- NFC / 空白开关开启时，对主体先做 NFC，将 Unicode White_Space 属性中的连续字符压成一个 ASCII 空格，并去除主体首尾空白；再执行开启的副本后缀清理。未开启的规范化不隐式执行；派生结果的合法性检查始终执行。
- 来源目录加入普通文件候选前，也按已开启的 NFC / 空白规则规范化该来源段，但不对来源段剥副本标记、不改源目录。完整候选生成后再按同一输出规则检查至不再变化，然后判定占用与长度，避免下一轮首次清理新加的前缀或因截短暴露的末尾副本标记。项目目录候选仅做必要合法性处理，仍不应用普通文件清理规则。
- 因派生改名产生的主体末尾 ASCII 点或空格去掉；主体空、`.` 或 `..` 时用 `_`。主体中的 Windows 禁用字符 `< > : " / \ | ? *` 及 U+0000～U+001F 替换为 `_`。来源目录拼接后的名称也受此约束，但绝不改写源目录名本身。
- 派生完整名若命中 Windows 设备保留名（含带扩展名形式的 CON、PRN、AUX、NUL、COM1～COM9、LPT1～LPT9 及系统视为等价的设备名），在主体前加 `_`，再验证。原扩展名本身无法合法保留时安全失败，不删除扩展名。合法性变换后重新参加全目标冲突判断；不能把 `_` 当作唯一名称保障。
- 本节输出规则仅适用于目录整理；解压对归档成员的危险或非法原名按 X-08 整包拒绝，不借本节把危险路径“修好后放行”。正常解压目标冲突仍按 H-07 / X-04 仅改主体。

<a id="内容签名修正扩展名"></a>

**内容签名修正扩展名**

- 该开关默认关闭，开启后只在分析阶段为非排除、非待删普通文件判型；无需对所有文件计算完整哈希。无法可靠判型不改，错误不可导致删除或猜测性改后缀。
- 本合同要求可确定识别并修正的类型为 PNG、JPEG、GIF、BMP、TIFF、WebP、PDF、FLAC、WAV、ZIP、7z、RAR，以及通过 ZIP 内部类型标识可确认的 DOCX、XLSX、PPTX、DOCM、XLSM、PPTM、ODT、ODS、ODP、EPUB。识别依赖该格式的有效结构与必要类型标识，不能仅凭几个相同开头字节把任意内容认作文件类型。
- 确认类型且现后缀不正确时，采用 `.png`、`.jpg`、`.gif`、`.bmp`、`.tif`、`.webp`、`.pdf`、`.flac`、`.wav`、`.zip`、`.7z`、`.rar` 或对应小写文档扩展名；已有 `.jpeg` / `.jpg`、`.tiff` / `.tif` 均为合法同义形式，不强制改名或统一大小写。
- ZIP 容器必须先区分上述文档类型；不能确认其内部类型时，保留原后缀为 Office、ODF、EPUB 或 X-09 其他已列容器格式的文件，不降级为 `.zip`。未承诺的类型不进行修正，不以模糊特征强行分类。

<a id="附录-c扫描排除-globs-04--r-03"></a>

**附录 C：扫描排除 glob（S-04 / R-03）**

- 输入为分号分隔的模式列表；去掉每段首尾空白，空段忽略，空列表表示不额外排除。各模式为“或”关系，任一命中即排除。
- 匹配对象为相对所选根的路径，统一使用 `/`，无开头 `/`、无结尾 `/`；用户模式中的 `\` 也视为目录分隔符，不作为转义符。按 Windows 序数忽略大小写匹配，不受界面语言影响。
- 模式匹配整个相对路径，不自动匹配任意文件名片段。`*` 为零个或多个字符，可跨 `/`；连续多个星号等同一个星号，`**` 没有独立递归语义。`?` 为恰好一个 Unicode 字符，不能匹配 `/`。除 `*`、`?`、分隔符和分号外均按字面匹配，不支持字符类、花括号展开、正则、否定或反向纳入；例如 `[ab]` 匹配字面 `[ab]`，不是 a 或 b。
- 不支持转义、引号包裹或分号字面匹配；输入含盘符、绝对路径或独立 `..` 路径段时作为无效模式阻止开始，指出错误段，不悄悄忽略。大小写无关不意味着先改写磁盘文件名。
- 目录路径命中时整树排除，不再为统计其后代读取内容；文件路径命中只排除该文件。目录后代即使没有逐个匹配，也不再纳入。Git 保护、链接边界、Windows 系统目录和隔离容器先于 glob，不存在用模式重新纳入的办法。

|模式|匹配结果|
|---|---|
|`*.tmp`|根及任意层级以 `.tmp` 结尾的路径；若命中目录则排除整树|
|`cache`|根直接子项 cache；若为目录则整树排除，不匹配 `a/cache`|
|`*/cache`|任意非根直接层级的 cache 项，如 `a/cache`、`a/b/cache`|
|`cache;*/cache`|根直接层级及深层的 cache 目录均可排除|
|`a/?.txt`|`a/x.txt`，不匹配 `a/xy.txt` 或 `a/b/x.txt`|

隐藏和系统属性开关是两个独立的包含开关，均默认开；某项具有任一被关闭包含的属性就排除。目录被属性排除时后代整树排除，不因后代属性不同重新纳入；必要 Git 边界检查仍在排除前进行。排除是范围限制，不是执行失败；界面同时显示限制与处理结果，不能把“范围内完成”写成“全部目录均已处理”。

### Requirement: 模型服务完整移除

JchTools MUST 完整删除模型服务的产品代码及所有调用，包括 GUI 接入、ACP 客户端与回调、HTTP/SSE 与会话、独立后台、发现和维护协议、配置读写、环境处理、工作目录创建、状态与专属诊断。不保留不可达实现、隐藏开关、空页面、兼容别名、协议占位或替代服务。

#### Scenario: 启动与导航不再提供模型服务
- **WHEN** 用户启动新版本、切换工具、打开设置或关于，或关闭主窗口
- **THEN** 不启动或连接模型服务与外部 ACP Agent，不出现该功能入口、配置、状态或退出确认；保留的七个工具仍可正常访问。

#### Scenario: 旧入口不再实现服务协议
- **WHEN** 外部调用方尝试使用旧模型服务 HTTP、控制发现或 `--acp-http-service` 及其停止入口
- **THEN** 新版本不实现这些协议，不返回兼容模型、伪造就绪或模拟结果，不为兼容旧调用额外保留参数分支、管道或监听器；不额外规定通用未知参数的处理方式。

#### Scenario: 安装维护取消 ACP 调用
- **WHEN** 新版本安装器升级或卸载
- **THEN** 不调用 ACP 维护命令或显示 ACP 维护状态；CodeAgent 仍遵守 CA-08，其他既有交付保护不变。旧版模型服务仍在运行时由用户先通过旧版正常退出，不新增兼容控制器、不强杀或绕过文件占用覆盖。

### Requirement: 模型服务专属依赖与合规材料移除

JchTools MUST 删除模型服务 crate、全部 Cargo 接入、专属直接依赖及 feature，并清除仅因该功能保留的传递依赖、vendor 源码、来源和许可登记。裁减范围以其余生产、构建、测试目标及适用配置仍需要的依赖闭包为准，保留剩余依赖的精确来源、必要修改记录和许可证，不借移除升级或重构无关依赖。

#### Scenario: 专属依赖不再留在构建与交付中
- **WHEN** 模型服务调用和测试均已移除，且某包或 feature 无任何保留目标需要
- **THEN** 根与各 crate 清单、workspace 成员、feature 转发、锁文件、vendor、来源清单及交付许可不再为模型服务保留该内容；不能只断开调用而保留整套专属依赖。

#### Scenario: 共享依赖不能误删
- **WHEN** 原模型服务使用的 Tokio、tokio-util、SQLite、Windows API、日志或其他依赖仍被保留目标需要
- **THEN** 保留其必要声明、feature、源码、来源和许可，不按包名、HTTP/异步归类或曾被 ACP 使用一概删除。

### Requirement: 模型服务测试与文档完整退役

JchTools MUST 删除模型服务全部专属测试、夹具、验收目标、配置及脚本分支，并同步清理基线、需求映射和文档。专属文档整体移除，共用文档仅删除相关内容，保留其他能力的说明和测试断言；退役变更自身仅记录移除依据，不构成继续提供该功能的要求。

#### Scenario: 专属测试与验收链路退出
- **WHEN** 生成当前产品测试目标、nextest 选择规则、门计划、桌面驱动、测试基线和需求引用清单
- **THEN** 不再包含模型服务单元、GUI、HTTP、断连、回调、发现、生命周期或真实 OpenCode 验收及专属 Agent/消费者夹具，不构建 `jchtools-acp-fixture`，不保留服务专属环境配置、过滤规则或阶段；删除不改为 ignored、恒真测试、空阶段或伪造 PASS/NOT RUN 项。

#### Scenario: 混合测试与门保留其余行为
- **WHEN** 一个 GUI、日志、安装、布局或门脚本同时涉及模型服务和其他能力
- **THEN** 仅删除模型服务部分及其已无消费者的准备逻辑，更新实际范围与统计；其余有效断言、独立桌面授权、离线要求及既有门层级不变，不借退役跳过保留能力。

#### Scenario: 当前文档不再承诺旧功能
- **WHEN** 阅读仓库内需求、README、使用与工程指引、日志约定、E2E、合规说明或审查交接文档
- **THEN** 不再含模型服务专属章节、AH-01～AH-17 及 AH-A01～AH-A16 的当前交付/验收承诺、操作命令、安装说明、联网例外、引用和失效链接；工具清单与关于信息反映七个保留工具。CodeAgent Purpose 中相关对比文字同步移除，CA-01～CA-08 不变；不重写 Git 历史。

### Requirement: 模型服务退役不改变保留能力与用户数据

JchTools MUST 保留递归解压、目录整理、MD 整理、转 Markdown、Git 工具、截图 OCR、CodeAgent 及设置、关于的既有功能。共享 Xberg、推理模型资产、SQLite、日志和后台基础能力仅移除模型服务专属接入；不新增旧服务兼容、运行期数据清理或外部系统修改。

#### Scenario: 旧配置和目录不影响新版本
- **WHEN** 已有应用数据含 `acp_http_config` 或旧 `acp-workspace`
- **THEN** 新版本不再读取或应用服务配置，也不因这些残留启动服务、报配置错误或影响其他设置；不删除共用数据库、历史日志或用户资料，不为移除新增清理与迁移逻辑。

#### Scenario: 其他后台与模型仍独立运行
- **WHEN** 用户截图、转换文档或媒体，或使用 CodeAgent 维护 Token
- **THEN** 保留 Xberg、OCR/转录模型、托盘、热键、自启与凭据维护的原有行为及退出边界，不把这些能力视为模型服务的一部分，不修改外部 OMP/OpenCode、Agent 安装、账号或用户环境。
