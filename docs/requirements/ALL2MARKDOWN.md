## 1. 定位、入口与交付边界

- **T-01【已确认】** 在现有左侧导航新增独立的「转 Markdown」工具，类别为「文档」；文档、图片 OCR 与 MP4/M4A 转录均在该工具内操作。现有「递归解压」「目录整理」「MD 整理」「Git 工具」的名称、入口与功能保持不变。转换不自动合并、拆分、整理或删除源文件，也不自动调用其他工具；其他工具不自动启动转换。

- **T-02【已确认】** 转换结果用于本地阅读与检索，不增加主题合并、私人文档管理或历史转换产物管理。功能完整集成到当前 JchTools，不能只是从新 tab 打开旧 all2markdown 窗口、调用旧项目脚本或要求旧项目继续存在。安装版与便携版均提供该功能入口，按 T-05 初始化可选组件后独立运行；主程序包不包含模型或转换专用运行依赖。运行不得依赖旧源码目录、旧 `.venv`、旧启动脚本或用户历史模型缓存。旧项目退出与删除条件见 T-28。

- **T-03【原需求迁入】** 本功能的支持范围为 Windows 11 x64、支持 AVX2 的处理器、纯 CPU 推理；不要求 GPU，不将这一限制扩大到 JchTools 的其他工具。平台或必要组件不满足时，在开始前显示具体原因并禁止转换，不影响其他工具的正常使用。

- **T-04【已确认】** 全部用户操作在 JchTools 页面内完成，不保留独立 GUI、`init.cmd` 或 `all2markdown.cmd` 产品入口，不提供用户命令行界面；旧命令行的成功、部分失败、配置错误、预检失败、引擎启动失败和取消语义迁为可区分的界面任务状态。此约定与 P-06 一致，不要求保留旧脚本的数字退出码作为产品接口。

- **T-05【已确认】** 转 Markdown 是可选功能：安装包与便携 ZIP 只提供工具页面及必要接入，不携带其模型、转换引擎及专用运行依赖，也不将这些资产压缩内嵌进主 EXE 规避不打包要求。首次启动 JchTools、切换到该 tab 或使用旧工具时不自动下载；未初始化时页面明确显示缺少组件，提供由用户主动点击的「初始化」入口，未就绪前禁止开始转换。初始化按清单下载并安装到本功能独立管理的位置，不要求旧项目存在或让用户手工配置运行环境。初始化可重试并保留已校验资产，显示进度、失败原因及取消状态；缺少组件、初始化失败或取消都不影响旧工具。初始化完成后转换完全离线，不在转换过程中补下载或访问无关缓存。

- **T-06【原需求迁入；按需安装已确认】** 转换组件与模型使用可核对的版本和来源清单，记录实际版本、来源、大小与 SHA-256；安装资产时校验摘要，运行前离线检查必需资产完整性。资产缺失或损坏时明确指出缺失项并提供重新初始化的修复入口，不执行不完整环境、不冒充就绪。失败安装不得覆盖已验证的最终资产；显式选定镜像时失败不静默切换来源。第三方许可、notice 和应随附材料随对应可选组件提供并保留。模型、转换引擎及专用运行依赖均按 T-05 单独获取；不改变既有 7-Zip 引擎的 E 分区来源、捆绑和发布规则。

## 2. 输入、扫描与输出

- **T-07【原需求迁入；目录选择已确认】** 用户在页面选择输入目录与输出目录，递归处理输入目录中匹配类型的普通文件；不依赖旧项目根目录的 `input/` 或 `output/`。页面提供按文件类型分组的多选过滤，默认处理全部支持类型；未选择的类型不进入待转换列表，全部不选时不启动任务。至少提供 PDF、Office、图片、视频音频、其他文档分组；筛选只能缩小支持范围，不能使未支持的格式被假定为可转换。

- **T-08【原需求迁入】** 文档与图片的支持集合以本次固定 Xberg 运行时的格式清单为准，`.pdf`、`.docx`、`.pptx`、`.xlsx` 为必需类型；`.mp4`、`.m4a` 固定由本地媒体链路处理，不依据文件后缀相似性扩大媒体承诺。格式清单中的其他输入保留原转换能力，不把“100 多种格式”的宣传数量作为验收依据。Office 容器应按实际文档类型提取正文、字段、表格及嵌入内容，不能因为外层是 ZIP 就只输出归档文件清单。

- **T-09【已确认】** 输入文件只读：任何成功、失败或取消路径都不得改写、移动、改名或删除源文件。只读扫描纳入 Git 项目内以及隐藏/系统属性的匹配文件，不做 H-06 的 Git 整树排除；不跟随符号链接、junction 或其他 reparse point，链接边界采用 S-04 同口径。输入与输出目录不得相同；输出位于输入目录子树时，整棵输出子树不作为新输入，不因生成了 Markdown 而在同一任务内重复转换结果。目录无效或输入输出重合时在开始前明确提示，不启动转换。

- **T-10【原需求迁入】** 每个顶层输入最多生成一份 UTF-8 Markdown，命名保留原扩展名的含义并将该扩展名标记小写化：`a.docx` → `a_docx.md`，`a.PDF` → `a_pdf.md`，`a.mp4` → `a_mp4.md`。不同原始格式不因主体相同而共用一个输出文件。嵌入文档、嵌入表格与图片 OCR 内容归入对应顶层 Markdown，不另生成子文档结果文件。

- **T-11【已确认】** 默认保留相对输入根的目录层级，用户可在页面切换平铺输出。平铺模式忽略层级，同一批次映射到同一结果名的输入只转换稳定排序最前的一份，其余计为同名跳过，不自动改名为多份结果、不按内容去重、不删除源文件。排序按相对路径的各目录段、文件名逐级进行 Windows 不区分大小写的序数升序比较，相同键再按原始路径 UTF-16 单元序列决胜；输出名称占用同样不区分大小写。用户必须能区分同名跳过与转换失败，不能把被跳过的其他源文件报告为已转换。

- **T-12【原需求迁入】** 对应最终 Markdown 已存在时直接跳过，不覆盖、不删除，也不为本次转换增加覆盖确认选项。重复运行时已有结果的内容和修改时间均保持不变，界面显示跳过数量与原因。不为跳过已有结果额外生成永久进度文件或状态文件，不实现断点恢复或任务重放；再次启动属于新任务。

## 3. 文档、OCR 与嵌入内容

- **T-13【原需求迁入】** 文档解析、OCR、Layout/Table 识别和嵌入对象递归由固定版本 Xberg 完成，不在 JchTools 内另写 Office/PDF 解析器。常规模式保留中文 OCR、CPU execution provider、Layout 与表格识别的既有行为；原生文字、表格、可见字段和能够解析的嵌入文档进入同一份结果。大文档快速模式的明确例外见 T-18，不以快速模式暗中缩小常规模式能力。

- **T-14【原需求迁入】** 保留原文图片位置的路径引用，包括没有真实图片文件的占位路径；图片 OCR 文本放在对应位置附近。最终结果不写 Base64、不生成供用户使用的图片文件；图片 description、name、title 或 alt text 不冒充 OCR 正文。同一图片在多个位置被引用时保留各处位置，不能因为识别结果相同而合并掉正文中的重复位置。

- **T-15【原需求迁入】** 图片与 OCR 结果的对应关系稳定，不能按 ZIP 成员顺序、relationship 顺序或不确定容器迭代顺序把结果错配到其他图片。PPTX 普通文字与可见字段混排时字段值不丢失；DOCX 正文及相关部件、XLSX 工作表 drawing 的图片关联按来源正确解析。OLE 本体与其预览图分别处理：本体解析失败不能冒充预览 OCR 失败，预览 OCR 成功也不能冒充本体解析成功。

- **T-16【原需求迁入】** 单个图片或嵌入对象失败不阻止顶层文档其余可提取内容输出，但必须显示部分内容未提取及原因，不能报告内容完整成功。诊断至少区分资源缺失、格式未知、解码/光栅化失败、OCR 执行失败、OCR 无文字、结果无法关联；无文字不记为解码失败。嵌入内容递归受固定配置限制，超限不继续展开并说明范围，不将被跳过部分视为已转换。

- **T-17【依据现状恢复】** 嵌入子文档以 `## Embedded document: <显示名>` 分节合入结果，相同嵌入内容不重复追加；该去重不删除正文中本来存在的重复段落。提取失败的嵌入归档不能用原始 ZIP/XML 内部清单冒充正文；Visio 等嵌入内容有可用文本时保留可读文本。转换后规范化只消除渲染伪影：保留代码围栏与行内代码、Markdown 标记和有效重复正文；OCR 只有结构化位置数据而没有已渲染正文时，保持行、列与代码间距，不对长行随意折行，不重复输出父行和子词。

- **T-18【原需求迁入及现状恢复】** PDF、Word 家族、PowerPoint 家族先通过仅读结构或元数据获得页数/幻灯片数；超过 200 时走快速提取模式，200 及以下使用常规模式。快速模式关闭高开销 Layout 与图片 OCR，必须在界面日志说明文件、页数、模式及未执行图片 OCR 的限制，不把快速输出声称为全内容识别。XLSX 等无法获得页数的格式、页数读取失败或探测依赖不可用时使用常规模式，不因分流判断失败跳过文件。禁止以提高并发替代已明确的分流行为。

## 4. 媒体转录

- **T-19【原需求迁入；Rust 集成边界见 T-27】** MP4/M4A 固定使用本地音频解码 → Silero VAD → SenseVoice INT8 的离线 CPU 链路，固定中文识别与 ITN，不提供云端、自动语言选择或 Xberg 媒体后端切换。Rust 通过 FFmpeg 原生解码/重采样接口及 sherpa-onnx 原生推理接口承接原媒体链路，保持解码、语音切分与识别行为，具体分工见附录 D。移除旧 PyAV、NumPy、Python 解释器和 `.venv` 运行依赖，不因替换语言降低识别质量或缩减格式范围。

- **T-20【原需求迁入；术语保留已确认】** 媒体 Markdown 包含输入文件名、音频时长、语音片段数与逐段转录，片段带起止时间戳。无音轨时生成明确的「无音频轨道」说明；有音轨但无语音时生成「未检测到语音」说明，不能产生无解释的空文件。解码失败属于失败，不留下半成品 Markdown。保留原转录后的芯片/EDA 固定术语替换，唯一映射见附录 C；仅按固定字面映射替换，未知识别文本保持原样，不扩大为通用智能润色。

## 5. 任务、错误与资源边界

- **T-21【原需求迁入；初始化边界已确认】** 转换过程完全离线，遵守 P-03，不访问互联网或局域网服务，不上传文件、正文、OCR 结果、路径或日志，不读取无关用户历史缓存；只使用 T-05 / T-06 已安装并校验的固定运行时和模型。仅用户主动初始化时允许下载必要组件和模型，访问范围限于资产清单的来源及其下载重定向地址；不向下载请求附加用户资料、文件路径或日志。不得后台自动初始化、更新或在转换过程中联网补齐依赖。Rust 集成不继承旧 Python 客户端的 HTTP 通信方式作为产品需求，优先直接调用 Rust/原生接口或本地进程；该下载例外不允许调用远程转换服务，也不改变旧工具的联网权限。

- **T-22【原需求迁入及现状恢复】** 顶层文件严格串行转换，同一时刻只处理一个输入，单文件可使用内部 CPU 线程预算；不通过同时发送多个转换请求增加吞吐。转换在后台执行，长任务和大量日志不得阻塞 JchTools 窗口。提供开始、停止、任务状态、当前文件、成功/失败/跳过计数和耗时；总数未知时不编造百分比，总数已知后按实际完成推进，并显示长时间处理中的活动提示。

- **T-23【原需求迁入及现状恢复】** 停止在当前文件处理结束后生效，不再开始下一文件；已完成结果保留。界面明确显示停止请求已接收和正在等待当前文件结束；主动停止不作为错误，不自动回滚已有结果。运行中关闭窗口按 U-09 确认停止并在同一安全边界结束任务。单文件超时与引擎失败不能让后续文件永久失去继续处理或结束任务的机会。

- **T-24【原需求迁入】** 单个文件失败不终止整个批次，其余输入继续处理；失败计入最终统计并显示文件、阶段与原因。用法/配置错误、预检失败、引擎启动失败、单文件失败、未预期错误和用户取消必须可区分。用户界面最终状态使用中文，不依赖用户理解旧脚本退出码；部分失败不能显示全部成功。日志呈现和导出限制服从 U-10 / P-06。

- **T-25【原需求迁入】** 最终 Markdown 只在该文件输出完整成功后提交，写入失败或转换中断不得留下被当成成功结果的截断文件。临时输出只清理本次创建并拥有的内容，不删除旧结果或用户文件；不得以原子替换为由覆盖 T-12 保护的已有文件。正常结束或取消后输出目录不残留中间文件。开发与测试临时产物遵循 AGENTS.md 的 `.tmp/` 规则；发布运行不得依赖源码仓库的临时目录。

- **T-26【原需求迁入】** 私人输入只用于用户授权的本地只读转换；公开测试使用从零构造、无业务含义的合成夹具。仓库、需求文档、测试、公开问题和提交信息不包含内部源文件名、目录、正文、OCR 结果、截图、原图、附件、可识别元数据或可反查源文档的哈希；不得直接裁剪、匿名化或重打包内部文档充当公开夹具。界面可以为当前用户显示当前处理文件及必要诊断，不将这些信息导出或上传。

- **T-27【已确认；按用户要求细化语言边界】** 新增业务与集成逻辑全部使用 Rust，包括初始化下载与校验、扫描、过滤、排序、页数分流、队列、超时、停止、进度、错误处理、转换结果后处理与安全落盘；界面沿用当前 Slint 声明及 Rust 回调。本次迁移的文档、OCR、Layout/Table 和媒体功能均通过 Rust 接口或 Rust 对原生库的调用实现，不安装、携带、启动或嵌入 Python 解释器、`.venv`、pip 包或 Python 脚本；旧 Python 包装层全部由 Rust 接替。允许继续使用 Xberg 所需的原生组件、ONNX Runtime、sherpa-onnx、FFmpeg 及必要 Windows 系统接口，不要求把这些现成第三方 C/C++ 实现重写成 Rust，也不把模型文件视为 Python 依赖。具体职责、装配与验收边界见附录 D；不得为追求依赖树纯 Rust 而减少格式、替换已确定模型或降低识别能力。用户所说“除非真的必要”仅保留为发现具体能力阻塞时的例外处理原则：必须给出 Rust/原生方案不能合理满足的证据、最小 Python 范围及替代方案，并更新本条后才能实施，不是默认或隐含的 Python 回退。该约束针对新功能运行链路，不要求改写仓库既有开发/验收脚本，也不改变旧功能。

## 附录 D：Rust 与原生组件的职责及配合（T-27）

“功能全部由 Rust 集成”指无需 Python 即可运行全部迁入功能，不承诺第三方依赖的每一行源码都是 Rust。下表区分本项目编写的逻辑与复用的现成引擎；原生库通过 Rust 绑定或 C 接口调用，不要求另写一套 C/C++ 业务层。

| 能力 | 本项目承担的 Rust 工作 | 复用组件与非 Rust 边界 |
|---|---|---|
| 功能页、初始化、文件任务与结果 | Slint 回调、下载校验、扫描过滤、稳定排序、队列、超时/停止、进度、Markdown 后处理及落盘 | 界面使用既有 Slint 声明语言；无需 Python GUI、HTTP 客户端包装或启动脚本 |
| PDF/Office/图片及嵌入对象转换 | 直接调用固定版本 Xberg Rust 接口，传入内置配置、组织结果与诊断 | 复用 Xberg 及其格式所需原生依赖，不另写整套文档解析器，不假设格式依赖全为纯 Rust |
| 页数/幻灯片数探测 | 通过 Rust 可调用的元数据接口，或成熟 Rust PDF / ZIP / XML 库读取结构；失败按 T-18 回到常规模式 | 不再依赖 PyMuPDF；页数探测不得先执行全文 OCR 或 Layout |
| OCR、Layout 与表格结构识别 | 经 Xberg 调用模型，设置 CPU、固定模型路径及配置，接收识别结果 | 保留 ONNX Runtime 原生推理库；不以纯 Rust 推理后端替换尚未覆盖的 TATR 表格结构能力 |
| MP4/M4A 解码及重采样 | Rust 直接调用 FFmpeg 原生接口，管理音轨、样本缓冲、时长与错误 | FFmpeg 的 C 解码/重采样库替代 PyAV 包装；保持原支持的媒体范围，不把能读 MP4 容器等同于支持其中全部既有音频编码 |
| 语音切分与中文转录 | Rust 调用 sherpa-onnx 的 C 接口或对应 Rust 绑定，配置 Silero VAD / SenseVoice INT8，处理片段、时间戳与固定术语 | sherpa-onnx 的 C++ 引擎及 ONNX Runtime；无需 `sherpa_onnx` Python 包，样本数组与数值换算由 Rust 接替 NumPy |

推荐装配方式为「JchTools Rust 主程序 + 可选 Rust 转换工作进程」。主程序保留页面、初始化与任务控制；转换工作进程直接接入 Xberg、FFmpeg 和 sherpa-onnx，重依赖不链接进主 EXE，也不成为主程序启动的前置条件。工作进程属于内部实现，不提供新的用户命令行入口。工作进程、原生库及模型全部纳入 T-05 / T-06 的可选资产清单，初始化时单独获取，不能随主包或主 EXE 变相携带。

主程序与工作进程通过本地管道传递任务、进度、结果及错误，可使用结构化 JSON 消息；不需要启动旧项目的 HTTP 服务或监听网络端口。工作进程内的 Rust 代码直接调用 Rust API / 原生接口，读取已安装的模型。模型可在同一批次复用，顶层任务仍严格串行；工作进程异常或单文件超时由主程序识别并按 T-23 / T-24 / T-29 处理，不能拖垮旧工具。进程拆分不能改变已确认的“当前文件结束后停止”语义。

媒体兼容边界保持旧行为：选择第一条音轨，流式解码并重采样为 16 kHz 单声道有符号 16 位 PCM，再由 Rust 按原比例转换为 `f32` 样本送入 VAD；完整处理解码器、重采样器和 VAD 的尾部样本，时间戳按原采样位置计算。固定模型与原切分/识别参数保持一致，不能因为去掉 Python 包装而换成另一种识别链路。模型为离线推理资产，本功能不增加训练、导出或转换模型的 Python 工具链。

选型依据用于解释原生组件的必要性，不代替附录 A 的实际验收：[Xberg 特性清单](https://raw.githubusercontent.com/jchanghong023/xberg/main/crates/xberg/Cargo.toml)区分 Rust 接口与原生推理依赖，其纯 Rust `layout-tract` 路径未承接 TATR 表格结构识别；[sherpa-onnx v1.13.6 C 接口](https://raw.githubusercontent.com/k2-fsa/sherpa-onnx/v1.13.6/sherpa-onnx/c-api/c-api.h)提供 Silero VAD 与 SenseVoice（含语言和 ITN）配置；[FFmpeg 重采样接口](https://ffmpeg.org/doxygen/trunk/group__lswr.html)直接提供采样格式、声道与采样率转换。实际可选资产仍须按 T-06 固定版本、特性、编解码支持范围及摘要，不追随这些链接的主分支自动升级。
