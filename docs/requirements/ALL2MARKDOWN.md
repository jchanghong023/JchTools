# 转 Markdown 需求（T）

本文唯一维护文档、图片和媒体转换为本地 Markdown 的行为。全局约束见 [CONTRACT.md](CONTRACT.md)，共享引擎、获取与配置见 [XBERG-INFERENCE.md](XBERG-INFERENCE.md)，开发纪律见 [../../AGENTS.md](../../AGENTS.md)。规格自包含，产品不依赖旧项目或旧 Python 环境；本文件不记录实现或测试状态。

## 1. 定位、入口与交付边界

- **T-01** 在现有左侧导航新增独立的「转 Markdown」工具，类别为「文档」；文档、图片 OCR 与 MP4/M4A 转录均在该工具内操作。现有「递归解压」「目录整理」「MD 整理」「Git 工具」的名称、入口与功能保持不变。转换不自动合并、拆分、整理或删除源文件，也不自动调用其他工具；其他工具不自动启动转换。

- **T-02** 转换结果用于本地阅读与检索，不增加主题合并、私人文档管理或历史转换产物管理。功能完整集成到当前 JchTools，不能只是从新 tab 打开旧 all2markdown 窗口、调用旧项目脚本或要求旧项目继续存在。安装版与便携版均提供该功能入口；按 T-05 配置共享 Xberg 运行目录并初始化其余可选组件后独立运行。主程序包不包含模型或转换专用运行依赖。运行不得依赖旧源码目录、旧 `.venv`、旧启动脚本或用户历史模型缓存；用户明确指定的外部 Xberg 运行目录是唯一例外。旧项目退出与删除条件见 T-28。

- **T-03** 本功能的支持范围为 Windows 11 x64、支持 AVX2 的处理器、纯 CPU 推理；不要求 GPU，不将这一限制扩大到 JchTools 的其他工具。平台或必要组件不满足时，在开始前显示具体原因并禁止转换，不影响其他工具的正常使用。

- **T-04** 全部用户操作在 JchTools 页面内完成，不保留独立 GUI、`init.cmd` 或 `all2markdown.cmd` 产品入口，不提供用户命令行界面；旧命令行的成功、部分失败、配置错误、预检失败、引擎启动失败和取消语义迁为可区分的界面任务状态。此约定与 P-06 一致，不要求保留旧脚本的数字退出码作为产品接口。

- **T-05** 转 Markdown 是可选功能：安装包与便携 ZIP 只提供工具页面及必要接入，不携带其模型、转换引擎及专用运行依赖，也不将这些资产压缩内嵌进主 EXE 规避不打包要求。统一设置页按 XB-20 / XB-21 提供下载及已有目录两种来源；用户可选择包含 `xberg.exe`、`models/` 与所需 DLL 的现有 Xberg 运行目录，保存该路径供下次启动使用；允许重新选择，并明确显示路径无效或资产不完整的原因。用户提供的 Xberg 不复制到 JchTools 管理目录，也不重复下载；用户主动选择下载来源时按 XB-10 获取完整 Xberg，选版固定采用最新发布版本。首次启动 JchTools、切换到该 tab 或使用旧工具时不自动下载；未配置 Xberg 或其他可选组件未就绪时禁止开始转换。媒体模型及其原生依赖也使用该共享运行目录，按需检查其就绪状态；非 Xberg 可选组件在设置页保留用户主动点击的「初始化」入口，不要求旧项目存在。初始化可重试并保留已校验资产，显示进度、失败原因及取消状态；缺少组件、初始化失败或取消都不影响旧工具。全部就绪后转换完全离线，不在转换过程中补下载或访问无关缓存。 资产来源与安装位置不决定进程数量，运行边界统一按 XB-10 / XB-14 执行。 Xberg 目录按 XB-18 存入应用级 SQLite，重启后自动恢复，无需重新输入或再次确认保存。

- **T-06** 转换组件与模型使用可核对的版本和来源清单，记录实际版本、来源、大小与 SHA-256；下载安装资产时校验摘要（防下载损坏），失败安装不得覆盖已验证的最终资产，显式选定镜像时失败不静默切换来源。运行前离线检查必需资产：JchTools 自有可选组件仍按清单摘要校验，不完整或与清单不匹配时阻止使用；用户指定或共享的 Xberg 运行目录只检查场景所需成员（`xberg.exe`、模型、DLL 与许可文件）是否在场，不做成员摘要比对，允许用户自行替换或更新引擎版本，不因目录内文件字节与内置清单不一致而拒绝使用（成员内容问题由引擎加载失败如实报错，按 XB-07 分类）。资产缺失时明确指出缺失项；Xberg 提示重新选择或修复用户指定目录，其余可选组件提供重新初始化的修复入口。不执行成员缺失的不完整环境、不冒充就绪。第三方许可、notice 和应随附材料随对应可选组件提供并保留，用户指定目录内的 Xberg 许可材料须可查看。媒体模型及其原生依赖按 T-05 / XB-10 使用用户提供的共享目录；不改变既有 7-Zip 引擎的 E 分区来源、捆绑和发布规则。 Xberg 下载选版、真实引擎测试版本与下载完整性按 XB-10，运行时能力兼容性按 XB-09 校验；独立安装不豁免 XB-14。

## 2. 输入、扫描与输出

- **T-07** 用户在页面选择输入目录与输出目录，递归处理输入目录中匹配类型的普通文件；不依赖旧项目根目录的 `input/` 或 `output/`。页面提供按文件类型分组的多选过滤，默认处理全部支持类型；未选择的类型不进入待转换列表，全部不选时不启动任务。至少提供 PDF、Office、图片、视频音频、其他文档分组；筛选只能缩小支持范围，不能使未支持的格式被假定为可转换。

- **T-08** 文档与图片的支持集合以本次所选并通过能力检查的 Xberg 运行时的格式清单为准，`.pdf`、`.docx`、`.pptx`、`.xlsx` 为必需类型；`.mp4`、`.m4a` 固定由本地媒体链路处理（经固定版本 Xberg 的本地离线链路承接，见 T-19），不依据文件后缀相似性扩大媒体承诺。格式清单中的其他输入保留原转换能力，不把“100 多种格式”的宣传数量作为验收依据。Office 容器应按实际文档类型提取正文、字段、表格及嵌入内容，不能因为外层是 ZIP 就只输出归档文件清单。

- **T-09** 输入文件只读：任何成功、失败或取消路径都不得改写、移动、改名或删除源文件。只读扫描纳入 Git 项目内以及隐藏/系统属性的匹配文件，不做 H-06 的 Git 整树排除；不跟随符号链接、junction 或其他 reparse point，链接边界采用 S-04 同口径。输入与输出目录不得相同；输出位于输入目录子树时，整棵输出子树不作为新输入，不因生成了 Markdown 而在同一任务内重复转换结果。目录无效或输入输出重合时在开始前明确提示，不启动转换。

- **T-10** 每个顶层输入最多生成一份 UTF-8 Markdown，命名保留原扩展名的含义并将该扩展名标记小写化：`a.docx` → `a_docx.md`，`a.PDF` → `a_pdf.md`，`a.mp4` → `a_mp4.md`。不同原始格式不因主体相同而共用一个输出文件。嵌入文档、嵌入表格与图片 OCR 内容归入对应顶层 Markdown，不另生成子文档结果文件。

- **T-11** 默认保留相对输入根的目录层级，用户可在页面切换平铺输出。平铺模式忽略层级，同一批次映射到同一结果名的输入只转换稳定排序最前的一份，其余计为同名跳过，不自动改名为多份结果、不按内容去重、不删除源文件。排序按相对路径的各目录段、文件名逐级进行 Windows 不区分大小写的序数升序比较，相同键再按原始路径 UTF-16 单元序列决胜；输出名称占用同样不区分大小写。用户必须能区分同名跳过与转换失败，不能把被跳过的其他源文件报告为已转换。

- **T-12** 对应最终 Markdown 已存在时直接跳过，不覆盖、不删除，也不为本次转换增加覆盖确认选项。重复运行时已有结果的内容和修改时间均保持不变，界面显示跳过数量与原因。不为跳过已有结果额外生成永久进度文件或状态文件，不实现断点恢复或任务重放；再次启动属于新任务。

## 3. 文档、OCR 与嵌入内容

- **T-13** 文档解析、OCR、Layout/Table 与嵌入对象递归由 Xberg 完成，JchTools 不另写 Office/PDF 解析器。常规模式须保留原生文字、表格、可见字段、中文 OCR 及可解析嵌入内容；Layout/Table 能力以所选发布物的实际编译特性为边界，不声明未编译能力，快速模式的例外仅按 T-18。文档场景使用 CPU、中文语种、paddle-ocr 后端与 PP-OCRv6 tiny 模型基线，和截图模型严格隔离。检测、识别调参细节如 unclip_ratio、limit_side_len、识别批大小及 drop_score 交由引擎默认与效果校准承接，验收保证中文召回。文档 extract 请求只传 path，不携带 mode、模型或请求级转换配置；场景基线在引擎启动配置中声明。

- **T-14** 常规转换保留图片本体及 OCR 文本。每个顶层 Markdown 产物旁建立同名（名称中空白转下划线）的 _media 目录，保存引擎返回的图片；正文引用使用该目录的相对路径，本地 Markdown 阅读器可显示原图，OCR 文本保留在相应位置，正文不写 Base64。同一图片的多处引用保留各处位置，不因识别结果相同而合并正文位置，description、name、title 或 alt text 不冒充 OCR 正文。嵌入图片由引擎围栏感知地重编号并入宿主 images，不使用 docNNN- 前缀。JchTools 只执行引擎调用约定中的媒体目录前缀及图片字节落盘，不改写代码围栏中的字面图片名或其他正文。快速模式不提取图片（T-18），源文件不变。

- **T-15** 图片与 OCR 结果的对应关系稳定，不能按 ZIP 成员顺序、relationship 顺序或不确定容器迭代顺序把结果错配到其他图片。PPTX 普通文字与可见字段混排时字段值不丢失；DOCX 正文及相关部件、XLSX 工作表 drawing 的图片关联按来源正确解析。OLE 本体与其预览图分别处理：本体解析失败不能冒充预览 OCR 失败，预览 OCR 成功也不能冒充本体解析成功。

- **T-16** 单个图片或嵌入对象失败不阻止顶层文档其余可提取内容输出，但必须显示部分内容未提取及原因，不能报告内容完整成功。诊断至少区分资源缺失、格式未知、解码/光栅化失败、OCR 执行失败、OCR 无文字、结果无法关联；无文字不记为解码失败。嵌入内容递归受固定配置限制，超限不继续展开并说明范围，不将被跳过部分视为已转换。

- **T-17** 嵌入对象合入、重复追加消除、深度限制、Visio 页文本和正文规范化由引擎负责，最终结果在 document.content 内完整表达，文件名不冒充宿主标题。相同嵌入内容不重复追加，但不得删除宿主中本来存在的有效重复正文；代码围栏、行内代码、Markdown 标记、行列关系、缩进及内部空白均须保留。归档原始清单不得冒充成员正文，OCR 父行与子词不得重复输出。JchTools 不自行分节、判重、规范化或使用 children 分节兜底；仅执行 T-14 的媒体目录前缀与安全落盘，正文其余内容零改写，未提取内容按 T-16 披露。

- **T-18** 页数或幻灯片数探测与常规 / 快速自动分流由引擎完成，auto_fast_pages 的明确默认值为 500；PDF、Word 家族和 PowerPoint 家族超过阈值进入快速提取。快速模式关闭高开销 Layout 与图片 OCR，不提取图片，须转达 processing_warnings 中 auto_mode 来源的降级说明，显示文件、模式及未执行内容，不宣称全内容识别。XLSX 等无法获得页数、探测失败或依赖不可用时回常规模式，不因分流失败跳过文件。JchTools 不本地探测页数，不发送 mode，不通过提高顶层并发替代分流。

## 4. 媒体转录

- **T-19** MP4/M4A 固定使用本地音频解码 → Silero VAD → SenseVoice INT8 的离线 CPU 链路，固定中文识别与 ITN，不提供云端、自动语言选择或媒体后端切换。该链路由 XB-14 所规定的共享 Xberg 本地 stdio worker 承接（FFmpeg 解码/重采样、Silero VAD、SenseVoice INT8 及其原生运行库均在组件内），解码、语音切分与识别行为保持不变，具体分工见附录 D。移除旧 PyAV、NumPy、Python 解释器和 `.venv` 运行依赖，不因替换承接方降低识别质量或缩减格式范围。

- **T-20** 媒体 Markdown 包含输入文件名、音频时长、语音片段数与逐段转录，片段带起止时间戳。无音轨时生成明确的「无音频轨道」说明；有音轨但无语音时生成「未检测到语音」说明，不能产生无解释的空文件。解码失败属于失败，不留下半成品 Markdown。保留原转录后的芯片/EDA 固定术语替换，唯一映射见附录 C；仅按固定字面映射替换，未知识别文本保持原样，不扩大为通用智能润色。

## 5. 任务、错误与资源边界

- **T-21** 转换过程完全离线，遵守 P-03，不访问互联网或局域网服务，不上传文件、正文、OCR 结果、路径或日志，不读取无关用户历史缓存；只使用 T-05 / T-06 与 XB-18 / XB-19 已配置并通过存在性检查的共享 Xberg 运行目录（含媒体转录所需的模型与原生运行库）。仅用户在设置页主动下载 Xberg 或初始化其他可选组件时允许按清单下载必要资产（XB-20 / XB-25）；不向下载请求附加用户资料、文件路径或日志。不得后台自动初始化、更新或在转换过程中联网补齐依赖。Rust 集成不继承旧 Python 客户端的 HTTP 通信方式作为产品需求，优先直接调用 Rust/原生接口或本地进程；该下载例外不允许调用远程转换服务，也不改变旧工具的联网权限。

- **T-22** 顶层文件严格串行转换，同一时刻只处理一个输入，单文件可使用内部 CPU 线程预算；不通过同时发送多个转换请求增加吞吐。转换在后台执行，长任务和大量日志不得阻塞 JchTools 窗口。提供开始、停止、任务状态、当前文件、成功/失败/跳过计数和耗时；总数未知时不编造百分比，总数已知后按实际完成推进，并显示长时间处理中的活动提示。 本条的串行范围仅为转换文件之间，与截图并用的边界见 XB-15。

- **T-23** 点击「停止」后，立即接受并显示停止请求，尽快取消当前文件的本次处理，不以等待整个文件自然处理结束为停止前提；不再启动下一文件。不可中断的原生调用在返回后的安全检查点响应取消，不伪称立即结束。取消按请求隔离，不能关闭共享连接、杀死共享引擎或影响截图。当前文件未完整完成的 Markdown、图片及临时产物不作为成功结果保留，只清理本次创建并拥有的内容；此前已完成结果保持不变。主动停止不作为错误，任务与当前未完成文件如实显示取消状态，不自动回滚已完成结果。关闭主窗口经 U-09 确认后采用同一取消边界，后台与截图继续常驻；超时和引擎异常仍按 T-24 / T-25 / T-29 处理。

- **T-24** 单个文件失败不终止整个批次，其余输入继续处理；失败计入最终统计并显示文件、阶段与原因。用法/配置错误、预检失败、引擎启动失败、单文件失败、未预期错误和用户取消必须可区分。用户界面最终状态使用中文，不依赖用户理解旧脚本退出码；部分失败不能显示全部成功。日志呈现和导出限制服从 U-10 / P-06。

- **T-25** 最终 Markdown 只在该文件输出完整成功后提交，写入失败或转换中断不得留下被当成成功结果的截断文件。临时输出只清理本次创建并拥有的内容，不删除旧结果或用户文件；不得以原子替换为由覆盖 T-12 保护的已有文件。正常结束或取消后输出目录不残留中间文件。开发与测试临时产物遵循 AGENTS.md 的 `.tmp/` 规则；发布运行不得依赖源码仓库的临时目录。

- **T-26** 私人输入只用于用户授权的本地只读转换；公开测试使用从零构造、无业务含义的合成夹具。仓库、需求文档、测试、公开问题和提交信息不包含内部源文件名、目录、正文、OCR 结果、截图、原图、附件、可识别元数据或可反查源文档的哈希；不得直接裁剪、匿名化或重打包内部文档充当公开夹具。界面可以为当前用户显示当前处理文件及必要诊断，不将这些信息导出或上传。

## 附录 D：Rust 与原生组件的职责及配合（T-27）

“功能全部由 Rust 集成”指无需 Python 即可运行全部迁入功能，不承诺第三方依赖的每一行源码都是 Rust。下表区分本项目编写的逻辑与复用的现成引擎；原生库通过 Rust 绑定或 C 接口调用，不要求另写一套 C/C++ 业务层。

| 能力 | 本项目承担的 Rust 工作 | 复用组件与非 Rust 边界 |
|---|---|---|
| 功能页、初始化、文件任务与结果 | Slint 回调、下载校验、扫描过滤、稳定排序、队列、超时/停止、进度、媒体目录前缀处理及落盘 | 界面使用既有 Slint 声明语言；无需 Python GUI、HTTP 客户端包装或启动脚本 |
| PDF/Office/图片及嵌入对象转换 | 通过 Rust 调用 XB-14 的共享 Xberg worker，传入文档场景的内置配置、组织结果与诊断 | 复用 Xberg 及其格式所需原生依赖，不另写整套文档解析器，不假设格式依赖全为纯 Rust |
| 页数/幻灯片数探测及自动分流 | 接收引擎 auto_mode 警告并如实显示，不本地探测、不发送 mode | 探测、阈值与失败回常规由 Xberg 按 T-18 承接，不依赖旧 PyMuPDF |
| OCR、Layout 与表格结构识别 | 经共享 Xberg 调用各场景模型、接收结果，配置只声明实际编译能力 | 保留 ONNX Runtime 原生库；Layout/Table 以所选发布物实际编译特性为边界，不声明未编译的 TATR 能力，不为纯 Rust 依赖树降低已确认能力 |
| MP4/M4A 解码及重采样、语音切分与中文转录 | 经共享 Xberg worker 承接（T-19 / XB-14）：JchTools 串行提交转换文件，传入媒体路径、接收结构化转录结果，按 XB-17 管理超时、取消与生命周期 | FFmpeg 的 C 解码/重采样库、Silero VAD 与 SenseVoice INT8（sherpa-onnx C++ 引擎及 ONNX Runtime）全部在 Xberg 推理组件内执行；无需 `sherpa_onnx` Python 包，JchTools 不直接链接这些原生库 |

装配边界按 XB-14～XB-17：JchTools 保留页面、初始化与任务控制，文档转换与媒体转录（T-19）均经共享 Xberg worker 承接。文档资产使用设置页当前选定并通过运行时检查的本地 Xberg 目录；FFmpeg 与 sherpa-onnx 等重依赖随可选组件交付，不链接进主 EXE，也不成为主程序启动的前置条件。推理子进程属于内部实现，不提供新的用户命令行入口。用户提供的 Xberg 目录不由 JchTools 复制；主动下载来源按 XB-20 / XB-21；媒体模型与原生运行库也使用同一用户目录并按场景清单校验（XB-10），不能随主包或主 EXE 变相携带。

主程序与推理子进程通过本地管道（stdio JSON 行协议）传递任务、结果及错误；不需要启动旧项目的 HTTP 服务或监听网络端口。组件内的推理代码直接读取已安装的模型。模型常驻、场景配置与生命周期按 XB-16 / XB-17；顶层转换文件仍按 T-22 严格串行，允许与截图按 XB-15 并用。共享进程异常或单文件超时按 T-23 / T-24 / T-29 及 XB-08 处理，不能拖垮旧工具；不得沿用超时终结进程组、下一文件另起引擎的装配方式，停止按 T-23 尽快取消当前文件。
