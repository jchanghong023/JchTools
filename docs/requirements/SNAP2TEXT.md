> 本文件承载 TextSnap Layout 迁入 JchTools 的独立功能域。全局要求见 [CONTRACT.md](CONTRACT.md)，开发与验收纪律见 [../../AGENTS.md](../../AGENTS.md)。本文只定义需求、约束与验收条件，不代表功能已实现或验证通过。
>
> 用户已确认：直接用 Rust 重写，沿用 Slint；截图、热键、托盘交互保持 TextSnap 原行为；截图功能作为独立后台服务，模型常驻，关闭 JchTools 主界面不影响托盘及截图；TextSnap 原模型不变、主动初始化时按需下载；推理框架兼容则复用，否则单独下载；既有文档转换不变。下文标注「已确认」的条目整理这些决定，「原需求迁入」来自 TextSnap 的 `IMPLEMENTATION_PLAN.md`，「依据现状恢复」只补足该规格需要的确定性行为。整份编号需求已于 2026-09-27 经用户逐条确认进入实现；同日确认：规格未记载的五项原实现行为（小裁剪增强、密集代码横向拉伸重试、去重 tile.index 决胜、瓦片并集边缘量重算、透视裁剪细节）全部迁入，确定性定义见附录 B；首启托盘通知文案跟随当前生效热键（O-12）；可选资产经用户拥有的 GitHub Release 发布（附录 A）。不把来源代码或旧测试当作用户新增授权。
>
> 本次替代的旧边界：不再要求所有模型随 TextSnap 独立便携包交付；允许用户主动初始化时下载本功能资产，正常 OCR 仍完全离线。Python/Qt 单进程架构改为 Rust 用户会话后台进程与 Slint 界面。原 TextSnap 仓库只读冻结为行为对照，不先重构、不删除；Xberg 仓库默认不修改。

## 1. 定位与功能隔离

- **O-01【已确认】** 在 JchTools 统一工具注册表与左侧导航增加第六个独立工具「截图 OCR」，提供真实 Slint 功能页及必要的初始化、设置、状态入口；热键截图与托盘仍可独立使用，不要求主窗口或该页面保持打开。输出只是一份布局保真纯文本，不增加 Markdown 转换、阅读顺序模式、翻译、润色、截图历史或自动保存结果。

- **O-02【已确认】** 新增业务逻辑用 Rust 重写，界面沿用 JchTools 的 Slint，不引入第二套 GUI 框架，不携带或运行 Python、PySide6、PaddleOCR Python 包或旧项目脚本。允许 Rust 调用必要的 Windows 与原生推理接口；测试期间的 Python 对照不属于产品运行依赖。先完成可从内部测试入口运行的无头核心，再接入真实桌面交互；内部工作进程协议和测试入口不构成 P-06 所禁止的用户命令行产品。

- **O-03【已确认】** 截图 OCR 与递归解压、目录整理、MD 整理、转 Markdown、Git 工具相互独立；不改变其功能、默认值、模型、配置、运行目录或停止语义。特别是转 Markdown 继续按 [ALL2MARKDOWN.md](ALL2MARKDOWN.md) 运行，不依赖截图服务；截图服务未初始化、启动失败、退出或识别失败不阻止文档转换及其他工具运行。复用推理组件不得覆盖、升级或删除其他功能正在使用的文件；不兼容时为本功能独立安装。

- **O-04【原需求迁入】** 截图 OCR 面向 Windows 11 x64、CPU/AVX2 环境，不要求 GPU，不扩大 JchTools 其他功能的平台或处理器要求。首轮真实对照验收沿用 TextSnap 的 Windows 11 x64 / Intel i7-13700 环境；历史性能数据不作为迁入版已达到的指标。不支持 Linux、ARM、UAC 安全桌面、受保护视频或 DRM 表面；不承诺识别系统未提供的图像内容。

## 2. 可选资产、原模型与联网边界

- **O-05【已确认】** 主程序安装包与便携 ZIP 均提供工具入口，但不携带、压缩内嵌或变相捆绑本功能的模型、OCR worker、专用推理运行库与专用字体等重资产。主程序包体积不得因截图 OCR 明显增大；对比新增前后的同类发布产物并列出增量来源，不自定未经确认的 MB 门槛。未初始化时其他功能正常可用，首次启动、打开页面或按热键都不自动下载。

- **O-06【已确认】** 用户在图形界面主动初始化后，才允许从资产清单声明的来源及必要下载重定向获取缺少的组件并安装到本功能的用户缓存；显示进度、失败原因、取消与重试状态，保留已校验资产。失败或取消不能将半成品标为就绪，不覆盖已经校验的完整资产。模型、运行组件缓存是明确允许的资产落盘，不属于截图或识别内容；不把源项目的「程序目录除设置外不落盘」解释成禁止本次已确认的用户缓存。

- **O-07【已确认】** 检测、识别模型保持 TextSnap 原有 PP-OCRv6 small FP32 ONNX 转换产物不变，连同原有有序 18708 字字典成套使用，身份见附录 A。不得换成 tiny、medium 或 Xberg 中同名但摘要不同的 small 导出产物；不重新导出、量化或调整模型权重。识别输出 18710 类的 CTC 对应关系固定为 blank、原字典顺序与尾部空格；不得混配字典、增删字符、重排或去重。

- **O-08【已确认】** 推理框架与原生运行库优先复用已存在且经验证兼容的组件；兼容前提是能够加载 O-07 的原资产并满足本文件的推理和行为对齐要求，不能为了复用而更换模型或降低识别能力。无法复用时随本功能单独按需下载，重依赖不链接进主 EXE，不成为启动其他工具的前置条件。不要求使用完整 Xberg 文档转换框架；复用底层 Rust OCR 能力也须保留独立检测、合并后重裁及识别的行为边界。

- **O-09【原需求迁入；下载边界已确认】** 所有可选资产使用固定版本、来源、大小、SHA-256 及许可清单，安装时校验，加载前离线验证所需资产；模型和字典的不完整或不匹配必须阻止识别并明确提示。ONNX 是从官方 Paddle 权重转换得到的固定派生产物，不冒称官方原生 ONNX。下载清单应提供这些确定字节的可获取来源，不让用户在运行期安装 Python 或转换模型；必要许可及 notice 随对应可选资产保留。

- **O-10【已确认】** 联网权限仅限 O-06 的用户主动初始化；截图、预热、识别、布局和重试加载完全离线，只加载已校验的本地绝对路径，不访问云端 OCR、遥测、更新检查或在线模型解析，不在识别中补下载。下载请求不携带截图、识别文字、用户路径或日志。该例外仅作用于 O 分区，不借用或扩大 Git、T 分区的网络权限。

## 3. 后台服务、托盘与设置

- **O-11【已确认】** 截图功能由当前登录用户会话中的独立后台进程承载，拥有托盘、全局热键和常驻模型；不是需要管理员安装的 Windows 系统服务。主界面连接该服务并提供配置，关闭主界面或结束其 GUI 进程不结束截图服务、不卸载模型、不移除托盘、不注销热键；主界面不存在时仍可完成截图、识别和结果显示。重开主界面连接同一服务，不重复创建托盘或第二套模型。未初始化、资产损坏的情况按 O-06 / O-09 处理，不能声称模型已就绪。

- **O-12【原需求迁入；首启文案已确认】** 截图服务首次正常启动只驻留托盘，显示一次「已启动，按 <热键> 截图」提示，热键文案显示当前生效组合（默认 Ctrl+Alt+O），用户自定义后跟随新组合，不写死默认组合；托盘菜单保留「截图识别、设置、开机启动、退出」，设置入口在主界面关闭时仍能打开相应界面。后台开机启动不显示首次启动通知。该约定只描述截图服务，不将整个 JchTools 的正常启动改成只显示托盘。

- **O-13【原需求迁入；常驻已确认】** 已安装资产在服务启动后于后台校验、加载并预热，模型在服务存续期间复用，不按每次截图重新加载，也不因关闭结果窗或主窗口而卸载。模型状态至少区分未初始化、加载中、就绪和错误；加载中允许截图并提示等待模型就绪，加载失败保留明确重试入口，重试加载不联网。加载和推理不得阻塞托盘、框选或其他 GUI 交互。

- **O-14【原需求迁入】** 默认全局热键为 `Ctrl+Alt+O`，设置中通过按键录制修改；先成功注册新组合，再释放旧组合，冲突时保留原设置和旧热键并明确提示。每个当前用户会话仅一个截图服务实例；重复启动截图服务通知已有实例打开设置，不加载第二套模型。此行为不改变 JchTools 其他工具自身的启动规则。

- **O-15【原需求迁入】** 开机启动默认关闭，由用户显式启用或关闭，仅管理当前用户的本功能启动项，关闭时不删除其他应用的值；启用后在用户登录时后台启动截图服务，无需主窗口存在。服务位置改变后重新运行时更新本功能已启用的路径；说明移动或删除前应先关闭开机启动。设置只在用户保存时持久化，配置损坏时使用内存默认值并提示，不静默覆盖原文件。保留快捷键、开机启动、模型状态、重试加载，并增加本次必需的初始化入口，不暴露 OCR 阈值等高级参数。

- **O-16【已确认；退出细则原需求迁入】** 关闭 JchTools 主窗口与托盘「退出」是不同操作：前者不取消 OCR、不停止截图服务；后者明确退出截图服务，注销热键、移除托盘并释放模型，不终止文档转换等其他任务。服务正在识别时，退出先请求取消并等待当前不可中断推理调用安全返回；超过 10 秒才提供显式「强制退出」，不自动强杀。其他工具正在处理时关闭主窗口仍遵守 U-09 及对应分区，只停止那些受主窗口管理的任务。

## 4. 截图、任务与结果窗口

- **O-17【已确认；细则原需求迁入】** 沿用 Win32 GDI `BitBlt + CAPTUREBLT` 截图，在创建截图相关窗口前启用 PerMonitorV2；热键或托盘截图触发后先隐藏本应用相关窗口并刷新桌面合成，抓取鼠标所在显示器的物理像素，不包含鼠标指针、不支持跨屏框选。正确处理显示器物理原点、负坐标及 DPI，框选坐标必须与实际截取像素一致。

- **O-18【原需求迁入】** 在冻结截图上显示无边框遮罩与十字光标，支持任意拖动方向；松开左键立即提交，Esc 或右键取消，任一边小于 8 像素的选区按取消处理。底层画面继续变化不改变冻结图像。截图失败或系统不可捕获的表面不得冒充 OCR 成功。

- **O-19【原需求迁入】** 同一时刻只允许一个截图 OCR 任务；识别中再次按热键只提示「正在识别」，不排队、不取消已有任务。识别时显示「正在识别…」和取消按钮，Esc 同样取消；取消在当前不可中断 ONNX 调用返回后的瓦片或识别批次检查点生效，用户主动取消不作为错误，不伪造百分比。

- **O-20【原需求迁入】** 新截图前隐藏旧结果并仅在内存中暂存；新任务取消、识别为空或失败时恢复旧结果，成功后才替换。无文字、截图失败和 OCR 失败分别给出简短明确提示，不打开空白结果窗；失败状态不得携带原图或识别正文作为诊断内容。

- **O-21【原需求迁入；GUI 技术替换已确认】** 用 Slint 承接结果窗口：位于截图显示器工作区中央，初始宽高约为工作区的 80%，显示时激活但不永久置顶。文本只读，以 Noto Sans Mono CJK SC Regular 12pt 的半宽/全宽等宽显示效果呈现，禁用自动折行，按需提供水平和垂直滚动；调整窗口大小不改变文字、空格或真实换行。专用字体按 O-05 / O-09 获取，不能因缺少字体静默破坏布局对齐。

- **O-22【原需求迁入】** 支持鼠标选择、右键复制、Ctrl+C、Ctrl+A 和「复制全部」；复制布局生成的原文，不二次格式化。「复制全部」后关闭结果窗口，局部复制和 Ctrl+C 不自动关闭。关闭结果窗口清空其文字和内存引用，不结束后台服务；剪贴板由 Windows 管理，不自动清除。输出是普通文本的近似二维布局，不承诺恢复原始 Tab、字体大小、表格线、HTML 或交互。

## 5. OCR 与二维布局

- **O-23【原需求迁入】** 固定 CPU 推理、10 个算子内线程及顺序执行；只运行指定 det/rec，关闭额外文档方向分类、去畸变及文字方向分类模型。预处理、透视裁剪、后处理与 CTC 解码须与原行为对齐，不以模型名字和阈值相同代替等价验证。

- **O-24【原需求迁入】** 任一选区边长大于 1216 像素时按最大 1216×1216、相邻 128 像素重叠生成瓦片，覆盖右/下边界；小选区单次检测。检测固定 `limit_type=max`、`limit_side_len=1216`、`thresh=0.3`、`box_thresh=0.5`、`unclip_ratio=1.5`，检测框映射回原选区全局坐标，不以缩小整张大图替代分块。

- **O-25【原需求迁入；顺序依据现状恢复】** 先合并跨瓦片接缝片段，再去除重复检测框，合并后的文字框从原始选区重新裁剪，不能拼接已识别文字代替重裁识别。重复关系为 IoU ≥ 0.4 或交集/较小面积 ≥ 0.6，按传递关系分组，优先保留不接触内部瓦片边缘、边缘距离更大、检测分数更高的候选。接缝合并要求来自水平相邻重叠瓦片、接触相应内部边缘、垂直重叠 ≥ 0.6 且文字高度相近，不能把普通分栏间距当接缝；确定性细则见附录 B。

- **O-26【原需求迁入】** 对框做四边形透视矫正后批量识别，batch 固定为 8。先尝试原方向；高宽比 > 1.3 的疑似竖排加试 90°、270°；其余普通框首试分数 < 0.5 时加试 180°，取最高置信结果，不把两条规则叠加成所有框四方向重试。`text_rec_score_thresh=0.0`，只丢弃空串，不因低置信度丢掉小字或代码符号，不进行拼写纠正、繁简转换、语言模型补全或普通字符替换。

- **O-27【原需求迁入】** 按框基线、中心及垂直重叠聚类行；垂直重叠 ≥ 0.45 或基线差 ≤ 正文中位字高的 0.5 可归入同一行。每行按全局 x 从左到右排列，跨栏但 y 相近的文字仍输出在同一行，以空格保留栏距，不改成按栏目串行阅读。

- **O-28【原需求迁入】** 以框宽除以 Unicode 显示单元数的截尾中位数估算半角网格，CJK/全宽计 2、ASCII/半宽计 1；全局 x 和框间距按半角网格四舍五入为空格，发生碰撞时后框右移，不覆盖前框。以正文中位行距估算 y 网格，按比例保留段落、图片区和不等高分栏形成的空行。只裁公共上/左外边距，保留缩进、内部空格及空行，去掉每行尾随空格，最终不额外追加结尾换行；控制字符包括框内 Tab/换行转为空格，不改写普通 Unicode。与原行为对齐的边界定义见附录 B。

## 6. 隐私、资源与迁移边界

- **O-29【已确认；细则原需求迁入】** 不上传、不遥测，不主动持久化截图、OCR 文字、运行日志或历史；截图、裁剪图、进程间传递数据和结果只驻内存，不借临时图片文件、任务数据库、错误报告或调试日志落盘。任务结束或取消后释放本次图像引用，旧结果按 O-20 暂存、关闭后按 O-22 清除；常驻的是模型，不是截图历史。不声称安全擦除原生库已释放内存或控制 Windows 的剪贴板历史、分页文件等系统行为。

- **O-30【原需求迁入】** 错误提示明确区分资产未就绪、截图失败、无文字、推理失败和用户取消；可以在内存中生成由用户主动复制的去敏诊断，只含应用版本、系统版本、错误类型与去敏内部堆栈，不含截图、OCR 正文或用户路径。该窄范围诊断例外不提供日志文件导出，也不扩大其他工具的报告或日志导出权限。

- **O-31【已确认】** 产品运行不得依赖 TextSnap 源码、Python 环境或 `E:\xberg` 开发目录；引用的 Rust 依赖固定版本或提交，不依赖开发机绝对源码路径。后台进程使用本地进程通信，不因「服务」而增加网络监听或远程接口。源仓库只读保留为迁移期 oracle，不把本次授权扩展为改写、移动或删除其他仓库。

- **O-32【原需求迁入】** 记录后台预加载耗时、常驻内存、OCR 峰值内存、普通选区和 4K 识别耗时，不凭 Python 历史数据宣称 Rust 更快，不自定硬性延迟上限。服务常驻和与文档转换同时运行时界面仍响应、取消仍可操作；共享 CPU/内存造成的速度变化如实报告，不承诺零资源竞争。测试数据与测量产物只在开发验收环境产生，不作为产品运行日志。

## 附录 B：对齐所需确定性定义（O-24～O-28）

本附录从冻结 TextSnap 的纯逻辑行为恢复，目的是让同一组构造坐标得到同一结果，不要求照搬 Python 类或文件组织；发现与上文明文行为冲突时先记录差异，不依据代码静默改写需求。

| 行为 | 确定性定义 |
|---|---|
| 瓦片尾部 | 从 0 起按 1088 像素步长推进；尾块裁至选区边界，不强行补足 1216 或回移扩大重叠；按先 y 后 x 的稳定顺序处理 |
| 内部边缘 | 距最近内部边缘 ≤ 2 像素视为接触；整张选区的外边缘不算内部接缝 |
| 接缝高度与距离 | 两框较小高度/较大高度 ≥ 0.65；接缝边缘容差为 max(4 像素, 较大字高×0.5)；横向间隙不超过瓦片重叠宽度加较大字高×2；满足 O-25 其余条件后按传递关系合并 |
| 方向平局 | 分数相同优先非空文字，仍同分按 0°、180°、90°、270° 顺序决胜 |
| 字符宽度 | Unicode East Asian Width 为 W/F 的字符计 2，其他计 1；有组合类的组合字符计 0，Unicode Cc 控制字符先替换为空格 |
| 截尾中位数 | 只取正值；样本数 ≥ 5 时两端各去掉 max(1, floor(数量×0.1)) 项，再取中位数；正文高度及横向网格无有效值时回退 1 |
| 行归属平局 | 文字框按顶部、基线、左边排序；候选行优先垂直重叠更大者，其次基线差更小者；行的顶部、底部和基线取成员中位数，行按中心 y、最左 x 排序，行内按左边、右边排序 |
| 纵向间距 | 取相邻行正基线差，排除大于正文高度×3 的间隔后求截尾中位数；不足时用正文高度×1.4，无有效高度时用 1；每一输出行至少在上一行之后 |
| 网格舍入 | 非负数使用 floor(x+0.5)，不使用银行家舍入；横向同时满足绝对位置、与前框的物理间隔及不覆盖已输出字符三个条件 |
| 小裁剪增强 | 送识别前，裁剪图高度 < 20 像素时按 2× INTER_CUBIC 等比放大（不改变宽高比与方向判据输入）；高度 ≥ 20 像素原样送识别 |
| 密集代码拉伸重试 | 初识别后，源高 ∈ [20,40] 像素且宽/高 ≥ 12 且首试文本 ≥ 40 字符、含 ≥ 3 个竖线且（含 `::` 或 ≥ 2 个下划线）的框，以 1.5× 横向 INTER_LANCZOS4 拉伸重识别；新文本非空且分数 ≥ 初次 − 0.02 且（更长，或同长且分数更高）时替换 0° 尝试；替换后的文本与分数参与 180° 加试判据及方向平局决胜 |
| 去重输出顺序 | 去重与合并后的候选按（顶部、左边、来源瓦片 index）稳定排序进入识别；index 为瓦片生成顺序（先 y 后 x） |
| 合并候选边缘量 | 接缝合并产生的候选在成员瓦片的并集矩形上重算内部边缘距离与接触标志；外接矩形取并集成员整体包围盒，检测分数取成员最大值 |
| 透视裁剪 | 4 顶点互异、凸（叉积同号）且面积非零方可裁剪；目标宽取上/下边较长者、高取左/右边较长者，按原实现的 Python `round`（半偶/银行家）舍入取整且任一边 < 2 像素判失败；重采样 INTER_CUBIC，边界复制填充；旋转重试仅接受 90/180/270 整数度 |
