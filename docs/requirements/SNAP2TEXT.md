# 截图 OCR 需求（O）

本文唯一维护热键或托盘截图、识别与布局保真纯文本结果，以及复用截图识别通道的 jchocr 命令。全局约束见 [CONTRACT.md](CONTRACT.md)，共享引擎、设置与后台生命周期见 [XBERG-INFERENCE.md](XBERG-INFERENCE.md)，开发纪律见 [../../AGENTS.md](../../AGENTS.md)。模型身份与确定性技术附录是规范性要求；本文件不记录实现或测试状态。

## 1. 定位与功能隔离

- **O-01** 在 JchTools 统一工具注册表与左侧导航增加第六个独立工具「截图 OCR」，提供真实 Slint 功能页，按 XB-24 仅保留快捷键设置与后台服务状态；随包资产自动发现，离线检查和故障恢复集中到设置页，不要求用户下载或手动配置截图组件；热键截图与托盘仍可独立使用，不要求主窗口或该页面保持打开。输出只是一份布局保真纯文本，不增加 Markdown 转换、阅读顺序模式、翻译、润色、截图历史或自动保存结果。

- **O-02** 新增业务逻辑用 Rust 重写，界面沿用 JchTools 的 Slint，不引入第二套 GUI 框架，不携带或运行 Python、PySide6、PaddleOCR Python 包或旧项目脚本。允许 Rust 调用必要的 Windows 与原生推理接口；测试期间的 Python 对照不属于产品运行依赖。先完成可从内部测试入口运行的无头核心，再接入真实桌面交互；内部工作进程协议和测试入口不构成 P-06 所禁止的用户命令行产品。

- **O-03** 截图 OCR 与递归解压、目录整理、MD 整理、转 Markdown、Git 工具相互独立；不改变其功能、默认值、模型、配置或停止语义。特别是转 Markdown 继续按 [ALL2MARKDOWN.md](ALL2MARKDOWN.md) 运行，不依赖截图服务；截图服务尚未加载、启动失败、退出或识别失败不阻止文档转换及其他工具运行。截图与文档转换的必需资产随包完整交付，按 XB-09 / XB-10 / XB-14 自动使用同一共享运行目录及至多一个 Xberg，模型保持独立；复用推理组件不得覆盖、升级或删除其他功能正在使用的文件，不因功能隔离要求用户另行安装截图或文档组件。未下载 FFmpeg 和音频模型不得阻止共享 worker、截图服务正常启动，也不影响截图、文档/图片 OCR、jchocr 及其他工具。

- **O-04** 截图 OCR 面向 Windows 11 x64、CPU/AVX2 环境，不要求 GPU，不扩大 JchTools 其他功能的平台或处理器要求。首轮真实对照验收沿用 TextSnap 的 Windows 11 x64 / Intel i7-13700 环境；历史性能数据不作为迁入版已达到的指标。不支持 Linux、ARM、UAC 安全桌面、受保护视频或 DRM 表面；不承诺识别系统未提供的图像内容。

## 2. 随包资产、固定模型与联网边界

- **O-05** 主程序安装包与便携 ZIP 均随附截图服务程序、共享 Xberg 引擎、截图和文档/图片转换各自所需的独立 OCR 模型与字典、DLL/原生运行库、字体和许可，按 XB-10 / XB-27 形成安装或解包后即可离线使用的完整交付，不要求用户额外下载截图或文档组件、手填目录或准备旧缓存。Noto Sans Mono CJK SC Regular 字体及 OFL 许可证直接内置于截图服务程序，无需用户额外初始化字体或安装系统字体；其他截图与文档重依赖随分发包置于共享运行目录，不要求链接或压缩内嵌到主 EXE。新安装、升级及后台登录自启均可离线使用随包资产，字体或程序损坏仍明确报错。两种分发默认均不带 FFmpeg，亦不得通过主 EXE 链接或压缩内嵌规避；FFmpeg 及其必要 DLL / 许可、音频转录模型作为音频转写可选资产，仅按 P-03 / XB-27 在用户于设置页明确发起后单独下载，不构成截图前置条件。sherpa-onnx、共享 ONNX Runtime 等既定随包运行库交付不变。

- **O-06** 截图后台程序、结果窗字体和许可证随主包交付，字体内置，不在运行时下载、不要求用户额外初始化。设置页保留离线检查及修复指引；随包程序、字体或生效共享目录中的截图推理资产缺失、损坏时提示从安装包修复或重新安装，便携版提示重新解包，不要求下载截图/文档组件，不静默降级字体。推理组件按 XB-18 / XB-20 / XB-21 读取或自动发现唯一生效共享目录，新装默认包内，已有配置恢复及迁移未完成时不得自行切换来源；运行时按 O-09 / XB-09 检查，不另下载或启动独立 Xberg，不提供手动目录入口。FFmpeg 与音频模型等音频转写可选资产的主动下载进度、失败、取消、重试及有效资产/配置保护按 XB-20 / XB-21，资产边界与路径事务按 XB-27；该下载不得替换已有有效共享引擎或随包 DLL，不成为截图初始化步骤，也不用于修复缺损的截图资产。

- **O-07** 截图检测采用 Xberg 正式发布的 PP-OCRv6 medium FP32 ONNX，识别保持 TextSnap 原有 PP-OCRv6 small FP32 ONNX，连同原有有序 18708 字字典成套使用，确定字节身份见附录 A。仅检测模型由原 small 切换为 medium，不改文档 tiny、截图识别模型、字典及布局规则；不得自动换成其他模型或同名但摘要不同的导出产物，不重新导出、量化或调整模型权重。识别输出 18710 类的 CTC 对应关系固定为 blank、原字典顺序与尾部空格；不得混配字典、增删字符、重排或去重。

- **O-08** 推理框架与原生运行库优先复用已存在且经验证兼容的组件；兼容前提是能够加载 O-07 的固定资产并满足本文件的推理和行为对齐要求，不能为了复用而更换模型或降低识别能力。XB-18 / XB-21 确定的生效共享目录中所需资产缺失或不兼容时明确报错并引导从安装包修复、重新安装或重新解包，不自行切换到包内或旧目录，不引导另行下载共享 Xberg；截图与文档所需重依赖随包提供而不要求链接进主 EXE，不成为启动其他工具的前置条件。单独使用截图不要求先配置文档转换功能或下载 FFmpeg、音频模型；不能因缺少 FFmpeg DLL 而阻止共享 worker 或截图服务启动。推理由 XB-14 的共享 Xberg 承接，仍须保留独立检测、合并后重裁及识别的行为边界，运行时不兼容按 O-09 / XB-09 / XB-10 报错。

- **O-09** 随包资产使用按 XB-10 锁定的精确版本、来源、大小、SHA-256 及许可清单，并在构建取材和组包时校验完整性；不以用户运行时下载代替随包交付。加载前离线检查所需资产存在；JchTools 自有后台工作进程、结果窗字体等不完整或与其清单不匹配必须阻止使用并明确提示从安装包修复、重新安装或重新解包。共享 Xberg 推理组件按 XB-09 只做成员存在性及必要协议检查，文件内容问题由引擎加载失败如实报错，不在运行时比对成员摘要，保留用户替换文件的权利。ONNX 是从官方 Paddle 权重转换得到的固定派生产物，不冒称官方原生 ONNX；清单记录确定字节的可获取来源，不让用户在运行期安装 Python 或转换模型，必要许可及 notice 随包保留。

- **O-10** 普通启动、tab 切换、截图、预热、识别、布局、文档转换、媒体处理和重试加载均不得自动联网下载或更新；截图仅加载 XB-18 / XB-21 确定的唯一生效共享目录中的本地绝对路径资产，运行检查按 O-09 / XB-09，不强制比对共享 Xberg 成员摘要。新装默认使用包内共享目录；已有配置及升级迁移未完成时继续使用原有效目录，成功保存并在安全边界统一切换前，截图服务、jchocr 与文档等场景不得各自改用包内路径或另起引擎，迁移规则仅按 XB-21。不得访问云端 OCR、遥测、更新检查或在线模型解析，不在识别中补下载。FFmpeg 与音频模型等音频转写可选资产仅按 P-03 / XB-27 在用户于设置页明确发起后下载，媒体所需资产未就绪时提示主动下载；下载请求不携带截图、识别文字、用户路径或日志，不借用或扩大 Git、T 分区的网络权限，系统代理与 TLS 行为仍按 P-09。jchocr 显式图片 URL 输入仅按 O-34 处理，不授权下载截图运行资产。

## 3. 后台服务、托盘与设置

- **O-11** 截图功能由当前登录用户会话中的独立后台进程承载，拥有托盘、全局热键，并使用 XB-14 / XB-16 规定的共享引擎与截图常驻模型；不是需要管理员安装的 Windows 系统服务。打开 GUI 后按 XB-22 读取或自动发现 XB-18 / XB-21 确定的唯一生效共享目录并启动或连接该服务，新装默认包内，已有配置及迁移未完成时仍使用原有效目录，不要求先进入设置页或下载 FFmpeg、音频模型，未下载这些可选资产时共享 worker 与截图服务仍须正常启动；配置统一由设置页管理，关闭主界面或结束其 GUI 进程不结束截图服务、不卸载模型、不移除托盘、不注销热键；主界面不存在时仍可完成截图、识别和结果显示。重开主界面连接同一服务，不重复创建托盘或第二套模型。截图所需资产缺失、损坏的情况按 O-06 / O-09 处理，不能声称模型已就绪。

- **O-12** 截图服务首次正常启动只驻留托盘，显示一次「已启动，按 <热键> 截图」提示，热键文案显示当前生效组合（默认 Ctrl+Alt+O），用户自定义后跟随新组合，不写死默认组合；统一托盘菜单提供「打开主界面、截图识别、设置、开机启动、退出后台服务」，设置入口在主界面关闭时仍能打开相应界面。后台开机启动不显示首次启动通知。该约定只描述截图服务，不将整个 JchTools 的正常启动改成只显示托盘。
  - 托盘使用与主程序一致的 JchTools 品牌图标，不使用 Windows 通用程序图标替代；品牌图像随后台程序内置，离线启动不依赖外部图标文件，按系统通知区小图标尺寸显示并保留透明圆角。

- **O-13** XB-18 / XB-21 确定的唯一生效共享目录中的截图推理资产在服务启动后于后台检查、加载并预热，新装默认包内，迁移未完成时不自行切源；检查边界按 O-09 / XB-09。模型在服务存续期间复用，不按每次截图重新加载，也不因关闭结果窗或主窗口而卸载。模型状态至少区分未加载、加载中、就绪和错误；加载中允许截图并提示等待模型就绪，加载失败保留明确重试入口，重试加载不联网。加载和推理不得阻塞托盘、框选或其他 GUI 交互。 场景常驻与隔离见 XB-16，不因转换任务切换而重载截图模型。

- **O-14** 默认全局热键为 `Ctrl+Alt+O`，设置中通过按键录制修改；先成功注册新组合，再释放旧组合，冲突时保留原设置和旧热键并明确提示。每个当前用户会话仅一个截图服务实例；重复启动截图服务通知已有实例打开设置，不加载第二套模型。此行为不改变 JchTools 其他工具自身的启动规则。

- **O-15** 登录自启默认关闭，由用户显式启用或关闭，仅管理当前用户本功能启动项，关闭不删除其他应用的值；启用后登录时后台启动，无需主窗口。服务位置改变后重新运行时更新本功能已启用路径，移动或删除前应关闭自启。快捷键在截图页面配置并显示后台状态；登录自启、离线资产检查与模型重试在统一设置页管理，托盘保留对应入口，不开放 OCR 阈值等高级参数。截图设置仅在用户保存时持久化，损坏时使用内存默认值并提示，不静默覆盖原文件；共享 Xberg 目录、FFmpeg 与音频模型等可选资产状态及相关设置的持久化与恢复统一遵循 XB-18 / XB-20 / XB-21，资产边界与路径事务按 XB-27，不保留三功能勾选。新装或解包后无 SQLite、无旧配置也必须自动发现包内目录，不以已下载 FFmpeg 和音频模型为前提；旧配置读取或安全迁移遵循 XB-21，不删除用户目录及有效资料，不以旧目录、旧缓存或既往功能选择作为使用随包截图资产的前提。

- **O-16** 关闭 JchTools 主窗口与托盘「退出」是不同操作：前者不取消 OCR、不停止截图服务；后者按 XB-23 明确退出全部后台，先确认并安全结束在途任务，再注销热键、移除托盘、释放资源并退出本应用共享引擎。服务正在识别时，退出先请求取消并等待当前不可中断推理调用安全返回；超过 10 秒才提供显式「强制退出」，不自动强杀；强制退出不跳过其他在途任务的安全停止，不强杀仍有其他任务的共享 Xberg；所有任务结束后按 XB-23 清理后台。其他工具正在处理时关闭主窗口仍遵守 U-09 及对应分区，只停止那些受主窗口管理的任务。

## 4. 截图、任务与结果窗口

- **O-17** 沿用 Win32 GDI `BitBlt + CAPTUREBLT` 截图，在创建截图相关窗口前启用 PerMonitorV2；热键或托盘截图触发后先隐藏本应用相关窗口并刷新桌面合成，抓取鼠标所在显示器的物理像素，不包含鼠标指针、不支持跨屏框选。正确处理显示器物理原点、负坐标及 DPI，框选坐标必须与实际截取像素一致。

- **O-18** 在冻结截图上显示无边框遮罩与十字光标，支持任意拖动方向；松开左键立即提交，Esc 或右键取消，任一边小于 8 像素的选区按取消处理。底层画面继续变化不改变冻结图像。截图失败或系统不可捕获的表面不得冒充 OCR 成功。

- **O-19** 同一时刻只允许一个截图 OCR 任务；识别中再次按热键只提示「正在识别」，不排队、不取消已有任务。识别时显示「正在识别…」和取消按钮，Esc 同样取消；取消在当前不可中断 ONNX 调用返回后的瓦片或识别批次检查点生效，用户主动取消不作为错误，不伪造百分比。 该单任务限制只约束截图请求；与转换并用及取消隔离分别见 XB-15 / XB-17。

- **O-20** 新截图前隐藏旧结果并仅在内存中暂存；新任务取消、识别为空或失败时恢复旧结果，成功后才替换。无文字、截图失败和 OCR 失败分别给出简短明确提示，不打开空白结果窗；失败状态不得携带原图或识别正文作为诊断内容。

- **O-21** 用 Slint 承接结果窗口：位于截图显示器工作区中央，初始宽高约为工作区的 80%，显示时激活但不永久置顶。文本只读，以 Noto Sans Mono CJK SC Regular 12pt 的半宽/全宽等宽显示效果呈现，禁用自动折行，按需提供水平和垂直滚动；调整窗口大小不改变文字、空格或真实换行。专用字体按 O-05 内置，并按 O-09 校验，不能因缺少字体静默破坏布局对齐。

- **O-22** 支持鼠标选择、右键复制、Ctrl+C、Ctrl+A 和「复制全部」；复制布局生成的原文，不二次格式化。「复制全部」后关闭结果窗口，局部复制和 Ctrl+C 不自动关闭。关闭结果窗口清空其文字和内存引用，不结束后台服务；剪贴板由 Windows 管理，不自动清除。输出是普通文本的近似二维布局，不承诺恢复原始 Tab、字体大小、表格线、HTML 或交互。

## 5. OCR 与二维布局

- **O-23** 固定 CPU 推理、10 个算子内线程及顺序执行；只运行指定 det/rec，关闭额外文档方向分类、去畸变及文字方向分类模型。预处理、透视裁剪、后处理与 CTC 解码须与原行为对齐，不以模型名字和阈值相同代替等价验证。

- **O-24** 任一选区边长大于 1216 像素时按最大 1216×1216、相邻 128 像素重叠生成瓦片，覆盖右/下边界；小选区单次检测。检测固定 `limit_type=max`、`limit_side_len=1216`、`thresh=0.3`、`box_thresh=0.5`、`unclip_ratio=1.5`，检测框映射回原选区全局坐标，不以缩小整张大图替代分块。

- **O-25** 先合并跨瓦片接缝片段，再去除重复检测框，合并后的文字框从原始选区重新裁剪，不能拼接已识别文字代替重裁识别。重复关系为 IoU ≥ 0.4 或交集/较小面积 ≥ 0.6，按传递关系分组，优先保留不接触内部瓦片边缘、边缘距离更大、检测分数更高的候选。接缝合并要求来自水平相邻重叠瓦片、接触相应内部边缘、垂直重叠 ≥ 0.6 且文字高度相近，不能把普通分栏间距当接缝；确定性细则见附录 B。

- **O-26** 对框做四边形透视矫正后批量识别，batch 固定为 8。先尝试原方向；高宽比 > 1.3 的疑似竖排加试 90°、270°；其余普通框首试分数 < 0.5 时加试 180°，取最高置信结果，不把两条规则叠加成所有框四方向重试。`text_rec_score_thresh=0.0`，只丢弃空串，不因低置信度丢掉小字或代码符号，不进行拼写纠正、繁简转换、语言模型补全或普通字符替换。

- **O-27** 按框基线、中心及垂直重叠聚类行；垂直重叠 ≥ 0.45 或基线差 ≤ 正文中位字高的 0.5 可归入同一行。每行按全局 x 从左到右排列，跨栏但 y 相近的文字仍输出在同一行，以空格保留栏距，不改成按栏目串行阅读。

- **O-28** 以框宽除以 Unicode 显示单元数的截尾中位数估算半角网格，CJK/全宽计 2、ASCII/半宽计 1；全局 x 和框间距按半角网格四舍五入为空格，发生碰撞时后框右移，不覆盖前框。以正文中位行距估算 y 网格，按比例保留段落、图片区和不等高分栏形成的空行。只裁公共上/左外边距，保留缩进、内部空格及空行，去掉每行尾随空格，最终不额外追加结尾换行；控制字符包括框内 Tab/换行转为空格，不改写普通 Unicode。与原行为对齐的边界定义见附录 B。

## 附录 B：对齐所需确定性定义（O-24～O-28）

本附录从冻结 TextSnap 的纯逻辑行为恢复，目的是让同一组构造坐标得到同一结果，不要求照搬 Python 类或文件组织；发现与上文明文行为冲突时先记录差异，不依据代码静默改写需求。

| 行为 | 确定性定义 |
|---|---|
| 瓦片尾部 | 从 0 起按 1088 像素步长推进；尾块裁至选区边界，不强行补足 1216 或回移扩大重叠；按先 y 后 x 的稳定顺序处理 |
| 内部边缘 | 距最近内部边缘 ≤ 2 像素视为接触；整张选区的外边缘不算内部接缝 |
| 接缝高度与距离 | 两框较小高度/较大高度 ≥ 0.65；接缝边缘容差为 max(4 像素, 较大字高×0.5)；横向间隙不超过瓦片重叠宽度加较大字高×2；满足 O-25 其余条件后按传递关系合并 |
| 方向平局 | 分数相同优先非空文字，仍同分按 0°、180°、90°、270° 顺序决胜 |
| 字符宽度 | Unicode East Asian Width 为 W/F 的字符计 2，其他计 1；有组合类的组合字符计 0，Unicode Cc 控制字符先替换为空格 |
| 截尾中位数 | 只取正值；样本数 ≥ 5 时两端各去掉 max(1, floor(数量×0.1)) 项，再取中位数；正文高度及横向网格无有效值时回退 1 |
| 行归属平局 | 文字框按顶部、基线、左边排序；候选行优先垂直重叠更大者，其次基线差更小者；行的顶部、底部和基线取成员中位数，行按中心 y、最左 x 排序，行内按左边、右边排序 |
| 纵向间距 | 取相邻行正基线差，排除大于正文高度×3 的间隔后求截尾中位数；不足时用正文高度×1.4，无有效高度时用 1；每一输出行至少在上一行之后 |
| 网格舍入 | 非负数使用 floor(x+0.5)，不使用银行家舍入；横向同时满足绝对位置、与前框的物理间隔及不覆盖已输出字符三个条件 |
| 小裁剪增强 | 送识别前，裁剪图高度 < 20 像素时按 2× INTER_CUBIC 等比放大（不改变宽高比与方向判据输入）；高度 ≥ 20 像素原样送识别 |
| 密集代码拉伸重试 | 初识别后，源高 ∈ [20,40] 像素且宽/高 ≥ 12 且首试文本 ≥ 40 字符、含 ≥ 3 个竖线且（含 `::` 或 ≥ 2 个下划线）的框，以 1.5× 横向 INTER_LANCZOS4 拉伸重识别；新文本非空且分数 ≥ 初次 − 0.02 且（更长，或同长且分数更高）时替换 0° 尝试；替换后的文本与分数参与 180° 加试判据及方向平局决胜 |
| 去重输出顺序 | 去重与合并后的候选按（顶部、左边、来源瓦片 index）稳定排序进入识别；index 为瓦片生成顺序（先 y 后 x） |
| 合并候选边缘量 | 接缝合并产生的候选在成员瓦片的并集矩形上重算内部边缘距离与接触标志；外接矩形取并集成员整体包围盒，检测分数取成员最大值 |
| 透视裁剪 | 4 顶点互异、凸（叉积同号）且面积非零方可裁剪；目标宽取上/下边较长者、高取左/右边较长者，按原实现的 Python `round`（半偶/银行家）舍入取整且任一边 < 2 像素判失败；重采样 INTER_CUBIC，边界复制填充；旋转重试仅接受 90/180/270 整数度 |
