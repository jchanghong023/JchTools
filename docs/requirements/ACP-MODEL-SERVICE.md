# ACP HTTP 模型服务需求（AH）

本文唯一维护独立 ACP HTTP 模型服务的接口、Agent 适配、配置与后台生命周期。全局联网、交付与 GUI 约束见 [CONTRACT.md](CONTRACT.md)，开发及执行授权纪律见 [../../AGENTS.md](../../AGENTS.md)。2026-10-09 已确认进入全部实现阶段及源码纳入范围，并确认第 4 节列出的选择；具体行为只在对应 AH 条目维护。本域不属于截图或共享 Xberg 后台；本文不记录实现或测试通过状态，验收方案不等于执行验收。

## 1 功能与职责边界

- **AH-01** 在 JchTools 中增加独立模型服务工具及真实 GUI 入口，使用成熟的 Rust HTTP 服务后端和官方 Rust ACP 客户端；本工具全部新增代码均使用 Rust，包括 HTTP 装配、中间层、配置、状态、后台生命周期、客户端回调适配及新编写的本工具测试代码，不引入 Node.js / Python 业务包装层。本项目只承担两者之间的中间层适配及工具箱必需的接入，不自建模型推理引擎，不重写 ACP 客户端或 HTTP 网络栈，不改变其他工具的行为。用户配置的外部 ACP Agent 的实现语言不受本项目 Rust 约束；既有开发及验收脚本保留，不要求为本工具重写成 Rust。

- **AH-02** ACP 客户端采用 [agentclientprotocol/rust-sdk](https://github.com/agentclientprotocol/rust-sdk) 的官方 Rust SDK `agent-client-protocol` 客户端能力。本项目通过其公开接口完成初始化、会话、提示请求、事件接收及必要回调处理，不另写一套 JSON-RPC / ACP 客户端。支持范围以实际协商的协议版本及 Agent 能力为准，不凭 Agent 名称承诺兼容所有能力；SDK 包版本不是通信协议版本。文件和终端等客户端能力按 AH-13 接入，不能只宣告支持却缺少可执行的回调处理。

- **AH-03** 请求链路固定为“HTTP 调用方 → HTTP 服务后端 → 本项目适配层 → 官方 Rust ACP 客户端 → 用户配置的 ACP Agent”；响应沿相反方向返回。Agent 是 ACP 服务端；验收所用 `opencode acp` 处于该上游角色，不是向本工具 HTTP 接口发请求的客户端。本项目不接管 Agent 内部模型推理、模型供应商接口或账号认证。

- **AH-04** 第一版 HTTP 对外接口为 `POST /v1/chat/completions` 和 `GET /v1/models`，不包含 Responses、Embeddings 或其他推理接口。Chat Completions 提供普通 JSON 响应和 `stream: true` 的真正增量 SSE 文本响应。输入接受 `system` / `developer` / `user` / `assistant` 角色的文本字符串或纯 `text` 内容块，图片、音频及客户端工具消息明确拒绝；默认每请求新建 ACP 会话，完整消息历史按角色标记传入。调用方可通过 `X-JchTools-Session-ID` 显式延续会话，校验已有历史，仅提交新增部分，历史不一致明确报错；同会话按接收顺序串行。Models 只公布 Agent 协商确认且可实际选择的模型标识，将 HTTP `model` 映射到 ACP 模型选择；缺少相关能力时明确不可用，不编造模型列表、不回退为固定服务别名，也不把 Agent 内部全部模型自动声明为可用。

- **AH-05** 第一版由 ACP Agent 负责工具调用决策及执行流程，HTTP 返回其文本结果；需要由客户端承接的文件或终端操作，通过 AH-13 的 Rust 回调适配完成，不交给 HTTP 调用方执行。Agent 的工具执行事件不转换为要求 HTTP 调用方执行的 OpenAI `tool_calls`。不承诺 HTTP 调用方提供 `tools` / `tool_choice`、执行工具并回传结果的循环；对此类不支持的输入应明确拒绝，不能静默忽略或伪称支持。权限固定按 AH-13 最大授权处理，不向 API 暴露审批流程。

## 2 常驻、启动与配置

- **AH-06** 模型服务运行于当前 Windows 用户会话的独立后台进程，持有 HTTP 监听、官方 ACP 客户端及其启动的 Agent 进程；不依赖 GUI 线程或 GUI 进程持续存活。打开工具箱时按有效配置启动或连接已有模型服务，启动与 ACP 初始化不得阻塞 GUI；没有有效配置时明确显示未就绪，不影响其他工具。Agent 启动及 ACP 会话的绝对工作目录固定使用应用状态目录下的 `acp-workspace`，按需创建，不增加工作目录配置项，不依赖源码目录或 GUI 启动位置；其他路径需由请求提示明确提供。

- **AH-07** 关闭主窗口或终止 GUI 进程不停止模型服务、不关闭 ACP 连接、不终止本应用启动的 Agent；已有请求可继续执行，GUI 不存在时仍可通过 HTTP 完成新请求。重新打开工具箱连接原服务，不重复监听同一服务端口或重复启动对应 Agent。该常驻只适用于新工具，不把原工具的 GUI 在途任务改为关窗后继续运行，也不自动增加 Windows 登录自启要求。

- **AH-08** GUI 提供分栏的 ACP Agent 启动程序与参数以及 HTTP 监听端口；参数采用 Windows 引号规则、不简单按空格拆分。默认端口为 8765，监听地址固定为 `127.0.0.1`，第一版不接受局域网连接。端口仅接受 1～65535 的整数，非法输入或端口占用必须明确报错，不暗中换端口；命令缺失、启动失败或 ACP 初始化失败同样显示具体原因，不冒称服务已就绪。

- **AH-09** 配置应持久保存，重新打开工具箱及后台服务后恢复同一启动程序、参数与端口，不要求重复输入。保存立即持久化，不打断运行中的服务；保存失败保留原配置，不冒称成功。首次有效配置自动启动服务；运行中配置变更显示待应用，提供“应用并重启”：用户主动执行后停止接新请求、等待所有已有请求结束，再以新配置重启，不静默取消已有任务。模型与推理等级可以作为 Agent 启动参数，本工具不接管供应商配置；HTTP 模型选择仅按 AH-04 的协商能力执行。

- **AH-10** 新工具的启停不影响截图服务、共享 Xberg 或其他工具；关闭 GUI 与主动退出后台服务是不同操作。模型服务页提供独立退出入口，用户确认后停止接新请求、请求级取消并等待在途任务安全收尾，然后释放本应用拥有的 Agent、终端和连接，不自动强杀、不操作用户自行启动的进程。模型服务不纳入截图/Xberg 统一托盘退出，也不新增托盘；主动退出后当前 GUI 不自动重启模型服务，下次重开 GUI 才按 AH-06 自动启动。

- **AH-11** HTTP 后端采用 Axum 0.8.9，复用其 Rust HTTP、JSON 与 SSE 服务能力，本项目只写 OpenAI 与 ACP 之间的适配，不移植 vLLM Router 的推理模块。选型须保留可核对的维护记录、真实服务使用证据及 Windows 集成验证，说明与推理后端的耦合及可复用接口；仅有演示程序、仓库宣传或 Stars 数量不能作为成熟度结论。Node.js / Python 桥接项目仅可作协议映射参考，不作为本工具运行后端或客户端。官方 ACP SDK 的 HTTP 传输也不自动等同于 OpenAI HTTP 接口。

- **AH-12** 第一版并发使用单 Agent 进程：一个模型服务后台通过一个官方 ACP 客户端连接复用同一个常驻 Agent，不建立多 Agent 进程池、不为每个请求启动 Agent。独立请求在该进程的不同 ACP 会话中并发执行，文本、事件、完成和取消均按会话及请求关联；同一会话的提示轮次按接收顺序串行提交，不以追加提示取消正在执行的上一轮。最多 4 个请求执行、另有最多 16 个请求等待，同会话等待请求同样计入等待容量，队列满返回 HTTP 429，不无限排队。单进程限制指 ACP Agent，不要求合并 GUI、HTTP 后台与 Agent。外部 Agent 的单进程多会话并发能力须真实验证；不支持时明确报告能力限制，不自动增开 Agent，也不以串行排队冒充并行。

- **AH-13** 第一版权限统一使用 Agent 与 ACP 提供的最大授权，不提供 HTTP 权限字段、审批端点、权限查询或调整接口，也不弹出每次工具调用的 GUI 审批。Agent 支持最大授权或免审批启动模式时，按其公开启动方式启用；收到 `session/request_permission` 时自动选择最宽允许选项，存在“始终允许”时优先使用，不因 GUI 已关闭而等待人工确认。官方客户端的文件读写、终端执行及生命周期回调由本项目 Rust 适配承接，宣告能力与实际实现一致，操作结果或失败明确回传。最大授权仅作用于 ACP/Agent 及当前 Windows 用户已有权限，不自动提权、触发 UAC 或改变系统权限，不声称覆盖 Agent 固定策略或系统限制；缺少允许选项或必要能力时明确失败，不伪造批准。非权限交互明确失败，不编造回答。HTTP 断连请求取消对应 ACP 轮次，不关闭唯一 Agent 或影响其他会话；Agent 连接断裂使全部受影响的在途请求明确失败，下个新请求可重建唯一 Agent，恢复保持单实例、不重放旧任务。

- **AH-14** 本工具采用的 HTTP 后端、协议类型、官方 Rust ACP 客户端、本项目适配与测试代码，以及构建、运行和测试所需的全部直接与传递依赖源码及必要资源，均复制纳入本项目仓库并受版本控制；不能只登记包名或远程仓库地址，也不能依赖开发机其他源码目录、外部 Git 工作树或仅存在于本地缓存的源文件。Cargo 依赖声明可以保留，但实际源码解析必须使用仓库内的固定副本，锁定精确版本或提交；使用具有所需 Rust 工具链和 Windows SDK 的干净环境时，应能仅凭本仓库解析并构建本工具，不再从网络获取依赖源码。复制官方 SDK 后仍通过其客户端公开接口接入，不另写 ACP 实现；保留所有依赖的上游来源、版本或提交、版权、许可证及要求的 notice，并记录本项目对副本的必要修改。该复制范围限于本工具代码和依赖，不扩大为重写或搬迁其他工具；Rust 工具链、Windows 系统组件及由用户命令指定的外部 ACP Agent（验收使用 OpenCode）不是需要复制源码的项目依赖，不将用户账号、凭据、配置、缓存或输入资料纳入仓库。产品交付仍按 P-05 提供本工具必要运行组件，不要求将开发用依赖源码全部打进运行安装包。

- **AH-15** 当前 Windows 用户及同一登录会话内的调用方可通过模型服务已有控制命名管道的只读 `Discover` 操作发现已存在的后台，不增加面向其他用户、其他登录会话或网络的发现入口。响应采用版本化协议，只提供必要的协议版本 `protocol_version`、固定服务标识 `service_id`（`jchtools-acp-http`）、后台实例标识 `instance_id`、实际服务阶段 `phase`、HTTP 基地址 `base_url`、执行模式 `execution_mode`（`server_agent`）及能力 `capabilities`；能力明确为文本、流式、服务端工具受支持，客户端工具不受支持，不据此声明未经 Agent 协商的模型、上下文容量或输出上限。实例标识在同一后台进程内保持，后台重新创建后改变；仅实际就绪时提供当前运行配置对应的 `http://127.0.0.1:<实际端口>`，不能使用默认端口或尚未应用的已保存配置冒充运行端点。后台存在但未就绪、正在启动、停止或失败时仍可查询实际阶段，`base_url` 为 `null`；后台不存在或管道不可用时只表示发现不可用，不启动后台或 Agent。发现响应不包含启动程序、参数、配置、凭据或其他秘密，也不读取已保存配置作为发现来源；发现本身不保存或应用配置，不启动、停止、重启服务或 Agent，不触发模型请求或改变已有请求。

- **AH-16** 模型服务启动其拥有的 ACP Agent 子进程时，给该子进程环境显式设置 `OMP_JCHTOOLS_DISCOVERY=0`，覆盖继承值，防止作为后端的 OMP 再发现并选择本服务而递归调用；该保护仅作用于子进程及其继承链，不改写系统或用户环境、不持久化为用户配置，也不修改用户保存的启动程序和参数。此保护及 AH-15 的发现入口不改变 AH-04 的 HTTP API、AH-06～AH-10 与 AH-13 的后台和 Agent 生命周期、工作目录、断连取消及异常恢复行为；HTTP 仍只提供文本 Chat Completions，工具决策与执行仍归后端 ACP Agent，必要的客户端回调仍按 AH-05 / AH-13 由本工具承接，不转交 HTTP 调用方执行。

## 3 验收方案

2026-10-10 用户明确确认真实验收基准切换为截图所示的 OpenCode v2.0.26，提供方为 OpenCode Zen，模型为 MiMo-V2.6-Flash Free，完整模型 ID 固定为 `opencode/mimo-v2.6-flash-free`。该版本是本次截图基准；执行时记录实际程序版本，不强制产品只能运行此版本。Agent 启动命令为：

```text
opencode acp
```

启动方式依据 [OpenCode ACP 文档](https://opencode.ai/docs/acp.md)，模型完整 ID 与 Free 定位依据 [OpenCode Zen 文档](https://opencode.ai/docs/pl/zen)。本机 `opencode acp --help` 未提供 `--model`、`--thinking` 或 `--approval-mode yolo` 启动选项，不编造这些 CLI 参数、不强迫推理等级 `low` 或 OMP 专属 yolo 模式。目标模型须通过真实 ACP 协商、模型选择及请求结果核对，不能只凭文档、配置文本或模型目录输出认定可用；Free 未开放、认证缺失或能力不足时如实 FAIL / NOT RUN，不回退付费、其他模型、提供方或 Agent 冒充通过。最大授权按 AH-13 及 OpenCode 的公开启动能力执行，并记录实际权限回调与工具结果，不将 ACP 自动允许夸大为绕过 Agent 固定策略或 Windows 权限。

OpenCode 是本文件唯一指定的真实 Agent 验收基准，真实 Rust 验收目标唯一为 `acp_opencode`；它不是产品默认命令的强制值，任意其他 ACP Agent 的兼容性仍以实际协商能力和运行结果为准。本次用户已明确授权该基准及目标模型的真实 ACP 验收；该授权不扩展为 fulltest、slowtest 或发布授权，也不使尚未执行的用例成为通过。

用户当前第一阶段仅执行单 Agent、单并发的基本链路：经真实 JchTools 后台、HTTP 公开入口及官方 ACP 客户端完成 `GET /v1/models`，确认并选择上述唯一目标，再完成普通 Chat Completions JSON 与真正增量 SSE 请求；依次运行请求，不以本阶段证明 AH-12 多会话并行。下表 AH-A01～AH-A15 全部保留；第一阶段未执行的真实 GUI、工具、权限、并行及其他高级验收仍逐项记为 `NOT RUN`，夹具验证与本阶段结果均不能替代这些真实验收或宣称本域全部验收通过。

测试数据与验收工作目录由 `python scripts/make_tmp.py` 在仓库 `.tmp/` 内生成；真实 Agent 工具用例只操作该合成工作区，不操作仓库代码或私人资料。按 P-03 / AH-03，OpenCode 可为已授权模型请求访问自身模型服务；JchTools 不直接调用供应商 API、不接管账号或上传自身诊断日志。真实模型调用须在明确授权的验收阶段执行，本次授权仅覆盖上述已确认范围，其他真实调用仍需当次明确授权。
