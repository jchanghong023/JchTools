## 1. 定位与行为不变

- **XB-01【推理提供方】** 截图 OCR（O-07 固定模型字节）与媒体转录（T-19 链路）的模型、原生库与推理由固定版本的 Xberg 发布物提供；JchTools 保留工具注册表与 Slint 页面、扫描/过滤/排序/队列/超时/停止等任务控制、截图服务的独立后台进程、托盘、全局热键、单实例、开机启动、模型常驻监督、框选与结果窗（O-11～O-22）。
- **XB-02【行为不变】** 迁移后截图 OCR 的识别、瓦片与二维布局行为仍满足 O-23～O-28 及附录 B；媒体转录仍满足 T-19/T-20 与附录 C。验收沿用对应文件的既有口径（同图对照、桌面 E2E、合成媒体逐项断言）；旧实现的既有通过记录不得当作迁移后证据。
- **XB-03【两套模型明确区分】** Xberg 侧文档 tiny 与截图 small 两套 OCR 模型分别命名、分别校验、显式选择；JchTools 不得依赖或利用任何「同属 PP-OCRv6」的混用、覆盖或自动回退（对应 Xberg 草案 SNAP-02～SNAP-06）。
- **XB-04【离线与隐私】** 沿用 O-10 / O-29 / T-21：与 Xberg 的全部调用只经本地进程通信（stdio / 管道），不新增网络监听或远程接口；截图、裁剪图、转录正文与音频解码数据不落盘、不上传、不入日志。

## 2. 本地调用接口

- **XB-05【接口形态】** JchTools 通过 Xberg 本地 worker 协议（`xberg worker`，stdio JSON 行）调用截图识别与媒体转录：截图以图像字节（base64，无损编码）传参，不要求落盘；转录传本地媒体文件路径。每请求恰好一行响应，成功携带布局文本或转录结构，失败携带可分类错误。
- **XB-06【模型选择参数】** worker 启动配置显式声明所启用的能力与模型集（截图模型集 `snapshot-pp-ocrv6-small-textsnap`、SenseVoice 链路）；请求与启动能力不匹配时返回明确错误，不自动切换模型。
- **XB-07【错误类型】** 至少区分：资产未就绪、模型/字典校验失败、模型错配、输入解码失败、无文字（截图）/无音轨/无语音（媒体）、超时、用户取消、内部失败；界面文案沿用 O-30 / T-24 的分类与措辞约束。
- **XB-08【取消边界】** 用户取消（O-19 / T-23）通过关闭连接或终止进程实现，Xberg 侧在瓦片/识别批次或 VAD 段检查点终止当前请求；单文件超时（T-29）到点由 JchTools 结束进程。取消与超时不得伪造成成功，已完成部分按 T-23/T-25 语义处理。
- **XB-09【版本兼容】** Xberg 运行组件携带可校验版本标识（发布 tag 与组件清单摘要）；与 JchTools 内置期望不一致时明确报错并指引更新对应组件，不自动降级、不混用其他版本、不因「同名文件」认定兼容（呼应 T-06 精神）。
