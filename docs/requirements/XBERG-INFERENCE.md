# 共享 Xberg 与后台服务需求（XB）

本文件唯一维护共享推理进程、本地接口、Xberg 获取与版本、统一设置、持久配置和后台生命周期。截图行为在 [SNAP2TEXT.md](SNAP2TEXT.md)，转换任务与产物在 [ALL2MARKDOWN.md](ALL2MARKDOWN.md)，全局约束在 [CONTRACT.md](CONTRACT.md)。本文只定义需求与验收条件，不记录实现、历史授权或测试状态。

## 1. 推理职责与独立性

- **XB-01** 文档转换、文档及独立图片 OCR、截图 OCR 和媒体转录均由本地 Xberg 发布物承接，遵守 XB-14～XB-17；获取及测试选版按 XB-10。JchTools 保留工具注册与 Slint 页面、扫描/过滤/排序/队列/超时/停止等任务控制，以及独立截图后台的托盘、热键、单实例、自启、常驻监督、框选和结果窗。截图固定模型仍按 O-07，媒体链路仍按 T-19，不因最新版引擎而擅自改变已确认行为。

- **XB-02** 迁移后截图 OCR 的识别、瓦片与二维布局行为仍满足 O-23～O-28 及附录 B；媒体转录仍满足 T-19/T-20 与附录 C。验收沿用对应文件的既有口径（同图对照、桌面 E2E、合成媒体逐项断言）；旧实现的既有通过记录不得当作迁移后证据。

- **XB-03** Xberg 侧文档 tiny 与截图 small 两套 OCR 模型分别命名、分别校验、显式选择；JchTools 不得依赖或利用任何「同属 PP-OCRv6」的混用、覆盖或自动回退（对应 Xberg 草案 SNAP-02～SNAP-06）。

- **XB-04** 沿用 O-10 / O-29 / T-21：与 Xberg 的全部调用只经本地进程通信（stdio / 管道），不新增网络监听或远程接口；截图、裁剪图、转录正文与音频解码数据不落盘、不上传、不入日志。

## 2. 本地接口、错误与取消

- **XB-05** 全部功能经唯一 Xberg 的本地 worker 协议（xberg worker，stdio JSON 行）提交请求。截图传无损编码的图像字节（base64），不要求落盘；文档与转录传本地路径。每请求恰好一行响应，结果与请求明确关联，成功返回对应结构或文本，失败返回可分类错误；协议须支持跨场景并用，不能串错结果或将截图排在当前文档结束之后。文档 extract 请求仅传 path，不携带 mode、模型或请求级转换配置；document.content 是引擎最终 Markdown，顶层 warnings 为 document.processing_warnings 的副本。JchTools 只执行媒体目录前缀及字节落盘，嵌入合入、去重与规范化由引擎承接，不重复处理或自行分节兜底。

- **XB-06** 共享 worker 的能力配置显式声明各场景的模型集及独立配置，包括文档 OCR、截图模型集 `snapshot-pp-ocrv6-small-textsnap` 与 SenseVoice 链路；各请求显式选择其场景，模型与配置按 XB-16 隔离并复用。请求与已配置能力不匹配时返回明确错误，不自动切换模型，不通过另起进程处理错配。

- **XB-07** 至少区分：资产未就绪、模型/字典校验失败、模型错配、输入解码失败、无文字（截图）/无音轨/无语音（媒体）、超时、用户取消、内部失败；界面文案沿用 O-30 / T-24 的分类与措辞约束。

- **XB-08** 取消、停止和超时按请求及场景隔离。截图取消按 O-19 在不可中断调用返回后的瓦片或识别批次检查点生效；文档及媒体批次停止按 T-23 尽快取消当前文件，而非等待整文件自然完成，且不开始下一文件；单文件超时按 T-29 结束当前处理。正常取消和超时不得关闭共享连接、终止共享进程或进程组，不得影响另一场景或卸载其模型。未完成产物不伪造为成功，仅清理本次拥有的内容，已完成结果保留；引擎自身异常退出按 XB-17 报错与恢复。

## 3. Xberg 获取、交付与退役

- **XB-09** Xberg 发布 tag 与资产清单用于下载完整性校验及来源核对。运行时保存/读取共享目录、就绪检查与任务启动前，只检查场景所需成员是否存在以及 worker 协议能力是否满足，不比对成员大小、SHA-256 或版本一致性，不因文件字节与内置清单不同而拒绝使用。允许用户替换组件或改用其他版本目录，不要求其维护成员摘要清单；成员缺失、加载失败或能力不满足时明确报错并指引修复，不自动降级，不按功能混用多个目录或用同名文件冒充兼容。下载选版按 XB-10，模型与行为约束不因此取消。

- **XB-10** 全部 Xberg 功能使用统一设置当前选中的同一个运行目录，支持用户主动下载或选择已有目录。下载来源固定为 Xberg 正式发布来源；每次下载前解析最新发布版本并固定采用该版本，不把历史钉死版本作为下载默认，不因最新版本获取失败而静默回退旧版。本次下载确定版本后记录精确 tag、来源、资产大小与 SHA-256，按对应发布清单校验完整性，失败或取消不覆盖有效资产与配置。已有的最新版不重复下载；普通启动、截图及转换不自动下载或升级。用户提供的目录不复制、不改写、不删除，运行时按 XB-09 检查，不强迫其目录版本与自动下载来源一致。
  - 使用真实 Xberg 发布物的测试与验收必须采用测试时最新发布版本；已存在最新版则复用，不存在时按项目测试目录规则获取最新版并替换旧测试引擎，不使用旧发布物代替当前验证。
  - 本条唯一维护 Xberg 获取与选版；其他字体或可选资产仍按各自清单，不改变既有 7-Zip 的 E 分区规则。

- **XB-11** 后台及截图服务程序按 XB-25 随主安装包和便携包交付；安装包与便携包随附除 Xberg 组件目录外的全部运行依赖，截图字体及许可证按 O-05 直接内置于截图服务程序；主包仍不携带 Xberg 引擎、模型和 OCR/媒体推理运行库（O-05 / T-05）；`package-windows.ps1` 的 fail-closed 泄漏检查与 `installer/JchTools.iss` 边界保持。

- **XB-12** 媒体转录和截图推理统一由共享 Xberg 承接，不保留独立 markdown-media-worker 或截图托盘 worker 内的 det/rec 推理、vendored 推理实现及重复下载的模型/字典/onnxruntime 资产条目。保留托盘服务本体、结果窗字体、用户设置与登录自启语义；就绪检查、初始化和交付须与这一资产边界一致，不删除仍被引用或用户提供的资产。

- **XB-13** 推理承接或旧组件退役前，使用同批公开合成样本对照文本、布局、时间戳、耗时及内存，按 T / O 分区给出可观察结果与差异；不凭实现或历史记录宣称更好或已通过。对照满足需求并经用户确认后再移除对应旧推理实现；规格与验收应自包含，产品运行不依赖旧源码目录，真实 Xberg 对照侧仍按 XB-10 使用最新发布版。

## 4. 统一设置入口

- **XB-19** Xberg 目录选择、下载与保存集中到 XB-20 的「设置」页；「转 Markdown」和「截图 OCR」显示同一当前配置的就绪状态并提供前往设置的入口，用户只需配置一次。各功能按自己的场景成员和协议能力要求检查这一目录；单独使用一种功能不强制初始化另一种功能。相关资产缺失或不兼容时明确提示，不能悄悄改用独立下载的另一份 Xberg 或启动第二个引擎；Xberg 获取来源按 XB-20 / XB-21，不由各功能重复下载、复制或改写。正在运行的任务仍遵守 XB-17，不因保存新目录而终止共享进程或中断其他任务。

- **XB-20** 左侧导航新增独立「设置」tab，集中管理文档转换、图片 OCR、截图和媒体转录共同使用的 Xberg。支持用户主动按 XB-10 下载最新发布版并校验来源与摘要，或选择已有运行目录；各工具页显示就绪状态及前往设置的入口，不再分别编辑 Xberg 目录。用户提供的目录不复制、不改写、不删除；下载失败或取消不覆盖已校验版本或有效配置，不在普通启动时自动下载或升级。

## 5. 唯一共享进程与任务隔离

- **XB-14** 同一 Windows 用户会话内，JchTools 全部使用 Xberg 的功能共用至多一个活动 Xberg 引擎进程，包括文档转换、文档及独立图片 OCR、截图推理、媒体转录；多功能启用时全部由同一个进程承接，不能按功能、模型、配置、运行目录、文件或请求另起 Xberg，也不能以预检或辅助调用为由启动第二个 Xberg 进程。单进程限制指 Xberg 引擎，不要求将 JchTools 主界面、截图托盘服务合并成一个进程；仅使用其中一种功能时仍保持其独立可用。

- **XB-15** 文档转换正在处理当前文件时，热键或托盘发起的截图仍能在同一 Xberg 进程中执行识别并返回结果，不得等当前文档或整批转换结束后才开始截图推理，也不得停止或重启文档转换来切换场景。T-22 的顶层文件串行只约束转换任务之间，O-19 的单任务限制只约束截图任务之间；两者不构成跨场景互斥。资源竞争按 O-32 如实衡量，不新增固定延迟或零性能损失承诺。

- **XB-16** 同一 Xberg 进程按场景分别持有模型及配置；截图沿用 O-07 / O-23～O-28，文档转换沿用 T-13～T-18 / T-29 与 XB-03，媒体转录沿用 T-19 / T-20，不混用模型、字典、阈值、线程设置或文档快速模式。截图与文档转换两套已加载模型可同时驻留并在各自功能持续使用期间复用，不因另一场景开始、结束或每次请求而卸载重载；截图预加载与关闭主窗口后的常驻仍按 O-11 / O-13。模型常驻不扩大 O-29 的截图及结果保留范围。

- **XB-17** 截图取消只结束截图任务，不中断转换；转换停止按 T-23 尽快取消当前文件，单文件超时按 T-29 结束该文件，均不停止截图服务或卸载其模型。正常取消、超时及某一功能退出不得以杀共享 Xberg 实现；只有 XB-23 明确的全部后台退出，在安全结束全部在途任务后关闭本应用拥有的引擎。GUI 关闭或重开不产生第二个 Xberg；引擎自身异常退出时，受影响任务明确报错，不伪报成功，不重放失败任务，恢复仍满足至多一个引擎。

### 5.1 功能域关系

截图行为由 O 分区维护，转换行为由 T 分区维护；共享进程、并用与请求生命周期只由 XB-14～XB-17 维护。T-22 的串行与 O-19 的单任务分别限于各自场景，不构成跨场景互斥。

### 5.2 验收覆盖目标

以下是已确认需求的验收要求，不是当前测试通过记录；使用公开合成内容，继续遵循各功能验收矩阵及 AGENTS.md 的授权和 CI 条件。

| 层级 | 输入与可观察结果 |
|---|---|
| UT / 集成 | 分别验证模型与配置选择、请求和响应归属、多功能同时请求启动时只创建一个引擎、各场景取消/超时/退出只影响自身任务，转换停止须尽快取消当前文件；覆盖文档、图片 OCR、截图、媒体及预检调用，缺失或不兼容资产不得混用模型或另起引擎 |
| 真实桌面 E2E | 从转 Markdown 页面启动含 OCR 的长文档转换，在当前文档尚未结束时经热键或托盘完成截图、识别、结果显示与复制；验证截图正文与转换产物各自正确，并记录两者使用相同 Xberg PID、全程无第二个 Xberg，不能只断言 GUI 没有卡死 |
| 常驻与启动顺序 | 分别覆盖先启截图、先启转换、同时启用；重复截图与连续文件转换复用各自模型；用模型加载次数或等价观测确认驻留，不能仅凭 PID 相同推断模型未重载；关闭和重开主界面后截图仍可用且不增开引擎 |
| 任务及生命周期隔离 | 双场景运行时分别取消截图、尽快取消当前转换文件、触发单文件超时、退出截图服务，验证另一场景符合 XB-17；模拟共享引擎异常退出时检查错误归属、不完整产物处理及恢复后的进程数 |

## 6. 持久配置与恢复

- **XB-18** JchTools 在当前用户的应用状态目录使用 SQLite 按 XB-21 持久保存两种来源的目录与唯一当前来源，文档转换、图片 OCR、截图及媒体转录共同读取这一配置；配置独立于单次任务库与哈希缓存，保存成功即写入磁盘；关闭并重新启动应用、截图服务或重启 Windows 后自动读取已保存的目录，无需重新输入、重新选择或再次点击保存确认，不得只保存在内存或当前会话。路径不再由各功能分别保存为文本文件或另设互相独立的 Xberg 配置；模型及推理参数仍按 XB-16 分场景隔离。配置缺失、读取或保存失败应明确提示，不冒称保存成功，不以空值或默认路径覆盖已保存值；本条不将 R-01 中原工具的会话规则改为持久设置。

- **XB-21** 应用级 SQLite 分别保存下载所得目录、用户提供目录和当前选用来源；切换来源不丢失另一来源的路径。保存成功后，退出 GUI、退出后台服务并重新打开，或重启 Windows 后再次启动，均自动恢复当前来源和两个已保存路径，无需重新配置。原有唯一 Xberg 路径迁为用户提供目录并保留原值；失效目录显示原因，不静默换源、不清空已保存配置。全部功能仍使用当前选中的同一个引擎，模型与配置仍按 XB-16 隔离。

XB-18 验收必须覆盖保存后完全退出写入进程，由新进程从 SQLite 自动恢复相同路径，以及系统重启后的恢复；不能以同一进程重新打开连接或内存缓存命中代替重启验证。其余验收覆盖设置页写入、两功能页读取同一配置、未配置和无效目录、数据库读写失败保护，以及在有效目录下分别完成真实文档转换和截图推理；仍按第 5.2 节验证共享进程，不能只凭数据库有记录声称功能可用。旧文本配置的升级保留须避免覆盖已有 SQLite 值或删除唯一旧配置；本节不授权删除用户的 Xberg 目录或旧组件资产。

## 7. 常驻后台与 GUI 生命周期

- **XB-22** GUI 先显示可交互窗口，后台异步读取配置、校验资产并启动或连接当前 Windows 用户会话的单实例服务，界面不等待模型加载完成。有有效 Xberg 配置时自动启动并保活唯一共享 Xberg 与截图服务，不要求进入截图页或再点击启动；首次配置成功后同样自动生效。关闭或终止 GUI 进程不结束后台服务、Xberg、托盘、热键或截图任务；再次打开 GUI 连接原服务，不新增服务或引擎实例。引擎异常退出时明确报告受影响任务失败，后台恢复服务能力但不自动重放失败任务；恢复过程仍保持至多一个引擎。缺少或损坏资产如实显示未就绪，不阻塞 GUI 及其他工具。Windows 登录自启默认值仍按 O-15，不把「打开 GUI 后常驻」理解为默认开机自启。

- **XB-23** 常驻后台在系统通知区域提供统一托盘入口，可打开主界面、设置及截图，并提供明确的「退出后台服务」。关闭 GUI 仅关闭界面；用户主动结束后台通过托盘执行，退出时停止接受新任务，在各任务原有安全边界结束在途处理后释放截图资源并终止本应用拥有的共享 Xberg，不保留孤立进程，不操作用户自行启动的其他 Xberg。仍有任务时先明确提示并确认停止，等待过程可见，不静默强杀。托盘主动退出后，仍打开的 GUI 不立即自动重启服务；下次重新打开 GUI 才按 XB-22 自动启动。本条规定截图及共享 Xberg 后台的退出；新增 ACP HTTP 模型服务是否纳入统一退出范围，按 [CONTRACT.md](CONTRACT.md) 的 AH-10 确认，不从本条自动扩张其退出职责。

- **XB-24** 截图 OCR 页面移除「启动 / 重连」及用于常规启停服务的开关；自动连接、后台启动和常驻由 XB-22 / XB-23 管理。用户进一步明确：截图 OCR 页面仅保留快捷键设置及后台服务状态，不提供截图按钮、初始化、模型重载、服务启停或开机启动开关；截图由快捷键或托盘触发。Xberg 配置、随包组件检查及修复、故障恢复及应用级设置统一置于「设置」页。后台未就绪时状态明确说明原因。

- **XB-25** 将常驻后台及截图服务程序随安装包和便携 ZIP 交付，避免仅因 worker 尚未下载而无法兑现配置 Xberg 后自动启动；Xberg 引擎、模型及推理运行库仍按 XB-20 可选下载或使用用户目录，字体和许可证直接内置于随包截图服务程序，无需用户初始化；其余非 Xberg 运行依赖同样随主包提供，设置页保留离线检查及修复入口。只让服务、截图及模型生命周期脱离 GUI；文档转换、解压、整理、MD 和 Git 等在途任务关闭窗口时仍按 U-09 确认后安全停止，转换按 T-23 尽快取消当前文件，随后后台服务继续常驻。其他在途任务不转为关闭 GUI 后继续执行的后台任务，不能将保活进程当作任务已转入后台执行。

### 7.1 功能域关系

共享组件获取按 XB-10，设置入口按 XB-19 / XB-20，配置保存按 XB-18 / XB-21；GUI 关闭确认按 U-09，各工具停止按所属功能域，转换采用 T-23 的请求取消。截图页面范围按 XB-24，用户主动退出全部后台按 XB-23。

### 7.2 验收覆盖目标

自动化分别覆盖双来源保存/切换/失败保护及旧配置迁移的 UT，与真实设置页下载或选目录后完全退出、重开恢复的 E2E；下载失败、校验失败、取消不损坏原配置。真实桌面验证 GUI 可交互后模型异步加载、无启动按钮仍自动就绪、关闭和终止 GUI 后热键截图可用、重开后同一服务与同一 Xberg PID、托盘退出后相应进程与热键消失；覆盖加载失败、引擎异常与恢复、在途任务退出确认，以及两种交付形态。已有模拟引擎和 Slint 测试后端仅作补充；

## 8. 用户自由替换引擎

- **XB-26** 用户可以随意覆盖或替换共享 Xberg 引擎目录内的组件文件（含直接以新版本发布物整体覆盖或换目录），以获得新版本引擎能力；不需要用户自己维护或补报任何大小、SHA-256 或版本清单校验。运行时校验口径按修订后的 XB-09 执行：只检查场景所需成员是否存在，不因文件字节与内置清单不一致而拒绝使用；成员缺失或引擎自身加载失败仍如实报错。本条不改变下载安装链按清单校验下载内容的边界（XB-10），不扩大 XB-20 / XB-21 的联网与来源边界，也不解除 XB-14 的唯一共享进程约束。T 分区（T-05 / T-06）与 O 分区（O-06 / O-09）按各自修订后的表述引用本口径，不另行维护第二份引擎替换规则。

### 8.1 验收覆盖目标

自动化以「目录内成员文件被改写为与清单不同的字节后，保存目录、就绪检查与任务启动前检查全部放行；成员缺失时仍明确报错」为准（对应 `validate_assets` / `validate_runtime_dir` / 两侧就绪检查的存在性断言）；真实链路以一次「覆盖替换引擎文件后完成实际转换与截图」的桌面验证为准，不以前者替代后者。

真实 Xberg 的全部验收按 XB-10 使用当时最新发布版本，记录实际版本与来源；未运行或能力不满足不得报告通过。
