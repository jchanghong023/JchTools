## 2. 本地调用接口

- **XB-05【接口形态】** JchTools 通过唯一 Xberg 的本地 worker 协议（`xberg worker`，stdio JSON 行）承接全部功能请求（XB-14）：截图以图像字节（base64，无损编码）传参，不要求落盘；文档转换与转录传本地文件路径。每请求恰好一行响应，成功携带对应的文档结构、布局文本或转录结构，失败携带可分类错误；请求与响应明确关联，协议支持 XB-15 的跨场景并用，不因共享通信连接而串错结果或将截图排在当前文档结束之后。（2026-10-04 零配置接口改造确认：文档 extract 请求除 path 外零参数——mode 仅作显式覆盖，JchTools 默认不传；成功响应的 document.content 即引擎最终 Markdown（嵌入合入与规范化由引擎负责），顶层 warnings 为 document.processing_warnings 的副本；JchTools 仅执行媒体目录前缀与字节落盘，不重复实现引擎已承接的转换效果。）
- **XB-06【模型选择参数】** 共享 worker 的能力配置显式声明各场景的模型集及独立配置，包括文档 OCR、截图模型集 `snapshot-pp-ocrv6-small-textsnap` 与 SenseVoice 链路；各请求显式选择其场景，模型与配置按 XB-16 隔离并复用。请求与已配置能力不匹配时返回明确错误，不自动切换模型，不通过另起进程处理错配。
- **XB-07【错误类型】** 至少区分：资产未就绪、模型/字典校验失败、模型错配、输入解码失败、无文字（截图）/无音轨/无语音（媒体）、超时、用户取消、内部失败；界面文案沿用 O-30 / T-24 的分类与措辞约束。
- **XB-08【取消边界】** 取消、停止和超时按请求及所属场景隔离（XB-17）：截图取消按 O-19 在当前不可中断推理调用返回后的瓦片或识别批次检查点生效；文档及媒体批次停止按 T-23 等待当前文件结束，单文件超时按 T-29 结束该文件的本次处理。不得以关闭共享连接、终止共享进程或进程组处理正常取消与单文件超时；不得影响另一场景的任务或模型。取消与超时不得伪造成成功，已完成部分按 T-23/T-25 语义处理；进程自身异常退出按 XB-17 报错和恢复。
- **XB-09【版本兼容；2026-10-02 修订：运行时免摘要校验】** Xberg 运行组件仍携带可校验版本标识（发布 tag 与组件清单摘要），该标识用于下载安装链的完整性校验与内置资源自洽检查；运行时（保存/读取共享目录、就绪检查、任务启动前）对共享 Xberg 组件只做场景所需成员的存在性检查与 worker 协议能力检查（capabilities 不满足时报错），不做成员大小、SHA-256 摘要或版本一致性比对，不因文件字节与内置清单不一致而拒绝使用。用户可自行替换组件文件或改用其他 Xberg 版本目录（含直接覆盖升级引擎），不要求为新引擎版本重新维护成员摘要清单；成员缺失或引擎能力不满足时仍明确报错并指引修复。不自动降级、不按功能混用多个版本目录、不以「同名文件」冒充能力兼容（呼应 T-06 修订后的精神）。

- **XB-15【已确认：转换期间可识别截图】** 文档转换正在处理当前文件时，热键或托盘发起的截图仍能在同一 Xberg 进程中执行识别并返回结果，不得等当前文档或整批转换结束后才开始截图推理，也不得停止或重启文档转换来切换场景。T-22 的顶层文件串行只约束转换任务之间，O-19 的单任务限制只约束截图任务之间；两者不构成跨场景互斥。资源竞争按 O-32 如实衡量，不新增固定延迟或零性能损失承诺。
