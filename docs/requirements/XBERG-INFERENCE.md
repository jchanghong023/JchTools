# 共享 Xberg 与后台服务需求（XB）

本文件唯一维护共享推理进程、本地接口、Xberg 获取与版本、统一设置、持久配置和后台生命周期。截图行为在 [SNAP2TEXT.md](SNAP2TEXT.md)，转换任务与产物在 [ALL2MARKDOWN.md](ALL2MARKDOWN.md)，全局约束在 [CONTRACT.md](CONTRACT.md)。本文只定义需求与验收条件，不记录实现、历史授权或测试状态。

## 1. 推理职责与独立性

- **XB-01** 文档转换、文档及独立图片 OCR、截图 OCR 和媒体转录均由本地 Xberg 发布物承接，遵守 XB-14～XB-17；获取及测试选版按 XB-10。JchTools 保留工具注册与 Slint 页面、扫描/过滤/排序/队列/超时/停止等任务控制，以及独立截图后台的托盘、热键、单实例、自启、常驻监督、框选和结果窗。截图固定模型仍按 O-07，媒体链路仍按 T-19，不因最新版引擎而擅自改变已确认行为。

- **XB-02** 迁移后截图 OCR 的识别、瓦片与二维布局行为仍满足 O-23～O-28 及附录 B；媒体转录仍满足 T-19/T-20 与附录 C。验收沿用对应文件的既有口径（同图对照、桌面 E2E、合成媒体逐项断言）；旧实现的既有通过记录不得当作迁移后证据。

- **XB-03** Xberg 侧文档 tiny 与截图 small 两套 OCR 模型分别命名、分别校验、显式选择；JchTools 不得依赖或利用任何「同属 PP-OCRv6」的混用、覆盖或自动回退（对应 Xberg 草案 SNAP-02～SNAP-06）。

- **XB-04** 沿用 O-10 / O-29 / T-21：与 Xberg 的全部调用只经本地进程通信（stdio / 管道），不新增网络监听或远程接口；截图、裁剪图、转录正文与音频解码数据不落盘、不上传、不入日志。

## 2. 本地接口、错误与取消

- **XB-05** 全部功能经唯一 Xberg 的本地 worker 协议（xberg worker，stdio JSON 行）提交请求。截图传无损编码的图像字节（base64），不要求落盘；文档与转录传本地路径。每请求恰好一行响应，结果与请求明确关联，成功返回对应结构或文本，失败返回可分类错误；协议须支持跨场景并用，不能串错结果或将截图排在当前文档结束之后。文档 extract 请求仅传 path，不携带 mode、模型或请求级转换配置；document.content 是引擎最终 Markdown，顶层 warnings 为 document.processing_warnings 的副本。JchTools 只执行媒体目录前缀及字节落盘，嵌入合入、去重与规范化由引擎承接，不重复处理或自行分节兜底。

- **XB-06** 共享 worker 的能力配置显式声明各场景的模型集及独立配置，包括文档 OCR、截图模型集 `snapshot-pp-ocrv6-small-textsnap` 与 SenseVoice 链路；各请求显式选择其场景，模型与配置按 XB-16 隔离并复用。请求与已配置能力不匹配时返回明确错误，不自动切换模型，不通过另起进程处理错配。

- **XB-07** 至少区分：资产未就绪、模型/字典校验失败、模型错配、输入解码失败、无文字（截图）/无音轨/无语音（媒体）、超时、用户取消、内部失败；界面文案沿用 O-30 / T-24 的分类与措辞约束。

- **XB-08** 取消、停止和超时按请求及场景隔离。截图取消按 O-19 在不可中断调用返回后的瓦片或识别批次检查点生效；文档及媒体批次停止按 T-23 尽快取消当前文件，而非等待整文件自然完成，且不开始下一文件；单文件超时按 T-29 结束当前处理。正常取消和超时不得关闭共享连接、终止共享进程或进程组，不得影响另一场景或卸载其模型。未完成产物不伪造为成功，仅清理本次拥有的内容，已完成结果保留；引擎自身异常退出按 XB-17 报错与恢复。

## 3. Xberg 获取、交付与退役

- **XB-09** Xberg 发布 tag 与资产清单用于打包、音频转写可选资产下载时的完整性校验及来源核对，可选资产边界按 XB-27。运行时保存/读取共享目录、就绪检查与任务启动前，只检查场景所需成员是否存在以及 worker 协议能力是否满足，不比对成员大小、SHA-256 或版本一致性，不因文件字节与随包清单不同而拒绝使用。允许用户替换当前共享目录内的组件，不要求其维护成员摘要清单；成员缺失、加载失败或能力不满足时明确报错，不自动降级，不按功能混用多个目录或用同名文件冒充兼容。随包基础资产缺失或损坏时，设置页指引从安装包修复/重装或重新解包，不能要求另行下载截图或文档组件；音频转写可选资产未就绪时提示用户前往设置页主动下载，不自动下载。旧版已保存目录按 XB-21 保留读取与迁移，不删除用户资产；设置页不接受手动输入或选择 Xberg 目录。

- **XB-10** 全部 Xberg 功能使用同一个运行目录，获取与选版以本条为唯一权威。JchTools 打包时选择当时最新的 Xberg 正式发布版本，锁定精确 tag、正式来源、资产大小与 SHA-256，按发布清单校验归档及成员，并将该记录随包交付；不得因最新正式发布获取失败而静默改用旧版。安装或解包后默认使用包内版本，不在首次启动、普通启动、tab 切换、截图或处理文档及媒体文件时联网查询、下载或升级。主包与音频转写可选资产的边界按 XB-27，不能把共享引擎或截图/文档基础运行环境留待用户另行下载。
  - 音频转写可选资产仅在用户于设置页明确发起后下载，包括随包引擎清单声明的匹配 FFmpeg 及必要配套运行库/许可、SenseVoice INT8、Silero VAD 及配套模型数据，记录精确来源、版本、大小与 SHA-256 并校验；只补充所需 FFmpeg DLL 和模型等可选成员，不替换已有效的共享引擎或既有随包 DLL，不为追逐最新版更新它们，不重复下载已有效的匹配资产。下载和安装保留归档及成员完整性、路径安全检查和事务保护，失败或取消不覆盖有效资产与配置；不混合不匹配版本，不删除旧目录或未涉及的有效资料。设置及持久化保护按 XB-20 / XB-21，资产边界及路径事务按 XB-27，网络访问遵循 P-09 的系统代理与既有 TLS 策略，不因下载对象变化修改网络安全策略。
  - JchTools 安装包与便携 ZIP 的交付验收必须验证实际包内引擎及记录的精确版本、来源与摘要，不能另下载最新版替代包内引擎作为交付证据。真实已发布物的独立对照采用对照时最新正式发布版，已存在则复用，否则按项目测试目录规则获取；记录其版本与来源，并与包内验收明确区分，不能用旧发布物冒充最新对照，也不能用最新对照替代实际交付验收。
  - 其他字体或可选资产仍按各自清单，不改变既有 7-Zip 的 E 分区规则。

- **XB-11** 安装包与便携 ZIP 是等价交付形态，均按 XB-25 / XB-27 随附后台及截图服务、完整截图 OCR 与文档/图片转换所需的 Xberg 引擎、两套独立 OCR 模型和字典、DLL/原生运行库、字体和许可；sherpa-onnx、共享 ONNX Runtime 等既定随包运行依赖仍随主包提供，不因音频资产可选而移为下载。两种默认包均不带 FFmpeg，也不得通过主 EXE 压缩嵌入规避；FFmpeg 及必要配套运行库/许可与音频模型作为音频转写可选资产按 XB-10 主动下载。截图字体及许可证仍按 O-05 直接内置于截图服务程序。安装或解包后自动定位同一共享运行目录，无需额外下载、手填路径或依赖旧源码、Python 环境及历史缓存即可离线启动共享 worker 和截图服务，完成截图、文档/图片 OCR 及 jchocr；缺少 FFmpeg DLL 或音频模型不得阻止这些基础路径。随包内置指随分发包交付，不要求把大依赖链接或压缩嵌入主 EXE。`package-windows.ps1` 的 fail-closed 检查与 `installer/JchTools.iss` 的交付边界须按此契约验收，不继续禁止上述必需随包资产（O-05 / T-05）。

- **XB-12** 媒体转录和截图推理统一由共享 Xberg 承接，不保留独立 markdown-media-worker 或截图托盘 worker 内的 det/rec 推理、vendored 推理实现及重复下载的模型/字典/onnxruntime 资产条目。保留托盘服务本体、结果窗字体、用户设置与登录自启语义；就绪检查、初始化和交付须与这一资产边界一致，不删除仍被引用或用户提供的资产。

- **XB-13** 推理承接或旧组件退役前，使用同批公开合成样本对照文本、布局、时间戳、耗时及内存，按 T / O 分区给出可观察结果与差异；不凭实现或历史记录宣称更好或已通过。对照满足需求后再移除对应旧推理实现；规格与验收应自包含，产品运行不依赖旧源码目录，真实 Xberg 对照侧仍按 XB-10 使用最新发布版。

## 4. 统一设置入口

- **XB-19** Xberg 随包资产状态、离线检查/修复指引及音频转写可选资产下载集中到 XB-20 的「设置」页；「转 Markdown」和「截图 OCR」显示同一当前配置的就绪状态并提供前往设置的入口。各功能按自己的场景成员和协议能力要求检查这一目录；使用截图、文档转换、图片 OCR 或 jchocr 不要求下载或初始化 FFmpeg 及音频模型。相关资产缺失或不兼容时明确提示，不能悄悄改用另一份 Xberg 或启动第二个引擎；各功能不重复下载、复制或改写。媒体所需可选资产未就绪时提示用户前往设置页主动下载，不因处理媒体文件而静默下载。音频转写可选资产下载不得终止共享进程或中断其他任务，正在运行的任务仍遵守 XB-17。

- **XB-20** 独立「设置」tab 集中管理文档转换、图片 OCR、截图和媒体转录共同使用的 Xberg。页面展示当前共享运行目录及包内版本来源，文档转换与图片 OCR、截图 OCR 的随包就绪/缺失/不兼容状态，以及音频转写可选资产的未下载/下载中/已就绪/失败状态，区分 FFmpeg 及配套运行库与音频模型各自的就绪情况；不再提供三功能组件多选、首次仅勾截图或截图/文档组件下载入口。随包资产提供离线检查与安装包修复/重装或重新解包指引；音频转写可选资产提供用户主动下载、进度、取消、失败原因及重试入口，按 P-09 遵循系统代理和既有 TLS 策略。无需选择目录、输入路径或切换来源；首次及普通启动、tab 切换、截图和处理文档或媒体文件均不自动联网下载或更新。可选资产下载与安装按 XB-27 保留路径安全和事务保护，失败或取消不覆盖有效资产及配置，不替换已有效的共享引擎或既有随包 DLL；FFmpeg 或音频模型未下载不影响共享 worker、截图服务、截图、文档/图片 OCR、jchocr 或旧工具，不以关闭功能或取消下载删除已有效资产。

## 5. 唯一共享进程与任务隔离

- **XB-14** 同一 Windows 用户会话内，JchTools 全部使用 Xberg 的功能共用至多一个活动 Xberg 引擎进程，包括文档转换、文档及独立图片 OCR、截图推理、媒体转录；多功能启用时全部由同一个进程承接，不能按功能、模型、配置、运行目录、文件或请求另起 Xberg，也不能以预检或辅助调用为由启动第二个 Xberg 进程。单进程限制指 Xberg 引擎，不要求将 JchTools 主界面、截图托盘服务合并成一个进程；仅使用其中一种功能时仍保持其独立可用。

- **XB-15** 文档转换正在处理当前文件时，热键或托盘发起的截图仍能在同一 Xberg 进程中执行识别并返回结果，不得等当前文档或整批转换结束后才开始截图推理，也不得停止或重启文档转换来切换场景。T-22 的顶层文件串行只约束转换任务之间，O-19 的单任务限制只约束截图任务之间；两者不构成跨场景互斥。资源竞争按 O-32 如实衡量，不新增固定延迟或零性能损失承诺。

- **XB-16** 同一 Xberg 进程按场景分别持有模型及配置；截图沿用 O-07 / O-23～O-28，文档转换沿用 T-13～T-18 / T-29 与 XB-03，媒体转录沿用 T-19 / T-20，不混用模型、字典、阈值、线程设置或文档快速模式。截图与文档转换两套已加载模型可同时驻留并在各自功能持续使用期间复用，不因另一场景开始、结束或每次请求而卸载重载；截图预加载与关闭主窗口后的常驻仍按 O-11 / O-13。模型常驻不扩大 O-29 的截图及结果保留范围。

- **XB-17** 截图取消只结束截图任务，不中断转换；转换停止按 T-23 尽快取消当前文件，单文件超时按 T-29 结束该文件，均不停止截图服务或卸载其模型。正常取消、超时及某一功能退出不得以杀共享 Xberg 实现；只有 XB-23 明确的全部后台退出，在安全结束全部在途任务后关闭本应用拥有的引擎。GUI 关闭或重开不产生第二个 Xberg；引擎自身异常退出时，受影响任务明确报错，不伪报成功，不重放失败任务，恢复仍满足至多一个引擎。

### 5.1 功能域关系

截图行为由 O 分区维护，转换行为由 T 分区维护；共享进程、并用与请求生命周期只由 XB-14～XB-17 维护。T-22 的串行与 O-19 的单任务分别限于各自场景，不构成跨场景互斥。

### 5.2 验收覆盖目标

以下是已确认需求的验收要求，不是当前测试通过记录；使用公开合成内容，继续遵循各功能验收矩阵及 AGENTS.md 的授权和 CI 条件。

| 层级 | 输入与可观察结果 |
|---|---|
| UT / 集成 | 分别验证模型与配置选择、请求和响应归属、多功能同时请求启动时只创建一个引擎、各场景取消/超时/退出只影响自身任务，转换停止须尽快取消当前文件；覆盖文档、图片 OCR、截图、媒体及预检调用，缺失或不兼容资产不得混用模型或另起引擎 |
| 真实桌面 E2E | 从转 Markdown 页面启动含 OCR 的长文档转换，在当前文档尚未结束时经热键或托盘完成截图、识别、结果显示与复制；验证截图正文与转换产物各自正确，并记录两者使用相同 Xberg PID、全程无第二个 Xberg，不能只断言 GUI 没有卡死 |
| 常驻与启动顺序 | 分别覆盖先启截图、先启转换、同时启用；重复截图与连续文件转换复用各自模型；用模型加载次数或等价观测确认驻留，不能仅凭 PID 相同推断模型未重载；关闭和重开主界面后截图仍可用且不增开引擎 |
| 任务及生命周期隔离 | 双场景运行时分别取消截图、尽快取消当前转换文件、触发单文件超时、退出截图服务，验证另一场景符合 XB-17；模拟共享引擎异常退出时检查错误归属、不完整产物处理及恢复后的进程数 |

## 6. 持久配置与恢复

- **XB-18** JchTools 在当前用户应用状态目录使用 SQLite 持久保存唯一共享运行目录及相关设置，文档转换、图片 OCR、截图及媒体转录共同读取这一配置；保存成功即写入磁盘，关闭并重新启动应用、截图服务或重启 Windows 后自动恢复。新安装或便携包首次解压无需预先存在 SQLite、目录配置或功能勾选，即可自动发现包内共享运行目录并建立配置。数据库缺失时允许按该新装流程初始化；已有数据库读取或保存失败应明确提示，不冒称保存成功，不以空值或默认路径覆盖已保存有效值；本条不将 R-01 中原工具的会话规则改为持久设置。

- **XB-21** 应用级 SQLite 保存自动发现的包内共享目录及音频转写可选资产状态，区分 FFmpeg 及配套运行库与音频模型，不再以功能选择或首次下载作为发现截图/文档资产的前提。升级时保留读取旧文本及 SQLite 中的有效设置、旧用户目录和来源记录；新装默认包内目录，已有配置在迁移成功保存并于不打断在途任务的安全边界统一切换前，全部场景继续使用原有效共享目录，不各自改用包内路径、不另起引擎；迁移后同样只有一个生效目录。旧功能选择不再裁减主包必需资产，旧目录不得作为包内资产缺失或损坏后的隐式回退。
  - 禁止整体复制旧目录，禁止改写或删除源目录中的文件和用户资料；允许仅从旧已配置目录只读核对来源及兼容性，离线校验并复制仍匹配目标随包引擎清单的 FFmpeg、必要配套运行库/许可、音频模型及配套数据到目标目录，复用已有有效的匹配目标资产，不重复下载。只迁入所需可选成员及许可，不复制无关用户资料，不覆盖已有有效目标资产、共享引擎或既有随包 DLL；遵守 XB-10 / XB-27 既有路径安全与事务保护。迁入所需的来源及兼容性校验不要求用户维护摘要清单，不扩大为 XB-09 的运行期大小、摘要或版本准入检查。
  - 原目录媒体已就绪时，只有包内目录满足 XB-09 的基础场景要求、所需兼容媒体资产已复用或迁入并验证成功、媒体能力能够继续可用且新配置保存成功后，才可在上述安全边界提交新目录并让全部场景统一切换；升级后不要求重新下载或再初始化。迁入失败、所需资产验证失败、配置保存失败，或无法确认原已就绪媒体资产与目标兼容时，保留原有效目录、配置及可用能力并明确原因，不为完成基础迁移静默丢失媒体能力，不静默禁用媒体或联网补齐。
  - 原环境未安装媒体资产或媒体尚未就绪时，允许按上述规则复用其中已有效且匹配的部分成员并保留其状态；未下载的 FFmpeg、音频模型或其余可选成员不构成基础资产发现与迁移的前置条件，新装也不依赖旧目录。任何迁移失败均不覆盖原有效配置或改动源目录；后续音频转写可选资产下载只按 XB-10 / XB-27 补充当前唯一生效目录的匹配成员，不替换已有效的共享引擎或既有随包 DLL，失败或取消不改变生效目录或有效配置，模型与配置仍按 XB-16 隔离。

XB-18 验收覆盖无 SQLite、无旧目录和历史缓存的新装自动发现与配置建立，及保存后完全退出写入进程、由新进程从 SQLite 恢复相同共享目录与设置、系统重启后的恢复；不能以同一进程内缓存代替。其余验收覆盖两种交付形态的包内默认、升级统一迁移、各功能页读取同一配置、缺失/不兼容随包资产的离线修复指引、FFmpeg 及音频模型均未下载或部分就绪的状态恢复与下载失败/取消保护、数据库读写失败保护，以及分别完成真实文档转换和截图推理；仍按第 5.2 节验证共享进程。升级验收须覆盖原有效目录已有匹配 FFmpeg、配套运行库/许可与音频模型的完整媒体就绪情形，以及只含部分有效匹配成员的情形：按 XB-21 复用或迁入所需成员，已有有效目标资产不被覆盖，不重复下载，不改动源目录及用户资料，其他有效设置和唯一旧配置不丢失；完整媒体就绪情形在验证与保存成功后统一切换，并按 T-19 完成真实音轨转写，不能只以文件存在代替升级后媒体继续可用。分别覆盖迁入失败、所需资产验证失败、保存失败及无法确认旧已就绪媒体资产兼容的保护，确认原有效目录、配置及可用能力保持不变，迁移未完成时截图、文档/图片 OCR、jchocr 与媒体仍共用原有效目录、不另起引擎、不静默联网补齐；非媒体环境则验证缺少 FFmpeg 或音频模型不阻止基础迁移及离线使用。失效旧目录不得阻止新装式包内发现，也不得触发联网补下载截图/文档资产或音频转写可选资产。

## 7. 常驻后台与 GUI 生命周期

- **XB-22** GUI 先显示可交互窗口，后台异步读取配置、按 XB-09 检查资产并启动或连接当前 Windows 用户会话的单实例服务，界面不等待模型加载完成。新装自动发现包内目录，已有配置按 XB-18 / XB-21 恢复或迁移；截图基础资产就绪后自动启动并保活唯一共享 Xberg worker 与截图服务，不要求进入截图页、下载组件或再点击启动，FFmpeg 及音频模型未下载、FFmpeg DLL 缺失均不阻止这一过程及基础截图/文档路径。关闭或终止 GUI 进程不结束后台服务、Xberg、托盘、热键或截图任务；再次打开 GUI 连接原服务，不新增服务或引擎实例。引擎异常退出时明确报告受影响任务失败，后台恢复服务能力但不自动重放失败任务；恢复过程仍保持至多一个引擎。缺少或损坏随包资产如实显示未就绪并指引离线修复，不自动联网，不阻塞 GUI 及其他工具；音频转写可选资产未就绪仅影响媒体转录就绪状态，按 XB-20 提示主动下载。Windows 登录自启默认值仍按 O-15，不把「打开 GUI 后常驻」理解为默认开机自启。

- **XB-23** 常驻后台在系统通知区域提供统一托盘入口，可打开主界面、设置及截图，并提供明确的「退出后台服务」。关闭 GUI 仅关闭界面；用户主动结束后台通过托盘执行，退出时停止接受新任务，在各任务原有安全边界结束在途处理后释放截图资源并终止本应用拥有的共享 Xberg，不保留孤立进程，不操作用户自行启动的其他 Xberg。仍有任务时先明确提示并确认停止，等待过程可见，不静默强杀。托盘主动退出后，仍打开的 GUI 不立即自动重启服务；下次重新打开 GUI 才按 XB-22 自动启动。本条规定截图及共享 Xberg 后台的退出；新增 ACP HTTP 模型服务是否纳入统一退出范围，按 [ACP-MODEL-SERVICE.md](ACP-MODEL-SERVICE.md) 的 AH-10 确认，不从本条自动扩张其退出职责。

- **XB-24** 截图 OCR 页面移除「启动 / 重连」及用于常规启停服务的开关；自动连接、后台启动和常驻由 XB-22 / XB-23 管理。用户进一步明确：截图 OCR 页面仅保留快捷键设置及后台服务状态，不提供截图按钮、初始化、模型重载、服务启停或开机启动开关；截图由快捷键或托盘触发。Xberg 配置、随包组件检查及修复、故障恢复及应用级设置统一置于「设置」页。后台未就绪时状态明确说明原因。

- **XB-25** 常驻后台、截图服务与 XB-11 / XB-27 的完整基础运行资产均随安装包和便携 ZIP 交付，安装或解包后无需下载 worker、引擎、截图/文档 OCR 模型或基础推理运行库即可离线自动启动截图及共享后台，完成截图、文档/图片 OCR 和 jchocr；字体和许可证直接内置于随包截图服务程序，无需用户初始化。默认包不带 FFmpeg，FFmpeg 及必要配套运行库/许可和音频模型仅按 XB-10 由用户在设置页主动下载，缺少它们不阻止基础路径；sherpa-onnx、共享 ONNX Runtime 等其他既定随包运行依赖不改为下载。设置页保留离线检查及修复指引，其他功能的外部依赖边界按 P-05。只让服务、截图及模型生命周期脱离 GUI；文档转换、解压、整理、MD 和 Git 等在途任务关闭窗口时仍按 U-09 确认后安全停止，转换按 T-23 尽快取消当前文件，随后后台服务继续常驻。其他在途任务不转为关闭 GUI 后继续执行的后台任务，不能将保活进程当作任务已转入后台执行。

### 7.1 功能域关系

共享组件获取按 XB-10，设置入口按 XB-19 / XB-20，配置保存按 XB-18 / XB-21；GUI 关闭确认按 U-09，各工具停止按所属功能域，转换采用 T-23 的请求取消。截图页面范围按 XB-24，用户主动退出全部后台按 XB-23。

### 7.2 验收覆盖目标

自动化分别覆盖包内目录发现、共享配置持久化、旧配置保留读取与统一迁移、音频转写可选资产下载失败/取消保护的 UT；升级兼容媒体资产的完整/部分复用、迁入/校验/保存失败及兼容性无法确认时的保护、源目录不变和升级后媒体真实可用，统一按第 6 节验收，不另设迁移口径。安装包/便携 ZIP 的 E2E 覆盖在无旧源码、Python、SQLite、历史缓存、FFmpeg 和音频模型的环境中安装/解包后自动启动共享 worker 与截图服务、直接完成截图、文档/图片 OCR 和 jchocr、完全退出后重开恢复。检查两种实际交付包均包含 XB-27 的基础资产及精确来源记录、均不含 FFmpeg（包括主 EXE 压缩嵌入），并使用其包内引擎验证；FFmpeg 及音频模型未下载时基础路径与旧工具仍可用，缺少 FFmpeg DLL 不阻止基础进程启动，sherpa-onnx、共享 ONNX Runtime 等既定随包运行库无需另下载。覆盖首次及普通启动、tab 切换、截图与处理文档或媒体文件不发起下载/更新，媒体未就绪时明确提示前往设置主动下载；仅设置页明确操作触发匹配音频转写可选资产下载，验证进度、P-09 的系统代理与既有 TLS 策略、摘要/路径安全、已有有效资产复用、失败、取消及重试均不损坏有效资产与配置，仅补充所需 FFmpeg DLL 等可选成员而不替换已有效的共享引擎或既有随包 DLL，随包文件缺失/加载失败仅提示离线修复。音频可选资产完整后仍按 T-19 验证真实音轨转写链路；不新增独立断网测试。真实桌面验证 GUI 可交互后模型异步加载、关闭和终止 GUI 后热键截图可用、重开后同一服务与同一 Xberg PID、托盘退出后相应进程与热键消失；覆盖引擎异常与恢复、在途任务退出确认。模型身份与隔离仍按 XB-03 / XB-16，模拟引擎和 Slint 测试后端仅作补充。

## 8. 用户自由替换引擎

- **XB-26** 用户可以覆盖或替换当前共享 Xberg 目录内的组件文件，以获得新版本引擎能力；不需要自行维护大小、SHA-256 或版本清单。设置页不提供换目录入口；包内默认与旧配置迁移按 XB-18 / XB-21，运行时检查按 XB-09，成员缺失或引擎加载失败如实报错并对随包资产给出离线修复指引。此自由替换不改变 XB-10 的打包与音频转写可选资产下载完整性校验，也不授权下载流程替换已有效的共享引擎或既有随包 DLL；不把截图或文档组件改为另行下载，不解除 XB-14 的唯一共享进程约束；T-05 / T-06 与 O-06 / O-09 引用本口径。

### 8.1 验收覆盖目标

自动化验证目录内成员字节与随包清单不同时，保存/读取目录、就绪及任务启动前检查不会仅因大小、摘要或版本不同而拒绝，仍按 XB-09 检查场景所需成员存在性与协议能力；随包基础成员缺失或加载失败时明确报错并给出离线修复指引，FFmpeg 或音频模型未就绪时给出前往设置页主动下载音频转写可选资产的指引且不阻止基础截图/文档路径。主动下载仍按 XB-10 / XB-27 校验匹配资产，不替换已有效的共享引擎或既有随包 DLL。真实链路以一次「在当前共享目录内覆盖替换兼容引擎文件后完成实际转换与截图」的桌面验证为准，验证至多一个引擎、两套 OCR 模型不混用，不以前者替代后者。

实际安装包与便携 ZIP 的验收使用包内引擎并记录其精确版本、来源与摘要；用户替换引擎的验证另记替换来源，不能代替包内交付验收。真实已发布物的最新版本对照按 XB-10 单独执行，未运行或能力不满足不得报告通过。

## 9. 主包基础运行资产与音频转写可选资产

- **XB-27** JchTools 安装包与便携 ZIP 均随附完整基础运行资产：唯一共享 Xberg 引擎、文档/图片转换及截图 OCR 所需的全部成员、T-13 文档 tiny 与 O-07 / TextSnap 截图 small 两套独立模型和字典、sherpa-onnx、共享 ONNX Runtime 等既定随包 DLL/原生运行库，以及字体和相关许可；模型身份、字典、字体及许可要求不变。默认两种包均排除 FFmpeg 及其音频专用配套运行库/许可，不得通过主 EXE 压缩嵌入规避；本次新增的可选运行依赖仅 FFmpeg，不把其他既定随包依赖或 OCR 所需共享运行库移出主包。安装或解包后自动定位同一共享运行目录，无需再下载、配置目录或依赖旧源码、Python 环境及历史缓存，即可离线启动共享 worker 和截图服务、完成截图、文档/图片转换及 OCR 和 jchocr；缺少 FFmpeg DLL 和音频模型不得阻止上述基础路径。基础资产随包交付不要求将大依赖嵌入主 EXE。
  - 音频转写可选资产包括 FFmpeg 及必要配套运行库/许可、SenseVoice INT8、Silero VAD 及配套模型数据，仅在用户于设置页明确发起后按 XB-10 下载并安装到当前同一共享目录；升级时已有兼容资产的离线迁入与状态保持统一按 XB-21，不触发下载。FFmpeg 或音频模型未下载不影响基础共享 worker、截图服务、截图、文档 OCR、jchocr 与旧工具。下载可补充所需 FFmpeg DLL，不替换已有效的共享引擎或既有随包 DLL，不另装一份引擎，不把其他既定随包运行库改为下载；已有效的匹配资产复用，不重复下载。媒体资产未就绪时提示前往设置页主动下载，不因处理媒体文件而静默下载。录音、会议视频仅指 T-19 已有音轨转写，不新增录音采集、会议功能、视频画面理解或 T-08 / T-19 之外的格式。
  - 本条规定 JchTools 的分发边界，不要求上游发布特定数量或布局的功能 ZIP。上游独立功能 ZIP 可作为构建输入，但不再作为用户运行期下载截图/文档组件的要求；实际输入的选版、来源及完整性按 XB-10 核对，产出的安装包与便携 ZIP 必须包含完整基础资产及随包来源记录且不含 FFmpeg，不能用上游归档存在代替交付验收。
  - 打包与主动音频转写可选资产下载均保留归档和成员大小/摘要校验、路径安全及事务保护，失败或取消不覆盖有效资产及配置，不替换已有效的共享引擎或既有随包 DLL，不删除旧目录或未涉及的有效资料；运行期不重复做摘要准入检查，用户替换权按 XB-09 / XB-26。首次及普通启动、tab 切换、截图和处理文档或媒体文件不得自动下载或更新；随包资产缺失或损坏时按 XB-20 从安装包修复/重装或重新解包，不要求另下载截图/文档组件。设置与持久化保护按 XB-20 / XB-21，系统代理及既有 TLS 策略按 P-09，不因新增 FFmpeg 下载改变网络安全策略。实际包内版本验收与最新发布物对照严格区分，统一遵循 XB-10；可选音频资产完整后仍按 T-19 的真实音轨链路验收，同目录全部场景始终遵守 XB-14 的至多一个 Xberg 限制。
