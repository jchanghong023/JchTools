# JchTools 全局与共用需求（H / P / S / R / U / E）

本文唯一维护个人 Windows 本地工具箱的全局约束、共用安全与界面要求及引擎交付边界；各独立工具及共享推理的权威文档见 [需求目录索引](README.md)。本文件及附录只定义需求，不记录实现状态；开发纪律见 [../../AGENTS.md](../../AGENTS.md)。H 高于其他分区，其余冲突时 S 优先；各功能域须同时满足适用的全局条目与规范性附录，示例不得覆盖明文规则。附录 B～E 是跨工具共用定义与验收期望，不另设工具需求副本；普通文件大类映射由 [DIRECTORY-ORGANIZER.md 附录 A](DIRECTORY-ORGANIZER.md#附录-a普通文件大类映射c-05--c-06) 唯一维护。

## 最高优先级需求（H）

- **H-01** 个人工具，性能优先：JchTools 用于用户个人资料整理，处理性能是首要要求。避免无必要的重复扫描、重复读取文件内容、重复计算和复制；不为企业级、多人协作、处理期间外部改动等非目标场景增加负担。性能优化不得通过漏处理、错误删除或暗中缩小处理范围来实现。

- **H-02** 易用与流畅优先：界面方便好用、操作流畅是首要体验要求。扫描、解压、哈希和整理期间界面必须保持响应，处理状态可见、取消入口可用；常用操作直接可达，低频配置不妨碍日常使用。不以阻塞界面换取后台吞吐，不为方便而强制用户执行另一个工具。

- **H-03** 递归解压、目录整理、MD 整理、转 Markdown、Git 工具和截图 OCR 均为独立工具，具有正常可见的独立入口，不互相自动调用、串联、隐藏或降级。需要完整资料整理时，由用户先使用递归解压，再手动使用目录整理；解压完成只按 X-05 清理成功原包，不自动去重、归类或清理其他文件，目录整理不自动解压。截图与转换共用推理组件只按 XB 分区共享引擎，不改变工具独立性、输入输出或各自停止语义。

- **H-04** 递归解压结果：在明确的处理范围内，X-01 白名单内、能够由捆绑引擎成功解开的压缩包及本次解出的嵌套包都应完成解压；H-06、S-04 和 X-07 排除的范围除外，白名单外容器不被解压、也不计为未完成。每个包完整成功后按 X-05 永久删除原包及实际分卷，不把删除职责留给目录整理。确实无法解开的包按 X-06 隔离保留并说明原因；取消或空间不足时原地保留当前源包并停止。防护上限、范围限制或失败导致内容未解开时，不得宣称已全部解压。同次任务已处理的包不得反复入队；目录整理不补做解压、不无条件删除压缩包。

- **H-05** 整理后没有空目录：目录整理成功完成后，处理范围内除用户选定的根目录外，不得残留空目录，包括解压、去重、归类、删除后新产生的空目录。自底向上清理实际为空的目录及空目录链，不得递归删除有内容的目录；H-06 排除的目录树不参与清理。取消或清理失败时如实显示未完成，不得为了清空目录而在取消后继续删除。本条属于目录整理，不要求仅使用递归解压时额外清理目录。
  - 「处理范围」按 S-04 / R-03 确定：用户明确排除的目录树、关闭递归后未纳入的后代及链接边界不参与空目录清理。分类操作为已纳入文件新建的目标目录仍参与最终空目录清理；仅因处理范围缩小而留下的目录不算清理失败，但必须显示范围限制。

- **H-06** Git 目录整树忽略：任一目录直接含有名为 `.git` 的目录或文件时（一个 Git 项目取其最外层，内部再出现的 `.git` 不单独划分项目），该目录及全部后代整树排除：不解压、不读取内容参与哈希或去重、不改名、不删除、不清理内部空目录。唯一例外是目录整理的归类——整个项目目录作为一个整体移入「Git项目集合」目录，除此之外不进入树内做任何处理（去重、附属文件清理、改名、空目录清理、解压都不进行），见 C-14。只允许为识别边界进行必要的目录项检查，识别后不继续遍历内部；除该整体归类移动外，不得通过移动、改名或删除祖先目录间接改变该树。该排除不受隐藏文件、递归或清理开关影响，不提供关闭选项，整体归类移动同样是固定行为、无开关。选定根目录直接含 `.git` 时，整次处理不执行并明确提示；只有子目录含 `.git` 时，只排除该子树。新解出的目录含 `.git` 时，后续处理同样排除；界面明确提示 Git 目录的处置结果。
  - `.git` 名称按不区分大小写识别，`.GIT` 同样保护，不要求读取标记内容或验证仓库有效性。开始扫描前沿所选根及其祖先到卷根检查直接目录项；任一祖先直接含 `.git`，说明所选根位于 Git 项目内，两工具均拒绝整次处理。不能完成必要边界检查时不猜测为普通目录，报错且不开始处理。
  - 固定整体归类只适用于本次扫描范围内识别到、且不在用户排除或隔离容器内的项目；不以“归类固定开启”为由进入缩小范围之外查找项目。
  - 新增转 Markdown 工具只读扫描按 T-09 执行，不套用本条的 Git 整树排除；此限定仅适用于新增工具，不改变任何既有工具的扫描、保护或处理行为。

- **H-07** 递归解压不去重、不删除无关文件：只允许按 X-05 永久删除完整成功解开的源压缩包及其实际分卷，不得删除既有用户文件或已落盘的普通解压结果，不得以内容相同为由跳过正常落盘。目标冲突时保留已有文件，只为新解出的文件自动选择未占用的文件名，不覆盖、不淘汰、不询问冲突策略。只改文件名主体，原扩展名及复合扩展名保持不变，例如 `资料.txt` → `资料 (1).txt`、`资料.tar.gz` → `资料 (1).tar.gz`；不得通过更换或追加扩展名规避冲突。工具自身临时工作区只按本次所有权标记清理，不得删除用户目录。目录整理的去重、删除职责不受本条取消。
  - 「普通解压结果」不含已作为独立嵌套源包、随后满足 X-05 删除条件的归档；普通文件不会因为扩展名相似而被删。嵌套包是否删源逐包决定，不要求其所有后代包也成功。复合扩展名切分见附录 B，卷集改名另按 X-10 保持整组关系。

- **H-08** 完全不考虑无障碍：本项目不提出无障碍需求，不为屏幕阅读器、辅助技术、无障碍元数据、专门的键盘遍历或焦点规范进行开发、维护、测试和验收。不得以无障碍合规为由增加功能、复杂度或验收门槛；普通鼠标和键盘操作仍按 H-02 的方便好用要求处理。

## 0. 产品定位（P）

- **P-01** JchTools 是用户个人使用的 Windows 本地工具箱；「递归解压」「目录整理」是工具名称，不得用作产品名。

- **P-02** 工具经统一注册表（id / 名称 / 类别 / 摘要）接入，侧栏按注册表显示真实工具，不设空占位分类。递归解压和目录整理归「文件」，MD 整理、转 Markdown 和截图 OCR 归「文档」，Git 工具归「开发」；各工具按 H-03 独立启动。转换、截图的功能边界分别由 T / O 分区维护；共享组件的独立「设置」入口按 XB-20 管理，不将内部后台进程作为另一套 GUI 产品。

- **P-03** 离线处理：所有文件处理功能离线可用，程序自身不得发起网络请求，不得上传文件、日志或路径。用户主动点击关于页官网链接时，允许交由系统浏览器打开，不附加用户文件、路径或日志信息；该例外不允许后台联网或自动打开网页。
  - 关于页外开仅允许发布时确定的项目官网 `https://` 或 `http://` URL，不接受文件内容、路径或日志拼成 URL，不调用 `file:`、脚本或自定义协议。目标网址须在关于页可辨识；具体域名是发布身份信息，不影响离线处理规则。
  - Git 工具例外（仅限 G 分区）：用户在 Git 工具页主动启动任务后，允许通过 git 命令访问所选仓库当前分支已配置的 upstream 远端（fetch / push 及其合并所需网络访问由 git 自身完成，见 G-08 / G-10）；不向 upstream 之外的任何地址发起请求，不上传本工具的日志、配置或用户路径。任务未启动或停止后不发起任何网络访问。该例外不放宽其他工具与其他分区的离线要求。
  - 转 Markdown 可选组件初始化例外（仅限 T-05 / T-06 / T-21 / XB 分区）：仅用户在统一设置页主动下载 Xberg 或初始化其他可选组件时允许联网下载；Xberg 选版与下载校验按 XB-10，其余资产按各自固定清单下载；共享目录支持下载与用户提供两种来源并持久保存（XB-20 / XB-21），各功能不重复下载。转换完全离线，不上传用户文件、路径或日志；不改变既有工具的联网边界。
  - 截图 OCR 可选组件初始化例外（仅限 O-05～O-10）：后台及截图服务程序按 XB-25 随主包提供；结果窗字体和许可证直接内置于随包截图服务程序，不在运行时下载；Xberg 来源按 XB-20 / XB-21。正常加载、截图及识别完全离线，不自动更新或补下载，不上传截图、文字、路径或日志。
  - ACP HTTP 模型服务例外（仅限 AH 分区）：允许其独立后台按 AH-08 监听本机 HTTP、接受模型请求，并经本地 stdio 驱动用户配置的 ACP Agent。外部 Agent 可以为这些请求访问自身模型服务并使用其联网工具；这些访问、认证和模型供应商协议由 Agent 自身承接，JchTools 中间层不直接调用远程模型 API、不接管 Agent 账号。请求内容及 Agent 为任务读取的数据可能由 Agent 发送给其模型服务，本功能不承诺离线推理；不上传 JchTools 自身诊断日志。此例外不改变截图、转换、整理、解压、MD 或 Git 等原工具的联网及数据边界，也不为其他工具增加 HTTP 接口。

- **P-04** 界面中文；主题默认深色，浅色与跟随系统可在「关于」页切换（2026-10-09 用户确认）；颜色使用统一设计令牌。

- **P-05** 个人使用交付，两种形态并列：安装包安装到当前用户目录，不要求管理员权限或 UAC，默认创建桌面快捷方式、开始菜单入口及系统卸载项；同时提供便携 ZIP。不要求代码签名与公开分发验收。除共享 Xberg 组件目录（引擎、模型及推理运行库）及 AH 分区由用户启动命令指定的外部 ACP Agent 外，运行所需组件均随安装包和便携 ZIP 提供，无需另行安装或初始化字体、Git 或 7-Zip；字体按 O-05 内置于截图后台程序。AH 的 Rust HTTP 后台、官方 Rust ACP 客户端及本项目适配代码随包交付；外部 ACP Agent 使用用户已安装并完成所需认证的程序，不要求随工具箱捆绑。

- **P-06** 不提供命令行界面，全部用户操作经图形界面完成；不提供整理报告及任何形式的报告或日志导出，包括 CSV。
  - 截图 OCR 的内部测试入口与工作进程协议不作为用户命令行产品。正文复制按 O-22；仅本功能的用户主动复制去敏内存诊断按 O-30，不能含截图、识别文字或用户路径，不构成运行日志文件或报告导出，也不放宽其他工具的限制。
  - AH 分区例外：模型服务的配置仍经 GUI 完成，模型请求允许由外部 HTTP 调用方经 AH-04 / AH-08 的本机接口发起，并按 AH-07 在 GUI 关闭后继续使用；该 API 不作为其他工具的自动化入口，也不增加 JchTools 用户命令行产品或报告、日志导出功能。

- **P-07** 平台支持范围仅为 Windows；构建、测试、验证和 CI 只在 Windows 上运行，不为其他平台维护测试入口、验证阶段或流水线 job。

- **P-08** 不防御处理期间的外部改动：扫描、分析、执行全程假定文件与目录不被其他程序修改、删除、改名或替换，不为此做变化检测、二次快照比对、冲突重算或并发保护。发生此类外部改动时结果不作保证，该情形不计入需求范围；本条不取消不覆盖移动、路径边界检查或程序自身必要的同步。

- **P-09** 应用联网出口统一走 Windows 系统代理：应用读取 Windows 当前用户的手动系统代理（Internet 设置的 `ProxyEnable` / `ProxyServer`，支持整体与按协议（http / https / socks）形式及 `ProxyOverride` 例外表；PAC / WPAD 自动配置不支持，并在组件初始化指引中如实说明）。系统代理开启且目标未命中例外表时：应用自身全部下载（P-03 各初始化例外，含 XB-20 / XB-21 当前选定发布物）与 Git 工具经 git 发起的网络访问（fetch / push）都必须经系统代理发起；经代理连接失败时自动回退直连重试一次，直连同样失败才按原有失败口径报错。系统代理关闭时：应用自身下载直连，Git 工具不注入也不清除任何代理配置（保持现状）。本条只改变流量出口：不新增联网来源，不改变 P-03 的固定清单、upstream 限制与关于页交系统浏览器打开的行为。

- **P-10** 关键步骤的诊断日志必须写入磁盘文件：进程间通信（共享 Xberg 代理与引擎的启动、退出、通信断裂与重建、请求失败）、网络出口（可选组件下载与初始化的失败与重试）、关键功能（转换 / 整理 / 解压等任务的开始、结束统计与逐文件失败原因）以及进程 panic，都记录到状态目录 `logs/` 下按天轮转的日志文件（保留最近 14 天，超期自动清理）。日志只写本地磁盘，不联网上传、不包含截图、识别文字或文件正文；界面运行日志（S-07）保持不变，两者互不影响。日志初始化失败时先尝试用户级备用日志目录；仍失败时向 stderr 输出去敏原因，不弹窗、不终止业务。（日志补充及失败策略于 2026-10-10 用户确认）
  - 诊断日志的主要用途是运行期问题定位及 Agent 故障分析。文件必须以 `.log` 结尾；每个逻辑事件对应一条物理行，换行必须转义；每条事件包含至少毫秒精度的带时区时间戳、级别、PID、线程、组件及稳定事件名。默认运行配置保留关键诊断，`DEBUG` 仅用于额外细节；`INFO` 记录关键开始、成功结果和状态切换，`WARN` 记录可继续的异常、重试和回退，`ERROR` 记录导致当前操作失败的最终错误。
  - 初始化尽早于业务、网络、IPC 和子进程；启动记录应用名、版本、进程角色、实际日志路径、级别及构建模式，不倾倒环境变量。正常退出记录停止；异常退出记录去敏原因和可用退出码，主动退出前刷盘。日志写入失败不得递归写日志或改变业务结果。
  - 配置与存储、整理、解压、MD、转换、下载与 Git、共享 Xberg、ACP HTTP / SSE / Agent / 回调及截图 OCR 的关键调用必须记录开始和最终结果、耗时及安全结果摘要；已处理的异常记录具体阶段、可用错误类型和错误码，不要求纯透传层重复输出同一异常堆栈。网络记录安全目标、调用类型、状态及尝试编号；IPC 和子进程记录操作、可用对端 PID、返回分类、超时、取消及退出结果。现有重试和回退过程必须能由日志还原，不为日志改变重试次数、超时或业务控制流。
  - 同一完整业务操作的关键事件携带一致的操作 / 请求关联 ID；后台线程及异步任务继承必要关联上下文。内部进程协议兼容时传递关联 ID；不得为日志破坏外部协议，不能传递时记录已有请求号、消息类型及可用对端 PID，建立可追溯映射。
  - 密码、令牌、API key、认证头、Cookie、私钥、连接串凭据、用户敏感输入、图像及文档 / OCR / 提示正文不得直接入盘；URL、错误文本和命令信息只记录去敏且有界的诊断摘要，禁止完整请求 / 响应、配置对象和无限 stdout / stderr。截图链只记录运行元信息，继续遵守 O-29 / O-30。
  - 默认落点不可用时，备用目录为当前用户的 JchTools 备用诊断目录，并明确记录回退；两处均不可用时向 stderr 报告去敏失败类型及必要错误码。未取得日志写入能力不影响业务功能。日志格式、关联、正常调用和可安全模拟的失败须以隔离运行产物验证；未运行真实网络、模型或桌面链路不得冒报相应验收通过。

- **P-11** GUI 测试代码按业务代码同等标准长期维护，纳入同一版本控制、质量检查、评审与回归维护纪律；需求、业务行为或界面改变时，同步维护对应测试及其断言，不将 GUI 测试作为一次性演示脚本。测试失败须查明原因，不通过删测试、放宽断言、忽略或绕过真实链路冒充通过。

- **P-12** 自动化验收须覆盖已确认的必验需求范围，按需求编号建立可核对的需求与测试映射。功能验收以 Windows 本地测试为准；CI 只编译、打包和发布，不重复完整测试，本地已通过且源码未变的验证可复用。转 Markdown 的默认格式范围按 ALL2MARKDOWN.md 附录 A 的常用新老 Office、PDF、MP4 执行；已有扩展格式测试保留为可选，不计为通过，也不阻塞常用格式验收及发布。GUI 测试从真实公开入口覆盖全部可经界面触发或观察的需求及跨功能、设置链路，断言实际业务结果、状态和相关产物，覆盖核心成功与相关失败、停止和取消路径；内部逻辑、协议、资产及交付约束由关联的 UT、集成和交付验证共同覆盖，不遗漏非 GUI 约束。底层单测、模拟、仅完成点击或没有崩溃不能代替对应真实 GUI E2E 与可观察结果断言，未覆盖或未执行项不得报告通过。

- **P-13** 最终验收目标是无人值守测试：测试启动后，必要的环境与合成数据准备、界面操作、业务与布局结果判定、结果汇总及测试产物清理均自动完成，无需人工点击、输入、回归或目视判定。自动给出通过、失败及未验证状态，并保存足以定位失败的合规证据；依赖缺失、环境不满足、失败或未执行不能被计为通过或伪装为完整验收。未达到全覆盖或仍需人工介入时，必须明确标注尚未达到该目标，不因局部测试通过而宣称无人值守验收完成。

## 5. 数据安全不变量（S）

本分区服从 H；其余具体条款冲突时，本分区优先，不扩张到非目标场景的额外防御。

- **S-01** 所有移动、改名均不得覆盖已有目标。递归解压冲突时只给新文件改名，已有文件不动，仅按本次 X-02 确认和 X-05 成功条件删除原包；目录整理只按用户已确认的计划和 C 分区规则处置文件，不能把整理授权用于解压删除。
  - 固定容器（大类、「Git项目集合」「解压失败」）被普通文件、Git 项目或链接占用时不自动删除、挪走占用项或换容器名；相关操作保留源项并说明原因。普通目录可复用，但仅处理原本在范围内并经授权的内容。计划阶段已知占用纳入冲突计算；执行操作系统返回目标已存在等错误时该行失败，不暗中改成未经确认的新目标，不要求 P-08 范围外的变化侦测。
  - 路径必须能由实际 Windows 文件系统安全表示与创建；不统一以 260 字符拒绝合法长路径。目标总路径不可用、名称非法、权限或只读限制无法完成时保留源项并显示失败，不通过改变扩展名或越界搬移规避。
  - 普通文件确需跨文件系统移动时，先以不覆盖方式完整复制并成功设置需保留的创建时间及修改时间、关闭输出，再删除源项；复制、写入、关闭或时间设置失败不得删除源项。只清理本次新建且明确拥有的未完成副本，不删除原有目标；源删除失败时两份均保留并报告未完成，不假称移动成功。不要求内容二次哈希或事务回滚；Git 项目跨卷按 C-14 拒绝。

- **S-02** 目录整理的全局文件删除方式只有「保留」和「永久删除」，默认「永久删除」，不提供回收站或降级开关。C-04 的副本处置随该选择分别为「保留副本」或「永久删除副本」；选择保留时，不生成去重删除操作，也不生成跟随全局方式的文件清理删除操作。C-08 各清理项可显式覆盖删除方式，覆盖只作用于对应清理项，不改变副本处置；保留不禁止其余已启用规则的归类或改名。永久删除不可由本软件恢复，两工具的破坏性确认均必须明确告知；删除前满足 S-01 / S-03 等已授权校验，取消后不继续启动删除。递归解压仅按 X-05 永久删除完整成功的原包及分卷，不提供删除选项，不删除无关用户文件；空目录清理另按 C-07 执行，不受保留文件的选择影响。

- **S-03** 内容去重以整文件哈希一致为依据，删除前不得重读文件内容逐字节复核或进行其他二次内容比对。

- **S-04** 两工具扫描先识别 Git 边界，固定不跟随符号链接、junction 或其他 reparse point，不提供跟随开关，不读取其目标、不搬移或删除链接本身；所选根或其访问路径经过该边界时拒绝开始并提示。默认包含隐藏、系统属性资料，默认 glob 为空，不因普通目录名漏处理；仅 H-06、X-07 / C-09 的固定容器例外。隐藏、系统属性开关及分号分隔排除 glob 保留给用户显式调整，精确匹配见附录 C；排除目录整树生效，关闭递归按 R-03 缩小范围。范围缩小时显示有效限制；无法读取或处理的条目显示原因，不静默跳过后宣称全部完成。排除保护不得通过改名、移动或删除其祖先间接突破。

- **S-05** 不自动提权，不清除只读属性。两工具均拒绝直接选择当前系统 Windows 安装目录及其后代；路径以操作系统报告的实际系统目录为准，不假定在 C 盘，不仅按字符串前缀匹配（`Windows-old` 不算 Windows 后代）。选择包含系统目录的更高层根时整树排除该系统目录并提示，不允许通过全盘处理绕过限制。该规则不自动扩大为拒绝所有 Program Files、用户目录或盘根；它们仍受其余范围与权限规则约束。不提供放开系统目录限制的开关。

- **S-06** 整理摘要按逻辑大小报告已永久删除的项，不声称等于文件系统实际释放量；已可靠识别为同一个物理文件的硬链接，不重复计入可删除或已删除的数据量，跳过的项不得计为实际删除。

- **S-07** 不实现备份、事务回滚、断点恢复或任务重放。运行日志仅供界面审计，显示最近 300 条、最新在上，不提供导出。本次解压失败项另按 U-10 提供完整分页列表，不因日志淘汰而丢失失败明细；该列表不是历史任务库，不要求跨运行保存，不提供导出。

- **S-08** 目录整理去重保留策略中的「最新」指修改时间（mtime），不指 Xberg 发布版本，目录整理去重的平局规则见 C-03；归类不使用任何时间信息，两者互不影响。递归解压不按时间或大小选择保留者，冲突一律自动改名新文件。

## 6. 规则面板（R）

- **R-01** 按当前工具显示相关分区：递归解压显示解压及安全性能项；目录整理显示去重、归类、清理及安全性能项。MD 整理与 Git 工具不设规则面板：可调项（递归开关、输出位置、拆分大小、仓库路径等）直接位于各自功能页面。低频规则默认折叠进高级选项，默认配置直接可用。用户偏好仅会话内生效，不自动保存或恢复上次规则，原工具规则无独立设置页和规则导入导出；应用另设 XB-20 的共享组件设置页；允许任务库保存本次规则快照供计划一致性与审计使用，不作为下次任务的用户偏好。
  - 任务规则快照只服务当前计划一致性及内部审计，不要求任务库 UI、历史任务浏览或跨运行保留失败明细，不可用于恢复偏好或重放操作。当前任务结束后可在本次会话保留当前规则，重新启动程序恢复合同默认值。
  - 截图 OCR 的独立持久设置见 O-15，只适用于该后台服务；不将原工具的会话内规则改为跨运行保存。
  - 应用级 Xberg 配置按 [XBERG-INFERENCE.md](XBERG-INFERENCE.md) 的 XB-20 / XB-21 由独立设置页管理，两种来源和当前选择使用 SQLite 持久保存并在重启后自动恢复；该例外不改变本条中原工具处理规则的会话范围。

- **R-02** 规则面板按附录 D 的工具归属完整提供可调项。递归解压不提供去重、覆盖淘汰、删源方式、统一输出或冲突询问；目录整理保留三类去重开关、最新/最旧/最短名称保留者、全局保留/永久删除方式、大文件选项、C-08 六类开关及删除项覆盖。无最大/最小保留者、硬链接替换、关闭归类、另选输出目录、合并同名来源目录或折叠单子项层级选项；无关闭最终空目录清理、Git 保护/集合移动、失败容器保护的选项。摘要算法、命名规则和固定保护不是可配置策略。

- **R-03** 两工具默认递归扫描所选根全部后代。关闭递归时只处理根直接包含的普通文件；对子目录仅做必要 Git / 链接边界检查，不扫描其普通后代，直接子级 Git 项目可按 C-14 整体归类。递归解压在此模式下仅继续处理新落在根直接层级的嵌套包，落在子目录的包不继续解开并提示范围限制，不将此称为全部递归解压。目标分类目录可为已纳入文件创建，但不因此把其原有深层内容加入去重或清理范围，目标占用检查仍必须执行。哈希线程仅目录整理提供，1～16，默认 6，机械盘建议 1；磁盘预留与解压防护参数仅递归解压提供，详见附录 D。性能满足 H-01 / H-02，不为统计排除项而扫描排除树，不以阻塞界面换吞吐。

- **R-04** 整理规则或目录改动后，既有分析结果与执行按钮失效，必须重新分析；不允许用旧计划执行新规则。

## 8. 引擎与发布（E）

- **E-01** 构建所需 7-Zip 引擎只从官方 release 获取，固定版本并校验上游 SHA-256，不使用镜像；引擎可执行文件不进入 git，也不以独立可执行文件形式进入发布包。
  - 每个发布版本必须有唯一可核对的引擎来源清单，记录精确版本、架构、官方源 URL、上游下载包 SHA-256 及运行期所用文件摘要；构建和运行校验均以该清单为准，不以“最新版”代替固定版本。清单随发布提供供核对，不要求把每次引擎升级的具体摘要复制到合同正文；更新版本不得削弱来源和校验要求。

- **E-02** 运行期引擎解析顺序固定：EXE 同目录的 `resources/7zip` → 已释放的内嵌副本 → 从 EXE 释放。候选必需文件全部存在且逐文件符合 E-01 清单后才能使用；缺失或校验失败的候选绝不执行，显示原因并继续下一顺位，不自动覆盖现有文件。需要重新释放但固定位置被无效文件占用时，允许释放到新的独立自有位置，仍校验后使用，不删占用文件。全部候选不可用时按 E-05 报错停止。引擎可替换性仅指符合发布清单的候选，不允许替换为未校验任意程序。

- **E-03** 发布包必须保留 `licenses/`、NOTICE 与上游源码压缩包；打包时检查独立引擎可执行文件泄漏，检查不通过不得继续发布。

- **E-04** 发布经手动触发的 CI 工作流产出安装包 EXE 与便携 ZIP 两种产物；打包中未执行的阶段必须如实标注 `NOT RUN`。
  - 两种交付均包含 U-08 软件渲染启动入口、E-01 来源清单及 E-03 合规材料；不因提供启动脚本而增加处理命令行。发布失败或未执行阶段不能用其他产物存在冒充验收通过。

- **E-05** 构建机缺引擎时允许构建，只是不内嵌；运行期无引擎时解压必须明确报错并停止，不得静默跳过。引擎只能按 E-02 的顺序获得，不提供用户指定引擎路径的参数。

## 附录 B：名称、比较与扩展名定义（C-02 / C-03 / C-08 / C-16～C-21 / H-07）

### 文件名切分

- 普通扩展名为最后一个点及其后非空部分；点在首位且之后无其他点的名称（如 `.gitignore`）整体为主体，无扩展名。`.DS_Store` 按 C-08 完整名匹配，不依赖扩展名切分。
- `.tar.gz`、`.tar.bz2`、`.tar.xz`、`.tar.zst`、`.tar.lzma`、`.tar.z` 为复合扩展名，整体保留；匹配不区分大小写、输出保留原后缀大小写。其他多点名称只将最后一段视为扩展名，除下条分卷模式外不猜复合后缀。
- X-10 数字尾卷的「白名单扩展名 + `.NNN`」（如 `.7z.001`、`.tar.gz.001`）、part rar 的 `.partN.rar`、老式 `.rNN` / `.zNN` 在改名时均为不可拆分后缀。隔离用 X-10 的整组改名，整理只对每个普通文件主体按 C 规则命名，不改变编号串。
- 项目目录名整体为主体，含点也不拆扩展名；不对 Git 项目名执行文件副本后缀清理或内容签名修正。

### 比较与稳定决胜

- Windows 同名关系使用不依赖界面语言的序数忽略大小写比较（Windows ordinal ignore-case 语义），不是按拼音、自然数字或当前区域排序；操作系统实际报告的目标占用同样必须避开，即使其等价规则更严格。
- 稳定升序：将相对路径的目录分隔符统一 `/`，先按上述忽略大小写的序数比较，仍相同则按原始 UTF-16 单元序列逐单元升序决胜。长度为同样路径表示的 UTF-16 单元数，包括 `/`，不含根路径。保留者使用分析时原路径，不使用将生成的目标名。
- C-02 同名键是原完整文件名的忽略大小写比较键；副本名键按下面副本标记规则剥除后，连同未改变的扩展名一起比较。副本名键只用于候选判定，不能替代 C-08 的输出名，也不决定删除；删除仍以完整内容哈希为依据。

### 副本标记和名称规范化

- 副本标记仅识别主体末尾连续出现的标记序列：ASCII 圆括号包围的一个或多个十进制数字 `(N)`、ASCII 连字符加 `Copy`（忽略大小写）、中文 `副本`。标记前允许零个或多个 ASCII 空格，连字符与 Copy 之间允许零个或多个 ASCII 空格；不把主体中间的同样字串当作后缀。`report(1)`、`report (01)`、`report-Copy`、`report - copy`、`报告副本` 都识别。
- 从右往左收集整段末尾标记，剥除后保留原先从左往右的数字顺序。用于去重名称键时全部标记移除；用于输出名时每个 `(N)` 转为 `_N`，十进制前导零去掉、全零保留 `0`，其他标记移除。已有 `_1` 不视为待剥除副本标记，避免再次整理继续变化。
- 例：`报告 (1) (02).pdf` → `报告_1_2.pdf`；`report - Copy (1).tar.gz` → `report_1.tar.gz`；`报告副本.pdf` → `报告.pdf`；`报告副本说明.pdf` 不因含「副本」改名。`(1).pdf` 的基础主体为空时使用 `_` 作基础主体，得到 `__1.pdf`；不剥掉 `.pdf`。
- NFC / 空白开关开启时，对主体先做 NFC，将 Unicode White_Space 属性中的连续字符压成一个 ASCII 空格，并去除主体首尾空白；再执行开启的副本后缀清理。未开启的规范化不隐式执行；派生结果的合法性检查始终执行。
- 来源目录加入普通文件候选前，也按已开启的 NFC / 空白规则规范化该来源段，但不对来源段剥副本标记、不改源目录。完整候选生成后再按同一输出规则检查至不再变化，然后判定占用与长度，避免下一轮首次清理新加的前缀或因截短暴露的末尾副本标记。项目目录候选仅做必要合法性处理，仍不应用普通文件清理规则。
- 因派生改名产生的主体末尾 ASCII 点或空格去掉；主体空、`.` 或 `..` 时用 `_`。主体中的 Windows 禁用字符 `< > : " / \ | ? *` 及 U+0000～U+001F 替换为 `_`。来源目录拼接后的名称也受此约束，但绝不改写源目录名本身。
- 派生完整名若命中 Windows 设备保留名（含带扩展名形式的 CON、PRN、AUX、NUL、COM1～COM9、LPT1～LPT9 及系统视为等价的设备名），在主体前加 `_`，再验证。原扩展名本身无法合法保留时安全失败，不删除扩展名。合法性变换后重新参加全目标冲突判断；不能把 `_` 当作唯一名称保障。
- 本节输出规则仅适用于目录整理；解压对归档成员的危险或非法原名按 X-08 整包拒绝，不借本节把危险路径“修好后放行”。正常解压目标冲突仍按 H-07 / X-04 仅改主体。

### 内容签名修正扩展名

- 该开关默认关闭，开启后只在分析阶段为非排除、非待删普通文件判型；无需对所有文件计算完整哈希。无法可靠判型不改，错误不可导致删除或猜测性改后缀。
- 本合同要求可确定识别并修正的类型为 PNG、JPEG、GIF、BMP、TIFF、WebP、PDF、FLAC、WAV、ZIP、7z、RAR，以及通过 ZIP 内部类型标识可确认的 DOCX、XLSX、PPTX、DOCM、XLSM、PPTM、ODT、ODS、ODP、EPUB。识别依赖该格式的有效结构与必要类型标识，不能仅凭几个相同开头字节把任意内容认作文件类型。
- 确认类型且现后缀不正确时，采用 `.png`、`.jpg`、`.gif`、`.bmp`、`.tif`、`.webp`、`.pdf`、`.flac`、`.wav`、`.zip`、`.7z`、`.rar` 或对应小写文档扩展名；已有 `.jpeg` / `.jpg`、`.tiff` / `.tif` 均为合法同义形式，不强制改名或统一大小写。
- ZIP 容器必须先区分上述文档类型；不能确认其内部类型时，保留原后缀为 Office、ODF、EPUB 或 X-09 其他已列容器格式的文件，不降级为 `.zip`。未承诺的类型不进行修正，不以模糊特征强行分类。

## 附录 C：扫描排除 glob（S-04 / R-03）

- 输入为分号分隔的模式列表；去掉每段首尾空白，空段忽略，空列表表示不额外排除。各模式为“或”关系，任一命中即排除。
- 匹配对象为相对所选根的路径，统一使用 `/`，无开头 `/`、无结尾 `/`；用户模式中的 `\` 也视为目录分隔符，不作为转义符。按 Windows 序数忽略大小写匹配，不受界面语言影响。
- 模式匹配整个相对路径，不自动匹配任意文件名片段。`*` 为零个或多个字符，可跨 `/`；连续多个星号等同一个星号，`**` 没有独立递归语义。`?` 为恰好一个 Unicode 字符，不能匹配 `/`。除 `*`、`?`、分隔符和分号外均按字面匹配，不支持字符类、花括号展开、正则、否定或反向纳入；例如 `[ab]` 匹配字面 `[ab]`，不是 a 或 b。
- 不支持转义、引号包裹或分号字面匹配；输入含盘符、绝对路径或独立 `..` 路径段时作为无效模式阻止开始，指出错误段，不悄悄忽略。大小写无关不意味着先改写磁盘文件名。
- 目录路径命中时整树排除，不再为统计其后代读取内容；文件路径命中只排除该文件。目录后代即使没有逐个匹配，也不再纳入。Git 保护、链接边界、Windows 系统目录和隔离容器先于 glob，不存在用模式重新纳入的办法。

|模式|匹配结果|
|---|---|
|`*.tmp`|根及任意层级以 `.tmp` 结尾的路径；若命中目录则排除整树|
|`cache`|根直接子项 cache；若为目录则整树排除，不匹配 `a/cache`|
|`*/cache`|任意非根直接层级的 cache 项，如 `a/cache`、`a/b/cache`|
|`cache;*/cache`|根直接层级及深层的 cache 目录均可排除|
|`a/?.txt`|`a/x.txt`，不匹配 `a/xy.txt` 或 `a/b/x.txt`|

隐藏和系统属性开关是两个独立的包含开关，均默认开；某项具有任一被关闭包含的属性就排除。目录被属性排除时后代整树排除，不因后代属性不同重新纳入；必要 Git 边界检查仍在排除前进行。排除是范围限制，不是执行失败；界面同时显示限制与处理结果，不能把“范围内完成”写成“全部目录均已处理”。
