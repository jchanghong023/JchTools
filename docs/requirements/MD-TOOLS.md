# MD 整理需求（M）

本文唯一维护 Markdown 合并与无损拆分，不包含 [转 Markdown](ALL2MARKDOWN.md) 的文件转换。全局约束及共用界面、错误要求见 [CONTRACT.md](CONTRACT.md)，其附录 E 保留本域的边界期望；开发纪律见 [../../AGENTS.md](../../AGENTS.md)。本文不记录实现或测试状态。

## 3. MD 整理（M）

本工具是现有工具箱的新增独立工具（H-03 / M-01），只读处理 Markdown 文件：不修改、不删除、不移动任何原始文件，输出一律写入用户指定的新文件。

- **M-01** 功能范围与导航：保留工具箱现有全部功能，在现有左侧导航中新增「MD 整理」导航项；点击进入 MD 整理页面。当前 MD 整理只包含「合并 MD」和「拆分 MD」两个功能，不提供格式化、TOC、图片整理、链接检查、Front Matter、Markdown 转换或其他任何 Markdown 工具功能。

- **M-02** 合并输入与扫描范围：用户选择一个目录，并提供「不递归 / 递归」选项。不递归时只处理所选目录直属的 `*.md` 文件；递归时处理该目录及全部子目录中的 `*.md` 文件。扩展名 `.md` 匹配不区分大小写；扫描不跟随符号链接、junction 或其他 reparse point（与 S-04 的链接边界同口径）。原始文件全部保持不变。MD 整理只读取匹配文件参与合并、不改动它们，因此不做 H-06 的 Git 整树排除，也不做隐藏 / 系统属性过滤。

- **M-03** 合并顺序：全部参与合并的 Markdown 文件按文件创建时间从早到晚排序；多个文件创建时间完全相同时，以相对路径自然排序作为稳定的第二排序键——把相对路径（分隔符统一 `/`）切分为连续数字段与非数字段，数字段按数值比较（`2.md` 排在 `10.md` 之前，不是字典序的 `10.md` 在前），非数字段按 Unicode 码点逐字符比较，段序列按字典序决胜。文件创建时间按文件系统报告的创建时间；不可得时按修改时间替代。排序结果必须确定、稳定、可重复。

- **M-04** 合并后的文件结构：对每个原始 Markdown 文件，先输出一个新的 ATX 一级标题，标题文本为文件名本身（含 `.md` 后缀），例如 `abc.md` 输出 `# abc.md`；然后把该文件内部已有的 Markdown 标题按 M-05 整体下移一级。文件名标题与正文之间保留正常 Markdown 空行；不同文件之间也必须保证合理空行，防止上一文件最后一行与下一文件标题粘连。除标题下移与必要空行外，不增加任何本需求之外的说明文字、分割说明或元数据。

- **M-05** 标题转换规则：同时支持 ATX 与 Setext 标题。
  - ATX 标题（行首至多三个空格的 `#` 序列，`#` 后接空格或行尾，一至六级）：`#` → `##`、`##` → `###`、`###` → `####`、`####` → `#####`、`#####` → `######`、`######` 保持 `######`。Markdown 最大只保留六级标题，原六级标题保持六级，不生成七级（`#######`）。
  - Setext 标题：文本行下一行为仅由 `=` 组成的下划线行，视为一级标题，转换为该文本行加 `## ` 前缀的 ATX 二级标题；文本行下一行为仅由 `-` 组成的下划线行，视为二级标题，转换为 `### ` 前缀的 ATX 三级标题；原下划线行不再输出。Setext 判定要求下划线行紧跟非空文本行且不在代码块内。

- **M-06** 代码块保护：fenced code block 内的内容绝不能因为看起来像 Markdown 标题而被修改。fence 开始与结束均支持 ``` 与 `~~~` 两种字符，开始 fence 允许携带语言标注（如 ```bash）；代码块内的 `# shell comment` 等形似标题的内容必须保持原样。fence 开闭状态按开始 fence 的字符与长度匹配。行首缩进至多三个空格的 fence 有效，四空格及以上的缩进行不视为 fence 也不视为标题。

- **M-07** 合并输出与流式处理：用户可选择输出文件名与输出路径，生成新的 `.md` 文件。目标文件已存在时不得静默覆盖，必须使用项目现有交互模式（模态确认）提示用户，未获得明确覆盖操作前不得破坏已有文件。输出文件位于被扫描目录中时，扫描阶段不得把此次输出文件误作为输入参与合并。合并优先采用流式处理（逐文件逐行读写），不把整个目录的全部文件一次性读入内存；处理大量或超大文件时界面保持响应（U-12）。

- **M-08** 拆分输入：用户选择一个 `.md` 文件，并设置单个输出文件的最大大小，单位 KB / MB；换算固定 1 KB = 1024 字节、1 MB = 1024 × 1024 字节。大小必须为正数且换算后为整数字节，非法输入显示字段错误并禁止开始，不自动截断或钳制。原文件不修改、不删除。

- **M-09** 拆分硬限制：拆分大小是严格硬限制——任意输出文件的实际 UTF-8 字节大小必须小于等于用户设置的限制；不得因为章节、段落、代码块、列表等任何结构较大而允许输出文件超过限制。拆分不要求按 Markdown 结构（一级标题、二级标题、章节、段落、列表、表格、代码块等）进行，可以在任意安全的 UTF-8 字符边界处分割；核心优先级是严格满足用户设置的文件大小，而不是保持每个 Markdown 章节完整。

- **M-10** 拆分无损：不得把 UTF-8 多字节字符（中文、日文、Emoji 及其他多字节 Unicode 字符）从中间切断。拆分严格遵守不丢失、不重复、不改变顺序：把所有拆分结果按编号顺序直接进行二进制拼接，必须能够恢复原始文件内容。不得向拆分结果自动插入标题、文件序号、分隔线、注释、元数据或其他额外文本。若限制小到无法同时满足「单文件不超过限制」与「不切断多字节字符」（限制字节数小于文件中最大单字符的 UTF-8 字节数），按错误处理并说明原因，不产生任何输出文件。

- **M-11** 拆分命名与冲突：`document.md` 拆分输出为 `document_001.md`、`document_002.md`、`document_003.md`……至少三位编号；实际文件数量超过 999 时自动扩大编号宽度，且必须保证文件名排序正确、互不重名（编号宽度按本次拆分的实际分片总数统一确定）。用户可以选择输出目录。目标目录中已经存在将要生成的同名文件时，必须在正式写入前检测，不得静默覆盖，使用项目现有交互方式（模态确认）提示冲突，未获确认前不写入。拆分实现适合大文件（分块读写），不要求把整个文件一次性读入内存。
