# 实现与规则语义

## 模块边界

Slint 只负责显示、参数编辑、冲突回答、选择计划；`engine` 是状态机；`archive` 只管理官方本地解压进程；`planner` 产生数据化动作；`platform` 执行删除；`fsutil` 负责路径/快照/不覆盖移动；SQLite 是文件索引、候选、计划、审计的存储，不是自制备份系统。代理工具侧：`proxy` 只读检测环境变量、系统代理、VPN 进程与虚拟网卡，`nettest` 仅在用户点击时对固定目标站点发起 Windows 本机/WSL2 的 TCP 探测；两者都不修改系统、不上传数据。

新增工具首先在 `registry.rs` 增加真实工具描述，再添加它的独立页面和处理模块；现有导航只遍历注册工具。当前结构支持源码级扩展，不是尚未实现的二进制插件 ABI；新增工具仍需接入页面路由并重新编译。工具数大于 5 时显示搜索，搜索显示条件取完整注册表数量，不会因为搜索无结果把搜索框隐藏。

## 阶段状态

`analyzing → ready → executing → finished`；分析/执行异常转 `failed`，执行取消转 `cancelled`。SQLite 中状态不是 ready 的旧任务不允许再次执行。没有断点自动恢复、撤销或后台任务重放。

分析阶段先扫描、执行已授权的解压和解压冲突处置，然后重新扫描实际文件、分级 Hash、生成动作。UI 首次确认清楚说明已经进行文件变更；最后确认针对可见且已勾选的计划。改变规则/目录会使当前执行按钮失效，必须重新分析。

计划包含源/目标路径、源快照、可选保留文件快照、内容 Hash、删除模式和原因。用户修改勾选会先保存到任务 DB，收到确认后才允许执行。执行时按同一个计划分页读取，不重新发明另一套规则。目标冲突/源或保留文件变化均作为失败/跳过记录，不以覆盖方式“自动修复”。

## 决策顺序

1. 排除规则与保留原包保护先于后续处理。
2. 已启用清理规则的垃圾/临时/零字节候选先标记，不能成为重复组唯一保留文件。
3. 完整 Hash 相同，按相同名称、规范化副本名称、其他名称的独立开关找保留项。
4. 再做同名同大小但内容不同、同名不同大小的版本取舍。它们是用户授权的版本丢弃，不标记为真正重复。
5. 对剩余文件生成命名/目录合并/分类移动计划。
6. 最后自底向上复查目录；只有执行时确实为空才删，不递归删用户目录。

同名不同大小规则只删除大小不同于获选保留项的版本；与保留项同大小但 Hash 不同的文件由另一个规则控制，不能借这个开关绕过用户关闭的同大小版本规则。同大小但未成功算 Hash 的文件被排除出破坏性处理。

去重默认保留最新 mtime，平局使用相对路径长度再按路径排序。Windows 绝大部分普通名称按小写比较；Unicode NFC 只用于副本名称规范化，不声称已经覆盖 NTFS 每一个特殊大小写语义。

## 存储、IO 与容量

扫描每 2048 项提交一次；候选索引落 SQLite，Hash 每批约 `max(16, 4×线程数)` 项，预哈希与完整 Hash 的候选集合分阶段物化，避免每一页重新全表分组。解压条目列表在一个 DB 事务中写入，避免每个条目单独提交。

固实包整包解一次，进程输出两管道同时有界排空，不使用积累所有输出的 `Command::output`。条目清单和压缩元数据先检查，拒绝危险路径/链接/加密，非零退出码包括“警告”都不视为完全成功。当前只能处理可可靠取得条目大小的包。

输出写入同卷自有 staging，完成后 rename，不再复制整份数据。**磁盘上仍需要当前整个包的解压空间**；不能用这份代码声称已经实现流式零临时空间处理。多线程 Hash 不等于所有磁盘都更快，机械盘可设 1 个线程，SSD 可逐步调整；吞吐和资源占用以实测为准。

## 删除与链接

Windows 使用 `IFileOperation` 的回收标志与提前失败标志；不是拿 Rust `remove_file` 冒充回收。回收成功后检查源路径消失。回收失败且用户开启降级才调用永久删除；收到取消码或任务取消，必须保留；Shell 只返回含糊的“已中止”而没有明确失败码时也按取消保守处理，因此这种情况不会自动永久删除。回收端失败后若发现原路径已消失，按已回收处理，不去删除可能的新目标。测试通过注入 Recycler 模拟成功、容量不足、取消，Windows 真正 Shell 行为另行验收。

硬链接模式先创建替代链接，成功后才处理原副本；跨卷/不支持链接会在原文件删除前失败。修改任意硬链接会影响其他别名，不能把它宣传为互相隔离的备份。原本同 identity 的多个路径不计为重复占用空间；改用回收站会保留旧数据占用。

## 界面与并发

自绘无边框标题栏 + Fluent 控件 / 中文界面 / 主题 / PerMonitorV2 manifest；程序主窗口优先显示，再后台读取小配置。扫描/Hash/解压/计划/文件操作都由 worker 执行，UI 用 100ms 定时器批量接收有界事件。只有短小的配置/状态核对在 UI 回调中，未进行真实延迟测量。

持续状态允许合并/丢弃以保护 UI；冲突问题、结果等重要事件可靠传递。SQLite 审计是完整记录，GUI 只显示最近 300 条；分页计划从 DB 获取并关联任务路径，避免旧任务后台结果覆盖当前页面。
