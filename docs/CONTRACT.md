## 最高优先级需求（H）

- **H-01** 个人工具，性能优先：JchTools 用于用户个人资料整理，处理性能是首要要求。避免无必要的重复扫描、重复读取文件内容、重复计算和复制；不为企业级、多人协作、处理期间外部改动等非目标场景增加负担。性能优化不得通过漏处理、错误删除或暗中缩小处理范围来实现。

- **H-02** 易用与流畅优先：界面方便好用、操作流畅是首要体验要求。扫描、解压、哈希和整理期间界面必须保持响应，处理状态可见、取消入口可用；常用操作直接可达，低频配置不妨碍日常使用。不以阻塞界面换取后台吞吐，不为方便而强制用户执行另一个工具。

- **H-03** 两个独立工具：保留「递归解压」和「目录整理」两个独立、正常可见的工具入口。用户可以只递归解压并按 X-05 清理成功原包，结束后不得自动进行目录整理的去重、归类或清理；目录整理也不得自动解压。需要完整整理时，由用户先使用递归解压工具，再使用目录整理。「先解压、后整理」是使用顺序，不是统一入口、自动串联或将独立工具降为低频入口的要求。

- **H-04** 递归解压结果：在明确的处理范围内，X-01 白名单内、能够由捆绑引擎成功解开的压缩包及本次解出的嵌套包都应完成解压；H-06、S-04 和 X-07 排除的范围除外，白名单外容器不被解压、也不计为未完成。每个包完整成功后按 X-05 永久删除原包及实际分卷，不把删除职责留给目录整理。确实无法解开的包按 X-06 隔离保留并说明原因；取消或空间不足时原地保留当前源包并停止。防护上限、范围限制或失败导致内容未解开时，不得宣称已全部解压。同次任务已处理的包不得反复入队；目录整理不补做解压、不无条件删除压缩包。

- **H-05** 整理后没有空目录：目录整理成功完成后，处理范围内除用户选定的根目录外，不得残留空目录，包括解压、去重、归类、删除后新产生的空目录。自底向上清理实际为空的目录及空目录链，不得递归删除有内容的目录；H-06 排除的目录树不参与清理。取消或清理失败时如实显示未完成，不得为了清空目录而在取消后继续删除。本条属于目录整理，不要求仅使用递归解压时额外清理目录。
  - 「处理范围」按 S-04 / R-03 确定：用户明确排除的目录树、关闭递归后未纳入的后代及链接边界不参与空目录清理。分类操作为已纳入文件新建的目标目录仍参与最终空目录清理；仅因处理范围缩小而留下的目录不算清理失败，但必须显示范围限制。

- **H-06** Git 目录整树忽略：任一目录直接含有名为 `.git` 的目录或文件时（一个 Git 项目取其最外层，内部再出现的 `.git` 不单独划分项目），该目录及全部后代整树排除：不解压、不读取内容参与哈希或去重、不改名、不删除、不清理内部空目录。唯一例外是目录整理的归类——整个项目目录作为一个整体移入「Git项目集合」目录，除此之外不进入树内做任何处理（去重、附属文件清理、改名、空目录清理、解压都不进行），见 C-14。只允许为识别边界进行必要的目录项检查，识别后不继续遍历内部；除该整体归类移动外，不得通过移动、改名或删除祖先目录间接改变该树。该排除不受隐藏文件、递归或清理开关影响，不提供关闭选项，整体归类移动同样是固定行为、无开关。选定根目录直接含 `.git` 时，整次处理不执行并明确提示；只有子目录含 `.git` 时，只排除该子树。新解出的目录含 `.git` 时，后续处理同样排除；界面明确提示 Git 目录的处置结果。
  - `.git` 名称按不区分大小写识别，`.GIT` 同样保护，不要求读取标记内容或验证仓库有效性。开始扫描前沿所选根及其祖先到卷根检查直接目录项；任一祖先直接含 `.git`，说明所选根位于 Git 项目内，两工具均拒绝整次处理。不能完成必要边界检查时不猜测为普通目录，报错且不开始处理。
  - 固定整体归类只适用于本次扫描范围内识别到、且不在用户排除或隔离容器内的项目；不以“归类固定开启”为由进入缩小范围之外查找项目。

- **H-07** 递归解压不去重、不删除无关文件：只允许按 X-05 永久删除完整成功解开的源压缩包及其实际分卷，不得删除既有用户文件或已落盘的普通解压结果，不得以内容相同为由跳过正常落盘。目标冲突时保留已有文件，只为新解出的文件自动选择未占用的文件名，不覆盖、不淘汰、不询问冲突策略。只改文件名主体，原扩展名及复合扩展名保持不变，例如 `资料.txt` → `资料 (1).txt`、`资料.tar.gz` → `资料 (1).tar.gz`；不得通过更换或追加扩展名规避冲突。工具自身临时工作区只按本次所有权标记清理，不得删除用户目录。目录整理的去重、删除职责不受本条取消。
  - 「普通解压结果」不含已作为独立嵌套源包、随后满足 X-05 删除条件的归档；普通文件不会因为扩展名相似而被删。嵌套包是否删源逐包决定，不要求其所有后代包也成功。复合扩展名切分见附录 B，卷集改名另按 X-10 保持整组关系。

- **H-08** 完全不考虑无障碍：本项目不提出无障碍需求，不为屏幕阅读器、辅助技术、无障碍元数据、专门的键盘遍历或焦点规范进行开发、维护、测试和验收。不得以无障碍合规为由增加功能、复杂度或验收门槛；普通鼠标和键盘操作仍按 H-02 的方便好用要求处理。

## 0. 产品定位（P）

- **P-01** JchTools 是用户个人使用的 Windows 本地工具箱；「递归解压」「目录整理」是工具名称，不得用作产品名。

- **P-02** 工具经统一注册表（id / 名称 / 类别 / 摘要）接入，侧栏导航遍历注册表，不设空占位分类。当前两个工具为递归解压（文件类）和目录整理（文件类），均按 H-03 独立启动。

- **P-03** 离线处理：所有文件处理功能离线可用，程序自身不得发起网络请求，不得上传文件、日志或路径。用户主动点击关于页官网链接时，允许交由系统浏览器打开，不附加用户文件、路径或日志信息；该例外不允许后台联网或自动打开网页。
  - 关于页外开仅允许发布时确定的项目官网 `https://` 或 `http://` URL，不接受文件内容、路径或日志拼成 URL，不调用 `file:`、脚本或自定义协议。目标网址须在关于页可辨识；具体域名是发布身份信息，不影响离线处理规则。

- **P-04** 界面中文；浅色、深色主题默认跟随系统，可在「关于」页切换；颜色使用统一设计令牌。

- **P-05** 个人使用交付，两种形态并列：安装包安装到当前用户目录，不要求管理员权限或 UAC，默认创建桌面快捷方式、开始菜单入口及系统卸载项；同时提供便携 ZIP。不要求代码签名与公开分发验收。

- **P-06** 不提供命令行界面，全部用户操作经图形界面完成；不提供整理报告及任何形式的报告或日志导出，包括 CSV。

- **P-07** 平台支持范围仅为 Windows；构建、测试、验证和 CI 只在 Windows 上运行，不为其他平台维护测试入口、验证阶段或流水线 job。

- **P-08** 不防御处理期间的外部改动：扫描、分析、执行全程假定文件与目录不被其他程序修改、删除、改名或替换，不为此做变化检测、二次快照比对、冲突重算或并发保护。发生此类外部改动时结果不作保证，该情形不计入需求范围；本条不取消不覆盖移动、路径边界检查或程序自身必要的同步。

## 1. 递归解压（X）

本工具只做递归解压及成功原包清理，保持已有文件，不自动启动目录整理。

- **X-01** 只解压并按 X-05 清理成功原包，不去重、不删除无关用户文件、不归类、不做垃圾清理；不得为了跨目录去重或同名冲突裁决额外计算内容哈希或逐字节比较内容。自动解压只认用户意义上的归档文件，判断依据是扩展名白名单而不是引擎能否打开。白名单为 `.zip`、`.7z`、`.rar`、`.tar`、`.gz`、`.bz2`、`.xz`、`.zst`、`.lzma`、`.z`、`.tgz`、`.tbz2`、`.txz`、`.tzst`。压缩流条目（`.gz`、`.bz2`、`.xz`、`.zst`、`.lzma`、`.z`）前面允许再带一层 `.tar`（`.tar.gz`、`.tar.zst` 等），整体作为一个包处理，`.tgz` / `.tbz2` / `.txz` / `.tzst` 是这类组合的别名。扩展名匹配不区分大小写；复合扩展名按整体识别，不拆成两个包、不单独计数，中间层不留在正式位置。单文件压缩流按包内记录的成员名落盘，包内没有成员名时用去掉压缩扩展名后的文件名（`资料.txt.gz` → `资料.txt`、`备份.gz` → `备份`），冲突按 H-07 自动改名。包与分卷的范围见 X-10；白名单之外一律不碰，见 X-09。

- **X-02** 流程为一段确认：选目录 → 可选调整规则 → 点击「开始解压」→ 一次确认 → 连续解压至结束。确认说明发现的压缩包数量（限 X-01 白名单）、就地解压去向、完整成功后原包及分卷永久删除且不可恢复、已有文件保留、冲突自动改文件名且不改后缀、无法解开的包保留并记录原因。无计划审核环节，不提供删除方式或冲突策略选项。
  - 确认数量是扫描完成时、当前范围内按 X-01 / X-10 识别的包数；残缺但可归组的卷集计一包。尚未解出的嵌套包未知，不提前估算；运行中新发现者另累计显示，不再次弹出删除确认。Git、隔离容器和用户排除项不计入待处理包数，分别提示已跳过的目录或可知数量，不为获取数量突破排除边界。发现数为零时提示无可处理包，不启动空解压任务。

- **X-03** 就地解压：每个压缩包解到其所在位置，不集中到统一输出目录。

- **X-04** 目标冲突固定按 H-07 自动改名：已有文件不动，新文件选择未占用的文件名，保持扩展名。即使内容相同也不得跳过新文件落盘，不按时间、大小或内容淘汰文件。不提供覆盖、跳过、保留较新、保留较大或逐次询问的冲突选项；自动改名属于正常成功结果。
  - 新文件与已有普通目录同名时也只改新文件名。新目录与已有普通目录同名时合入该目录，内部文件逐项不覆盖；新目录名被文件占用时为新目录选择 `目录 (1)`、`目录 (2)` 等最小未占用序号，并将其成员整体映射到该新目录。不得向既有 Git、隔离容器或链接排除树内合入；需要该目录位置时为新目录另选未占用名，不能借合入修改受保护树。无法生成合法目标时该包不算完整成功。

- **X-05** 只有整包解码与校验成功、全部成员完整落盘后，才永久删除该原压缩包及其实际分卷；空包同样适用，嵌套包逐包判定。不经回收站，不受目录整理的全局删除方式影响；不得误删仅同主干但不属于该包的文件。失败、部分解开或取消时不启动原包删除；删除前检查取消，删除失败必须报错并保留未删除的原包或分卷，不把清理失败当成坏包隔离或报告全部成功。不承诺多卷删除事务回滚。
  - 外层包成员全部落盘后即完成该外层的成功判定；其内层包损坏、加密或超过嵌套上限，不撤销外层成功，外层仍可删源，内层按 X-06 隔离保留。正在合入的外层有任一成员未落盘则不能删源；不能用“内层以后会处理”豁免本层完整落盘条件。

- **X-06** 损坏、加密、引擎不支持、分卷不全、触发防护上限或含危险条目等未能完全解开的包，移入所选目录根下的「解压失败」子目录，不删除；移动不覆盖已有文件，遇冲突保持扩展名自动改名。逐包记录原因，在本次解压失败项分页列表中完整可查，不受最近 300 条运行日志的容量限制，见 U-10；隔离不等于完成解压。空间不足或用户取消不作为包损坏隔离，保留当前源包并停止本次解压任务。
  - 隔离按 X-10 的实际卷集一次规划目标名，不覆盖、不丢卷；移动失败时保留未移动源项，列明已移动及未移动位置，不宣称整包隔离成功。固定「解压失败」容器被文件占用或无法创建时，不删除占用项、不私自另建不同名容器；该失败包原地保留并记录隔离失败，其他不依赖该失败操作的包可继续。

- **X-07** 同次任务内避免重复处理已经处理的包；再次启动是新任务，对仍在处理范围内的包不增加跨运行内容比较或按历史成功记录自动跳过的机制，已有结果冲突仍自动改名。扫描遇到名为「解压失败」的目录时整树固定跳过，不依赖是否曾记入日志、失败列表或任务库；用户手动放入的普通包也跳过，不提供关闭选项，移出后下次自然重试。所选根本身名为「解压失败」时不开始解压，提示先将待重试包移出隔离容器。新解出的同名目录也按此规则停止后续递归，并提示范围排除；本层已完整落盘的成功判定不受后续排除改变。历史失败目录跳过不计为本次新失败，跳过路径及未完成事项明确可见。目录整理按 C-09 / C-10 执行。

- **X-08** 解压防护与取消规则：
  - 顶层包深度为 1，包内新解出的包为父包深度加 1；复合压缩流整体算一层，不把 `.tar.gz` 拆为两层。最大深度默认 16，深度等于上限仍处理，超过上限的包不解码，按 X-06 隔离并说明。可调范围见附录 D。
  - 单包条目数包括归档列出的文件、目录及重复路径条目，上限默认 100 万，等于上限允许，超过失败；可调范围见附录 D。最大展开比例是该包解码输出的累计逻辑字节数除以实际输入卷集合总字节数，默认 10000，0 为关闭；超过才失败，不将磁盘压缩或稀疏占用当作逻辑体积。输入为零且输出非零视为无限比例，输入输出均零视为 0；空包仍须通过引擎校验。
  - 单包与单文件展开体积不另设固定上限，允许 TB 级资料但仍受条目数、比例、空间和文件系统能力约束。解压前和运行中检查目标卷可用空间，预留默认 1 GiB，可调；已知下一步所需空间时，可用空间减预计新增占用不得小于预留。体积未知时运行中持续检查，不能仅做开始前检查。空间不足保留当前源包并停止整次任务，不批量隔离后续正常包。
  - 路径穿越、绝对或盘符相对路径、UNC / 设备路径、替代数据流、符号链接或硬链接成员、加密成员及无法解码或不能合法表示的文件名，任一出现都判整包失败。不得写出危险成员，不得把跳过后的安全子集认作成功；可预检发现时在解码前拒绝，运行中发现时停止该包，按 X-06 隔离。成员落点始终位于临时工作区及经授权的正式范围内，不能穿过既有重解析点。
  - 先解到包所在卷的独立临时工作区，带随机所有权标记；整包解码、条目检查与校验全部成功后才不覆盖合入正式位置。预检或解码失败的包不合入任何临时成员；合入阶段失败则保留已落盘结果与源包，显示部分完成。禁止先删旧目标再替换。临时工作区不参与本次扫描入队、分类或去重。
  - 取消在文件操作安全边界生效，不启动后续成员合入或源包删除；已落盘结果与尚未删除的原包或分卷保留，明确提示部分结果已处理。不承诺整包事务原子性或回滚；崩溃、强制中断不得报告为成功。
  - 只按本次所有权标记清理临时工作区，不递归删除用户目录或已落盘结果。
  - 不承诺崩溃残留自动回收或恢复；正常退出前清理失败时显示临时区位置与原因。其他任务遗留目录不得仅凭名称当作本次所有物删除，也不增加历史扫描或自动重放。用户需自行决定遗留资料的处置，不能将强制中断报告为已完成清理。

- **X-09** 白名单之外的文件完全不碰：安装资源 `.cab`，安装包 `.msi` / `.msix` / `.appx` / `.msixbundle` / `.appxbundle`，磁盘与系统镜像 `.iso` / `.img` / `.wim` / `.esd` / `.vhd` / `.vhdx`，程序与扩展包 `.jar` / `.war` / `.ear` / `.apk` / `.aab` / `.whl` / `.nupkg` / `.vsix` / `.crx` / `.xpi` / `.ipa` / `.pkg` / `.dmg`，文档与电子书容器 `.docx` / `.xlsx` / `.pptx` / `.docm` / `.xlsm` / `.pptm` / `.odt` / `.ods` / `.odp` / `.epub`，`.lz4` / `.br` / `.lz`（引擎没有对应解码器的流格式），以及 `.exe` / `.com` 等可执行与自解压文件——即使 7-Zip 能打开也不解压、不改名、不移动、不删除，不进入「解压失败」，不计入确认框的压缩包数量；它们仍作为普通文件参与目录整理。白名单外格式的分卷（`.iso.001`、`.docx.001` 等）以及无法由命名指认出白名单格式的孤立编号文件（如 `data.001`）同样完全不碰：不解压、不改名、不移动、不删除、不进入「解压失败」，不计入确认框的压缩包数量。

- **X-10** 包与分卷：按「同目录、同主干、同命名族」先识别卷集，再判断完整性；编号连续是完整性条件，不是识别条件。缺号或缺入口仍是一组失败包，不把余卷当独立包解开；一组仅入队、计数、判定一次。名称族和入口如下，匹配不区分大小写，数字为 ASCII 十进制：
  - 数字尾卷族：主包完整名具有 X-01 任一白名单扩展名（含复合扩展名），再带恰好三位 `.NNN`，从 `.001` 起；例如 `.7z.001`、`.zip.001`、`.tar.gz.001`。完整主包名自身不加入该族。`data.zip` 与 `data.zip.001` 同时存在时，是独立 zip 与数字尾卷集两个包，不能删除或隔离成一组。末尾 `.000` 可识别为该族的非法起始编号，整组失败，不作为普通独立包处理。
  - part rar 族：`主干.partN.rar`，N 为正整数；无前导零或统一最小补零宽度均可，例如 `part1`、`part01`、`part001` 分别属于不同宽度模式，位数超过最小宽度时自然增长。入口必须是该模式的编号 1；只有 part2、part3 仍识别一组并报告缺首卷。同一主干混用补零模式或重复卷号时，视为一组命名歧义包，列出全部歧义卷，不猜测归属、不解码删源。
  - 老式 rar 族：`主干.rar` 加 `.r00`～`.r99`，入口 `.rar`；老式 zip 族：`主干.zip` 加 `.z01`～`.z99`，入口 `.zip`。只发现这些尾卷、没有主包时仍归组，报告缺主包；没有尾卷的 `.rar` / `.zip` 为普通独立包。同主干 part rar 与老式 rar 同时存在时按不同命名族处理，普通 `.rar` 不加入 part 族。
  - 缺起始编号或中间断号直接判分卷不全；编号连续不证明尾卷齐全，最终还必须通过引擎整包解码及校验。只将上述精确命名族的实际存在卷纳入操作，不根据相似主干吸入备份、说明文件或其他格式。白名单之外及 `data.001` 这类无格式孤立编号仍按 X-09 完全不碰。
  - X-05 删除与 X-06 隔离均以该包实际卷集为边界。隔离遇冲突时选能让整组目标都未占用的最小正整数，统一改主干，如 `data (1).7z.001` / `data (1).7z.002`、`data (1).part01.rar` / `data (1).part02.rar`、`data (1).zip` / `data (1).z01`；后缀、编号及补零原样保留。命名歧义组隔离也保留原卷后缀，不改造成看似完整的卷集。

## 2. 目录整理（C）

本工具只做去重、归类和清理；需要解压时由用户先使用递归解压工具，不自动调用解压。

- **C-01** 独立两段式流程：选目录 → 可选调整规则 → 分析 → 分页计划（逐项可勾选或取消）→ 确认执行。分析只读扫描与计算，不改动待整理资料；用户确认后才执行去重、归类和清理。
  - 分析顺序固定：识别范围与排除树 → 计算开启的文件清理条件 → 从保留的文件中按 C-02 / C-03 判重 → 确定存活项的最终文件名、扩展名与分类目标 → 按 C-17～C-20 统一消解冲突 → 形成计划。附录 B 的去重名称键与最终输出名分别计算，不以清理开关缩小已开启的副本名去重范围。
  - 已确定永久删除的清理项不再参与去重选保留者；已确定删除的副本不再生成归类或改名操作。同一文件命中多个删除规则，只删除、计数一次，计划列明命中的原因。零字节清理选择永久删除时允许整组零字节文件都被清理，不受“去重至少留一份”约束；选择保留时仍可参加去重。
  - 多条文件清理规则同时命中时，各自按显式覆盖或全局方式决定是否请求删除；任一已启用规则请求永久删除，即形成一次清理删除。某项选择保留只取消该项的删除请求，不否决其他已启用规则；计划必须列出实际导致删除的规则，不能只显示选择了保留的那项。用户取消该文件删除计划行则取消对该文件的全部清理删除请求。
  - 内容签名修正若开启，分析阶段确定修正后的扩展名，再据此归类；移动保留创建时间与修改时间（跨卷复制同 S-01 的忠实移动要求）。执行不重新读取内容判型或哈希。
  - 计划按可独立授权的最终处置展示：同一存活项的改名与归类显示为一项源路径到最终路径的操作，不将相互依赖的中间移动伪装成独立步骤。执行遵守依赖关系，不要求按界面显示行顺序操作。
  - 取消勾选后，未执行项原位置视为占用，禁止删除依赖于已取消保留者移动的其他项。仅使用已有分析资料重新计算受影响的计划，不新增用户勾选、不读取内容；目标或依赖改变必须显示给用户，并按更新后的勾选结果确认后执行。没有任何可执行文件操作时仍可执行范围内必要的空目录清理。

- **C-02** 去重名称关系分三类：同名与副本名默认参与，不同名默认关闭、可手动开启。按附录 B 的名称键分组：原名比较相同属同名；原名不同但去除副本标记后的名称键相同属副本名；其余属不同名。启用的名称关系在同尺寸文件间构成候选关系，候选连通组内按完整内容哈希分成重复组；不同名开启时同尺寸项均为候选，不再受名称限制。只有整文件哈希一致才判定内容重复；删除前不得逐字节复核或做任何二次内容比对。同名但内容不同的文件不得自动淘汰，也不提供此类开关。哈希不可得的项保留并说明，不能凭名称或大小删除。

- **C-03** 重复组默认保留修改时间最新者；可选修改时间最旧者或最短名称者，不提供最大或最小选项（内容相同的文件大小相同）。最新按有效 mtime 降序，最旧按有效 mtime 升序；缺失 mtime 的项排在有效时间之后。最短名称按分析时原文件完整名称（含扩展名）的 UTF-16 单元数升序。各策略主条件相同时，统一按相对于本次所选根的原始路径长度升序、再按路径稳定升序决胜；比较定义见附录 B。保留者不由扫描顺序、线程完成顺序或计划排序决定。

- **C-04** 重复副本处置只有「保留副本」和「永久删除副本」，默认按 S-02 的全局文件删除方式永久删除其余副本；选择保留时不生成去重删除操作，副本仍按其余已启用规则参与归类和清理。不提供硬链接替换模式，不新建硬链接。可靠文件标识证明两个路径已指向同一个物理文件时，不再作为独立副本执行去重删除；此项既有硬链接识别保护仍保留，不因取消建链功能而取消。标识无效、退化时不得据此跳过去重，也不得额外读取内容进行二次复核。

- **C-05** 归类结构固定为「大类 → 功能分类」，不提供关闭归类或改变层级的选项。普通文件最终路径为「大类/功能分类/文件名」，分类目录层级严格只有这两级：禁止出现「大类/功能分类/子功能分类/文件」的三级及以上分类层级，禁止重新出现「大类/年/月/文件」或「大类/功能分类/年/月/文件」等把时间或更深语义层级写入目标路径的形态；多级功能语义（如 AMBA 下的 APB）必须压缩成一个第二级目录名（如 `AMBA_APB`）。大类按最终扩展名映射，唯一映射表见附录 A；未匹配入「其他」，C-06 大文件规则开启并命中时优先。功能分类表示这组文件实际属于的功能、主题或技术领域，由分析阶段按本条下列规则确定性生成。文件不保留原相对路径，直接落到大类/功能分类；分类目录与 C-14 的「Git项目集合」均固定建在本次所选根下，不提供另选输出目录。失去内容的原目录按 C-07 消失；因排除、取消勾选或失败而仍有内容的目录不得为满足标准形态强行删除。目标命名按 C-16～C-21 消解，标准结果见 C-15。固定目录的同名占用按 S-01 处理。
  - 分类依据与边界：功能分类只允许使用文件名与整理时当前真实可见的紧邻原父目录名称两类信息；不读取文件正文，不解析 PDF / Word / PPT / Excel / 图片 / 视频内容，不做 OCR，不读取文件内部 metadata 用于分类，不联网，不引入大语言模型、Embedding 或其他推理模型；纯本地、纯 CPU、离线，用确定性的传统字符串与统计方法完成。不恢复已经在过去整理中消失的历史目录信息（与 C-18 同口径）。功能分类不得跨大类合并；不同大类下允许出现同名功能目录（`文档/MBIST` 与 `图片/MBIST` 互不影响）。
  - 特征构造（只影响分类特征，不修改实际文件名；实际文件名的规范化、冲突改名继续按 C-08 / 附录 B / C-16～C-21 执行）：名称先做 Unicode NFKC 规范化、统一大小写、把各类分隔符视为词边界；日期、流水号、普通数字编号、版本标记（`v2` / `v3` 等）、自动重名后缀（`(N)`、`[N]`）、`copy`、`副本`、`final`、`最终版`、`最新版`等噪声从分类特征中剔除或降权；`文档`、`资料`、`说明`、`介绍`、`流程`、`版本`、`最终`等大量重复出现时区分度很低的高频低价值词同样降权或剔除。英文以完整单词和原文大写的技术缩写（如 MBIST、ATPG、DFT、RTL、AMBA、APB、JTAG）为重要 token，原文大写缩写串视为强特征；驼峰与字母数字边界拆分（`JTAG2APB` 拆出 `JTAG`、`APB`），长词附带字符 n-gram 以识别拼写变体（`AAMBA` 对 `AMBA`）；中文名称不依赖空格分词，提取 2-gram 与 3-gram 识别「测试流程」「设计规范」一类关联，正确处理中文、英文、数字混排。token 权重按本次待整理文件集合内的出现频率统计：越常见权重越低，越稀有、区分度越高权重越高。
  - 候选与评分：先建立倒排索引（token → 文件），只有共享有意义 token / n-gram 的文件对才进入较贵的精确相似度计算；稀有 token 优先、受全局候选预算约束，禁止全量 O(N²) 两两比较，不得因此退化 TB 级目录的整理能力。综合相似度以加权 token / n-gram 重叠（Sørensen-Dice 口径）为主（方向约 55%），整串字符串相似度（Jaro-Winkler 或规范化编辑距离，方向约 25%）与紧邻父目录名相似度（同口径加权重叠，方向约 20%）为辅；比例是实现方向，不要求机械照搬。公共高信息量关键词的关联强度高于整串字符串长得像：`SMS Mbist 介绍` 与 `Tessent_MBIST_RTL流程指导` 因共同 `MBIST` 强关联，`scan_report` 与 `scanner_driver` 不得仅凭前缀相似合并。紧邻父目录名可增强关联（`MBIST/intro.pdf` 与 `MBIST/flow.docx`），但不能无条件覆盖文件名明显不同的语义。
  - 聚类：对达到高置信度阈值的文件对建立连接，用并查集等轻量结构形成组；连边本身使用较高阈值，文件名或紧邻父目录共享强 token 时允许中阈值。中等强度关联只允许把单个文件并入既有组，不得在两个已成组之间继续传递合并，避免链式误聚类（A 与 B 像、B 与 C 勉强像、A 与 C 完全不像时不得扩散成一个大组）；必要时对最终组做组内一致性检查，大型异常聚类必须能被拆开。整体保守：宁可少合并，不要错误合并。
  - 数量上限与兜底：每个大类（含「大文件」大类与「其他」大类）下自动生成的功能分类目录至多 10 个；固定兜底目录「其他」收纳无法可靠分类的文件，不计入 10 个上限。功能分类采用粗粒度、少目录、高置信度、长期稳定、方便人工查找的策略，优先让资料容易查找而不是追求语义精细：只有一个文件的组、弱关联的两个文件、无法形成明确公共主题的组默认进入「其他」，不为一文件一目录消耗名额；厂商不同、流程阶段不同、RTL / Gate 等附加描述、版本不同、协议子类型不同、文件用途描述不同、少量附加关键词不同不得据此派生新目录（`Tessent_MBIST_RTL流程`、`MBIST算法介绍`、`MBIST Repair Guide`、`MBIST仿真方法` 优先同归 `MBIST`，不得拆成 `Tessent_MBIST`、`MBIST_RTL`、`MBIST_REPAIR`、`MBIST_SIM`）。未入选的小组与其保留组共享核心 token、能可靠合并时并入该组；不得为满足数量上限把语义明显无关的两个组强行合并，不确定时进入「其他」。
  - 超上限取舍与稳定性：候选功能组超过 10 个时按稳定优先级保留——覆盖文件数降序、组内关联置信度降序、核心关键词区分度降序、名称规范化字典序升序；未保留的组按上条规则并入已有大功能组或进入「其他」。功能组的选择与命名不受文件扫描顺序、哈希表遍历顺序或并行调度影响，权重并列时以明确、稳定的 tie-break（规范化字典序等）决胜。目录数达到 10 个后，新增少量冷门文件不得导致已有功能目录改名、大组拆分或大量文件迁移，排名第 10 的目录不得与新候选组反复互换；与当前已存在功能目录同名的候选组在并列时优先保留（在位者优先），新候选组仅在覆盖文件数、置信度或区分度明显更高时才替换在位组，否则进入「其他」。

- **C-06** 唯一归类附加项为「大文件单独归类」，默认关闭；默认阈值 1 GiB，按文件逻辑字节数大于或等于阈值命中。开启后命中的普通文件优先于扩展名大类进入「大文件」大类，功能分类在命中文件集合内按 C-05 同样规则生成，同样受每大类至多 10 个功能目录与「其他」兜底约束；不复制到两个大类；未命中者仍按附录 A 归类。阈值输入范围见附录 D。Git 项目与排除项不参与大小归类。合并同名来源目录、消除单子项层级不设独立选项：普通文件归类与实际空目录清理自然消除已搬空层级，不移动仍有内容的来源目录来强制折叠，也不折叠目标大类/功能分类。切换大文件规则或阈值后须重新分析；归类移动保留创建时间与修改时间（S-01 跨卷复制同口径）。

- **C-07** 整理成功完成前必须按 H-05 自底向上清理实际空目录及空目录链，包括本次操作新产生的空目录；保留选定根目录和 Git 排除树，不递归删除有内容的目录。不提供关闭这一步的选项；用户取消时停止后续删除，如实报告未完成。仅运行递归解压时不执行此项整理清理。

- **C-08** 清理与文件名规则：
  - 系统附属文件清理默认开：普通文件名精确匹配 `Thumbs.db`、`.DS_Store`、`desktop.ini`，或以 `._` 开头；目录名精确匹配 `__MACOSX` 时，其范围内可处理的普通文件均为清理候选。匹配不区分大小写，逐文件列入计划，不因命中目录名直接递归删除整树；Git、隔离目录、扫描排除和链接边界仍优先，空目录另按 C-07 清理。
  - 临时与备份清理默认关：普通文件最后扩展名为 `.tmp`、`.temp`、`.bak`，或完整文件名以 `~$` 开头（Office 临时文件）；不把名称中间含这些字符串的普通文件视为命中，不按这些模式递归删除目录。
  - 零字节文件清理默认关，条件为普通文件逻辑长度等于 0；不是“内容全部为零”的非空文件。
  - 副本后缀清理默认开，精确语法见附录 B：末尾 `(N)` 转为主体内 `_N`，`- Copy` / `副本` 标记移除；`report (1).pdf` → `report_1.pdf`。不限于去重保留者。复合扩展名整体保留，规则连续应用后的名称须幂等；先规范化再判定目标冲突。
  - 文件名 NFC 规范化及连续空白合并默认开；空白范围和空主体、保留名等合法性处理见附录 B。不改写扩展名、不删除正常字符；合法性处理只作用于实际派生的新名称，不为修饰既有合法名称额外改名。
  - 按内容签名修正错误扩展名默认关，改名必须列入计划。签名不足以确定实际类型时不改名；合法的同义扩展名不强制统一；不能仅因识别到 ZIP 等外层容器，就把 Office 文档或其他容器格式文件改成压缩包后缀。此功能仅属于目录整理，不改变递归解压保留扩展名的要求。
  - 上述各项独立启停；涉及删除的项目可独立覆盖删除方式，默认跟随全局文件删除方式。

- **C-09** 处理范围内名为「解压失败」的目录是固定保留的隔离容器（不区分大小写），其内容不参与去重、归类、文件清理或 Git 集合移动；包括用户手动放入的文件，不依赖日志、任务库或历史记录，不提供纳入处理的开关。发现后提示跳过的目录路径，不为统计其文件数而全面扫描内容。用户将待重试包移出后才重新处理。该目录及其子目录可在必要的目录项检查确认实际为空后按 H-05 清理，但不得读取文件内容或进入 Git / 链接排除树。不得把隔离视为完成解压；Git 整树保护始终优先。子目录单独整理留下的隔离容器，整理父目录时仍按本条保留，不强行聚合或删除。

- **C-10** 成功完成整理后，相同规则再次整理结果幂等（口径见 C-21）；用户手动改动资料、规则切换，或上次取消、失败留下未完成项时，可以重新分析产生新计划。规则或目录改变后，原计划和执行入口失效，必须重新分析。不做处理期外部变化检测，执行按分析记录进行，不得覆盖目标。用户取消不算失败、不报错，在安全边界生效；不实现断点恢复或任务重放，重新运行属于重新分析的新任务。

- **C-11** 任务状态（分析中、计划就绪、执行中、完成、失败、已取消）和计划行状态（待执行、已执行、已跳过、已取消勾选、执行失败）以中文如实显示；取消勾选后即时显示对应状态，重新勾选恢复待执行。仅计划就绪的任务可执行；翻页按钮仅在对应页真实存在时可用，切换类型筛选回到第一页。

- **C-12** 本次整理中，每个需要哈希的文件至多计算一次完整内容哈希，命中 C-13 缓存时可不计算；不做两阶段筛选哈希、采样哈希或二次哈希。候选仅由扫描获得的大小和名称关系决定，整文件哈希一次遍历完成。同尺寸是内容相同的必要条件，不得缩小 C-02 的检出范围。执行阶段不读取用户文件内容进行哈希、采样或内容复核；允许执行计划所需的移动、改名、删除及必要的目录项、元数据操作，不新建硬链接。清理空目录必须检查是否实际为空，但不得借此恢复 P-08 排除的外部变化检测。

- **C-13** 状态目录维护跨运行哈希缓存，以文件标识、大小、修改时间为匹配依据。三者均一致时可复用上次整文件哈希，任一不同或无记录时完整重算；信任三者未变即内容未变，不防御保留时间戳修改内容的行为。文件标识退化、无法区分不同文件时不得复用。缓存只是加速，不改变去重依据或候选范围；不存在、不可读、读写失败时自动降级为正常完整哈希计算，不因缓存故障中止整理或跳过候选，也不要求用户手动修复缓存才能继续使用。

- **C-14** Git项目集合归类：处理范围内每个 Git 项目（定义见 H-06）整体移入本次所选根目录下的「Git项目集合」目录，不参与 C-05 的逐文件归类。项目平铺在集合目录下、目录名保持不变、不保留原相对路径（`a/b/code/project-alpha` → `a/Git项目集合/project-alpha`）；项目同名冲突按 C-17～C-20 同一套规则消解整个项目目录名（目录名相当于文件主体，来源目录取项目当前所在路径并排除分类层级与本次所选根目录本身）。是否「已归类」只看项目是否位于本次所选根目录的「Git项目集合」下：`a/b` 单独整理后落在 `a/b/Git项目集合` 的项目，整理 `a` 时会再次移动、聚合到 `a/Git项目集合`，原目录变空后按 C-07 消失；已在本次根目录集合下的项目不再移动，保证 C-10 幂等、集合目录不自嵌套。项目只做整树平移：内部一个字节都不改写，解压、哈希去重、清理、改名、空目录清理都不进入树内。
  - 没有待移入项目时不预先创建集合目录。已有同名普通目录可作为集合容器，但原有内容不因容器身份获得删除授权；项目只和其他项目及所有目标占用做整目录名冲突消解，不进入项目内部比较。
  - 整体移动只允许不遍历项目内部的同卷目录移动；目标在另一文件系统时安全失败并保留原项目，不为跨卷复制突破 H-06 的禁止进入树内约束。不得通过复制部分项目后删除原项目伪装成“整树平移”。

- **C-16** 名称规范化先于冲突判断：按 C-08 / 附录 B 及各项开关生成名称；主体规范化不改扩展名，显式开启的内容签名修正另行确定最终扩展名，然后按该扩展名确定大类。规范化后同目标目录同名的项按 C-17～C-21 消解；`报告 (1).pdf` 与 `报告_1.pdf` 均为 `报告_1.pdf`，不得因原名不同忽略冲突。对应开关关闭时不做该项规范化。已就位文件也适用名称规范化，已就位身份不豁免明确开启的清理规则；没有变化、没有新冲突时不重命名。

- **C-17** 冲突按整个目标目录统一计算：
  - 每个参与项先确定目标目录（C-05 的大类/功能分类，或 C-14 的 Git项目集合）；目标目录与规范化文件名都相同的项构成一个冲突组，同名判定按 Windows 口径不区分大小写。

  - 组内两项及以上时整个冲突组统一消解，不得按扫描顺序先到先得：`x/合同.pdf`、`y/合同.pdf` 必须得到 `x_合同.pdf`、`y_合同.pdf`，不得出现 `合同.pdf` 配 `y_合同.pdf`。

- **C-18** 逐级加入来源目录消解冲突：
  - 从文件最近的父目录开始，逐级向前增加来源目录名作为前缀（`目录_…_原名`），只增加到让整个冲突组互不相同所必需的最少级数：`正式版_方案.pdf` 仍冲突 → `客户A_正式版_方案.pdf` 仍冲突 → `华东_客户A_正式版_方案.pdf` / `华南_客户A_正式版_方案.pdf` 唯一即停。

- **C-19** 稳定短哈希兜底：按 C-18 用尽可用来源仍不能区分，包括继续尝试来源后仍受到全目标占用阻挡时，采用「最近一级有效来源目录 + `_` + 规范化主体 + `_` + 短哈希」，没有有效来源则省略来源段；不保留本轮试加的整串祖先，只保留最近一级。既有文件名内的旧前缀仍属主体，不剥除。例如 `资料_report_1_A13F72C4.pdf`、`年报_产品说明_1_5B81D992.pdf`；哈希仅示意，过长另按 C-20。
  - 命名摘要输入为分析开始时该项相对于所选根的原始完整路径（文件含完整名，项目用项目目录路径），分隔符统一 `/`，无前导 `/`、无末尾 `/`，保留原始大小写和 Unicode 序列，不做 NFC 或副本后缀清理；以无 BOM 的 UTF-8 编码计算 SHA-256，取十六进制大写前 8 位。无法无损表示的路径保留并报错，不用替代字符制造同输入。此摘要只读路径，不读取文件内容、不使用随机数或文件标识，不计入 C-12 的内容哈希次数。
  - 完整候选与目标占用仍撞名时，对碰撞候选的摘要每次增加 2 位，最多 64 位。完整摘要仍冲突时，在摘要后追加 `_1`、`_2` 等稳定正整数：活动项按附录 B 原路径稳定升序分配各自最小可用序号，避开所有保留项和已分配候选。该极端兜底不由扫描顺序决定，不无限循环。
  - 相同路径输入得到相同摘要；路径或所选根变化可使摘要不同，不要求不同整理历史同名。重复整理不产生新哈希的含义是 C-21 保留已消解名称，不重新计算和替换已有后缀。

- **C-20** 名称过长处理：40 个 UTF-16 单元是冲突候选的退让阈值（含分隔符、哈希和扩展名），不是所有原名的强制上限；255 单元是单段名称硬上限。未冲突的既有合法长名不为满足 40 而改名。
  - C-18 逐层候选一旦超过 40，立即停止增加来源，转为「主体前段 + `_` + C-19 摘要 + 原扩展名」，去掉本轮新加的全部来源前缀，主体先取最长不超过 25 个 UTF-16 单元的前段；不剥除原主体自带的历史前缀。C-19 的最近一级来源候选超过 40 时采用同一形式，不继续尝试更长来源组合。
  - 初始 8 位摘要下若上述结果仍超过 40，继续从主体末尾截短以尽量满足 40，至少保留一个完整 Unicode 字符；扩展名和必要摘要本身过长导致无法达到 40 时允许超过该退让阈值，但不得超过 255。摘要扩展、序号增加时同样先截短主体腾位，不截摘要所需位数或扩展名。连一个合法主体字符、分隔符、必要摘要/序号和完整扩展名都无法容纳时，该项安全失败，不生成非法目标。
  - 截断不拆开 UTF-16 代理对，截短后合法性按附录 B 再检查。扩展名及复合扩展名永不截断。示例：`芯片研发中心第一联合研发重大专项技术合作合同及全部附件资料非常非常长的归档文件名称副本2026.pdf` → `芯片研发中心第一联合研发重大专项技术合作合同及全部_A83F21C7.pdf`。Windows 完整路径限制另按 S-01，不把 255 单段规则当作路径总长度规则。

- **C-21** 已就位项、最小改名与幂等：
  - 文件已位于本次根下、当前规则对应的目标目录（C-05 的大类/功能分类）内时为已就位项；位于子目录的旧分类结果不算对父根已就位。先按 C-16 应用开启的名称规则，无名称变化、无实际冲突时保持名称与位置，不重新计算前缀或哈希。
  - 名称规范化引入的冲突也是真实冲突，按 C-17 消解；除此之外不为形式统一改名，`客户B_合同.pdf`、`客户C_合同.pdf` 不因 `客户A_合同.pdf` 冲突而改变。已就位优先是冲突分配规则，不是禁用清理的特权。
  - 同一根、同一规则且资料未变时，完整成功整理后再运行，目录层级、文件位置、文件名、Git 项目位置均不变；不得新增来源前缀或替换已有哈希，`x_合同.pdf` 不得变成 `文档_x_合同.pdf`。取消勾选、范围限制或失败造成的未完成项须显示，不用“幂等”禁止后续用户重新纳入处理。

  - 归类移动必须保留创建时间与修改时间（S-01 跨卷复制同口径）；功能分类不读取时间，幂等由相同输入集合产生相同分组与命名保证。

## 3. 数据安全不变量（S）

- **S-01** 所有移动、改名均不得覆盖已有目标。递归解压冲突时只给新文件改名，已有文件不动，仅按本次 X-02 确认和 X-05 成功条件删除原包；目录整理只按用户已确认的计划和 C 分区规则处置文件，不能把整理授权用于解压删除。

  - 普通文件确需跨文件系统移动时，先以不覆盖方式完整复制并成功设置需保留的创建时间及修改时间、关闭输出，再删除源项；复制、写入、关闭或时间设置失败不得删除源项。只清理本次新建且明确拥有的未完成副本，不删除原有目标；源删除失败时两份均保留并报告未完成，不假称移动成功。不要求内容二次哈希或事务回滚；Git 项目跨卷按 C-14 拒绝。

- **S-02** 目录整理的全局文件删除方式只有「保留」和「永久删除」，默认「永久删除」，不提供回收站或降级开关。C-04 的副本处置随该选择分别为「保留副本」或「永久删除副本」；选择保留时，不生成去重删除操作，也不生成跟随全局方式的文件清理删除操作。C-08 各清理项可显式覆盖删除方式，覆盖只作用于对应清理项，不改变副本处置；保留不禁止其余已启用规则的归类或改名。永久删除不可由本软件恢复，两工具的破坏性确认均必须明确告知；删除前满足 S-01 / S-03 等已授权校验，取消后不继续启动删除。递归解压仅按 X-05 永久删除完整成功的原包及分卷，不提供删除选项，不删除无关用户文件；空目录清理另按 C-07 执行，不受保留文件的选择影响。

- **R-04** 整理规则或目录改动后，既有分析结果与执行按钮失效，必须重新分析；不允许用旧计划执行新规则。

## 6. 引擎与发布（E）

- **E-01** 构建所需 7-Zip 引擎只从官方 release 获取，固定版本并校验上游 SHA-256，不使用镜像；引擎可执行文件不进入 git，也不以独立可执行文件形式进入发布包。

- **E-03** 发布包必须保留 `licenses/`、NOTICE 与上游源码压缩包；打包时检查独立引擎可执行文件泄漏，检查不通过不得继续发布。

- **E-04** 发布经手动触发的 CI 工作流产出安装包 EXE 与便携 ZIP 两种产物；打包中未执行的阶段必须如实标注 `NOT RUN`。

- **E-05** 构建机缺引擎时允许构建，只是不内嵌；运行期无引擎时解压必须明确报错并停止，不得静默跳过。引擎只能按 E-02 的顺序获得，不提供用户指定引擎路径的参数。

## 附录 B：名称、比较与扩展名定义（C-02 / C-03 / C-08 / C-16～C-21 / H-07）

### 文件名切分

- 普通扩展名为最后一个点及其后非空部分；点在首位且之后无其他点的名称（如 `.gitignore`）整体为主体，无扩展名。`.DS_Store` 按 C-08 完整名匹配，不依赖扩展名切分。
- `.tar.gz`、`.tar.bz2`、`.tar.xz`、`.tar.zst`、`.tar.lzma`、`.tar.z` 为复合扩展名，整体保留；匹配不区分大小写、输出保留原后缀大小写。其他多点名称只将最后一段视为扩展名，除下条分卷模式外不猜复合后缀。
- X-10 数字尾卷的「白名单扩展名 + `.NNN`」（如 `.7z.001`、`.tar.gz.001`）、part rar 的 `.partN.rar`、老式 `.rNN` / `.zNN` 在改名时均为不可拆分后缀。隔离用 X-10 的整组改名，整理只对每个普通文件主体按 C 规则命名，不改变编号串。
- 项目目录名整体为主体，含点也不拆扩展名；不对 Git 项目名执行文件副本后缀清理或内容签名修正。

### 比较与稳定决胜

- Windows 同名关系使用不依赖界面语言的序数忽略大小写比较（Windows ordinal ignore-case 语义），不是按拼音、自然数字或当前区域排序；操作系统实际报告的目标占用同样必须避开，即使其等价规则更严格。
- 稳定升序：将相对路径的目录分隔符统一 `/`，先按上述忽略大小写的序数比较，仍相同则按原始 UTF-16 单元序列逐单元升序决胜。长度为同样路径表示的 UTF-16 单元数，包括 `/`，不含根路径。保留者使用分析时原路径，不使用将生成的目标名。
- C-02 同名键是原完整文件名的忽略大小写比较键；副本名键按下面副本标记规则剥除后，连同未改变的扩展名一起比较。副本名键只用于候选判定，不能替代 C-08 的输出名，也不决定删除；删除仍以完整内容哈希为依据。

### 副本标记和名称规范化

- 副本标记仅识别主体末尾连续出现的标记序列：ASCII 圆括号包围的一个或多个十进制数字 `(N)`、ASCII 连字符加 `Copy`（忽略大小写）、中文 `副本`。标记前允许零个或多个 ASCII 空格，连字符与 Copy 之间允许零个或多个 ASCII 空格；不把主体中间的同样字串当作后缀。`report(1)`、`report (01)`、`report-Copy`、`report - copy`、`报告副本` 都识别。
- 从右往左收集整段末尾标记，剥除后保留原先从左往右的数字顺序。用于去重名称键时全部标记移除；用于输出名时每个 `(N)` 转为 `_N`，十进制前导零去掉、全零保留 `0`，其他标记移除。已有 `_1` 不视为待剥除副本标记，避免再次整理继续变化。
- 例：`报告 (1) (02).pdf` → `报告_1_2.pdf`；`report - Copy (1).tar.gz` → `report_1.tar.gz`；`报告副本.pdf` → `报告.pdf`；`报告副本说明.pdf` 不因含「副本」改名。`(1).pdf` 的基础主体为空时使用 `_` 作基础主体，得到 `__1.pdf`；不剥掉 `.pdf`。
- NFC / 空白开关开启时，对主体先做 NFC，将 Unicode White_Space 属性中的连续字符压成一个 ASCII 空格，并去除主体首尾空白；再执行开启的副本后缀清理。未开启的规范化不隐式执行；派生结果的合法性检查始终执行。
- 来源目录加入普通文件候选前，也按已开启的 NFC / 空白规则规范化该来源段，但不对来源段剥副本标记、不改源目录。完整候选生成后再按同一输出规则检查至不再变化，然后判定占用与长度，避免下一轮首次清理新加的前缀或因截短暴露的末尾副本标记。项目目录候选仅做必要合法性处理，仍不应用普通文件清理规则。
- 因派生改名产生的主体末尾 ASCII 点或空格去掉；主体空、`.` 或 `..` 时用 `_`。主体中的 Windows 禁用字符 `< > : " / \ | ? *` 及 U+0000～U+001F 替换为 `_`。来源目录拼接后的名称也受此约束，但绝不改写源目录名本身。
- 派生完整名若命中 Windows 设备保留名（含带扩展名形式的 CON、PRN、AUX、NUL、COM1～COM9、LPT1～LPT9 及系统视为等价的设备名），在主体前加 `_`，再验证。原扩展名本身无法合法保留时安全失败，不删除扩展名。合法性变换后重新参加全目标冲突判断；不能把 `_` 当作唯一名称保障。
- 本节输出规则仅适用于目录整理；解压对归档成员的危险或非法原名按 X-08 整包拒绝，不借本节把危险路径“修好后放行”。正常解压目标冲突仍按 H-07 / X-04 仅改主体。

### 内容签名修正扩展名

- 该开关默认关闭，开启后只在分析阶段为非排除、非待删普通文件判型；无需对所有文件计算完整哈希。无法可靠判型不改，错误不可导致删除或猜测性改后缀。
- 本合同要求可确定识别并修正的类型为 PNG、JPEG、GIF、BMP、TIFF、WebP、PDF、FLAC、WAV、ZIP、7z、RAR，以及通过 ZIP 内部类型标识可确认的 DOCX、XLSX、PPTX、DOCM、XLSM、PPTM、ODT、ODS、ODP、EPUB。识别依赖该格式的有效结构与必要类型标识，不能仅凭几个相同开头字节把任意内容认作文件类型。
- 确认类型且现后缀不正确时，采用 `.png`、`.jpg`、`.gif`、`.bmp`、`.tif`、`.webp`、`.pdf`、`.flac`、`.wav`、`.zip`、`.7z`、`.rar` 或对应小写文档扩展名；已有 `.jpeg` / `.jpg`、`.tiff` / `.tif` 均为合法同义形式，不强制改名或统一大小写。
- ZIP 容器必须先区分上述文档类型；不能确认其内部类型时，保留原后缀为 Office、ODF、EPUB 或 X-09 其他已列容器格式的文件，不降级为 `.zip`。未承诺的类型不进行修正，不以模糊特征强行分类。

## 附录 C：扫描排除 glob（S-04 / R-03）

- 输入为分号分隔的模式列表；去掉每段首尾空白，空段忽略，空列表表示不额外排除。各模式为“或”关系，任一命中即排除。
- 匹配对象为相对所选根的路径，统一使用 `/`，无开头 `/`、无结尾 `/`；用户模式中的 `\` 也视为目录分隔符，不作为转义符。按 Windows 序数忽略大小写匹配，不受界面语言影响。
- 模式匹配整个相对路径，不自动匹配任意文件名片段。`*` 为零个或多个字符，可跨 `/`；连续多个星号等同一个星号，`**` 没有独立递归语义。`?` 为恰好一个 Unicode 字符，不能匹配 `/`。除 `*`、`?`、分隔符和分号外均按字面匹配，不支持字符类、花括号展开、正则、否定或反向纳入；例如 `[ab]` 匹配字面 `[ab]`，不是 a 或 b。
- 不支持转义、引号包裹或分号字面匹配；输入含盘符、绝对路径或独立 `..` 路径段时作为无效模式阻止开始，指出错误段，不悄悄忽略。大小写无关不意味着先改写磁盘文件名。
- 目录路径命中时整树排除，不再为统计其后代读取内容；文件路径命中只排除该文件。目录后代即使没有逐个匹配，也不再纳入。Git 保护、链接边界、Windows 系统目录和隔离容器先于 glob，不存在用模式重新纳入的办法。

|模式|匹配结果|
|---|---|
|`*.tmp`|根及任意层级以 `.tmp` 结尾的路径；若命中目录则排除整树|
|`cache`|根直接子项 cache；若为目录则整树排除，不匹配 `a/cache`|
|`*/cache`|任意非根直接层级的 cache 项，如 `a/cache`、`a/b/cache`|
|`cache;*/cache`|根直接层级及深层的 cache 目录均可排除|
|`a/?.txt`|`a/x.txt`，不匹配 `a/xy.txt` 或 `a/b/x.txt`|

隐藏和系统属性开关是两个独立的包含开关，均默认开；某项具有任一被关闭包含的属性就排除。目录被属性排除时后代整树排除，不因后代属性不同重新纳入；必要 Git 边界检查仍在排除前进行。排除是范围限制，不是执行失败；界面同时显示限制与处理结果，不能把“范围内完成”写成“全部目录均已处理”。
