# JchTools 需求合同（CONTRACT）

> 本文档是用户需求的权威载体，只定义软件必须满足的行为，不记录实现进度或验收结果。开发、测试和提交纪律由 `AGENTS.md` 规定。
>
> 本版本整合用户截至 2026-09-22 在本次会话中确认的需求。最高优先级需求 H 高于其他分区的具体约定及历史表述；其余分区冲突时，数据安全不变量 S 优先。与本版本相反的历史要求不再适用。
>
> 保留既有条目编号；需求的增改、拆分、合并和重编号须经用户确认。代码与合同不一致时，不得为迁就代码而擅自改写需求。

## 最高优先级需求（H）

- **H-01** 个人工具，性能优先：JchTools 用于用户个人资料整理，处理性能是首要要求。避免无必要的重复扫描、重复读取文件内容、重复计算和复制；不为企业级、多人协作、处理期间外部改动等非目标场景增加负担。性能优化不得通过漏处理、错误删除或暗中缩小处理范围来实现。

- **H-02** 易用与流畅优先：界面方便好用、操作流畅是首要体验要求。扫描、解压、哈希和整理期间界面必须保持响应，处理状态可见、取消入口可用；常用操作直接可达，低频配置不妨碍日常使用。不以阻塞界面换取后台吞吐，不为方便而强制用户执行另一个工具。

- **H-03** 两个独立工具：保留「递归解压」和「目录整理」两个独立、正常可见的工具入口。用户可以只递归解压并按 X-05 清理成功原包，结束后不得自动进行目录整理的去重、归类或清理；目录整理也不得自动解压。需要完整整理时，由用户先使用递归解压工具，再使用目录整理。「先解压、后整理」是使用顺序，不是统一入口、自动串联或将独立工具降为低频入口的要求。

- **H-04** 递归解压结果：在明确的处理范围内，X-01 白名单内、能够由捆绑引擎成功解开的压缩包及本次解出的嵌套压缩包都应完成解压；H-06 排除的目录树除外，白名单外的容器（X-09）不被解压、也不计为未完成。每个包完整成功后按 X-05 永久删除原包及其分卷，不把删除职责留给目录整理。确实无法解开的包保留并说明原因；取消、空间不足、防护上限或范围限制导致内容未解开时，不得宣称已全部解压。同次任务中已处理的包不得反复入队；目录整理不承担补做解压或无条件删除压缩包的职责。

- **H-05** 整理后没有空目录：目录整理成功完成后，处理范围内除用户选定的根目录外，不得残留空目录，包括解压、去重、归类、删除后新产生的空目录。自底向上清理实际为空的目录及空目录链，不得递归删除有内容的目录；H-06 排除的目录树不参与清理。取消或清理失败时如实显示未完成，不得为了清空目录而在取消后继续删除。本条属于目录整理，不要求仅使用递归解压时额外清理目录。

- **H-06** Git 目录整树忽略：任一目录直接含有名为 `.git` 的目录或文件时（一个 Git 项目取其最外层，内部再出现的 `.git` 不单独划分项目），该目录及全部后代整树排除：不解压、不读取内容参与哈希或去重、不改名、不删除、不清理内部空目录。唯一例外是目录整理的归类——整个项目目录作为一个整体移入「Git项目集合」目录，除此之外不进入树内做任何处理（去重、附属文件清理、改名、空目录清理、解压都不进行），见 C-14。只允许为识别边界进行必要的目录项检查，识别后不继续遍历内部；除该整体归类移动外，不得通过移动、改名或删除祖先目录间接改变该树。该排除不受隐藏文件、递归或清理开关影响，不提供关闭选项，整体归类移动同样是固定行为、无开关。选定根目录直接含 `.git` 时，整次处理不执行并明确提示；只有子目录含 `.git` 时，只排除该子树。新解出的目录含 `.git` 时，后续处理同样排除；界面明确提示 Git 目录的处置结果。

- **H-07** 递归解压不去重、不删除无关文件：只允许按 X-05 永久删除完整成功解开的源压缩包及其实际分卷，不得删除既有用户文件或已落盘的普通解压结果，不得以内容相同为由跳过正常落盘。目标冲突时保留已有文件，只为新解出的文件自动选择未占用的文件名，不覆盖、不淘汰、不询问冲突策略。只改文件名主体，原扩展名及复合扩展名保持不变，例如 `资料.txt` → `资料 (1).txt`、`资料.tar.gz` → `资料 (1).tar.gz`；不得通过更换或追加扩展名规避冲突。工具自身临时工作区只按本次所有权标记清理，不得删除用户目录。目录整理的去重、删除职责不受本条取消。

- **H-08** 完全不考虑无障碍：本项目不提出无障碍需求，不为屏幕阅读器、辅助技术、无障碍元数据、专门的键盘遍历或焦点规范进行开发、维护、测试和验收。不得以无障碍合规为由增加功能、复杂度或验收门槛；普通鼠标和键盘操作仍按 H-02 的方便好用要求处理。

## 0. 产品定位（P）

- **P-01** JchTools 是用户个人使用的 Windows 本地工具箱；「递归解压」「目录整理」是工具名称，不得用作产品名。

- **P-02** 工具经统一注册表（id / 名称 / 类别 / 摘要）接入，侧栏导航遍历注册表，不设空占位分类。当前两个工具为递归解压（文件类）和目录整理（文件类），均按 H-03 独立启动。

- **P-03** 离线处理：所有文件处理功能离线可用，程序自身不得发起网络请求，不得上传文件、日志或路径。用户主动点击关于页官网链接时，允许交由系统浏览器打开，不附加用户文件、路径或日志信息；该例外不允许后台联网或自动打开网页。

- **P-04** 界面中文；浅色、深色主题默认跟随系统，可在「关于」页切换；颜色使用统一设计令牌。

- **P-05** 个人使用交付，两种形态并列：安装包安装到当前用户目录，不要求管理员权限或 UAC，默认创建桌面快捷方式、开始菜单入口及系统卸载项；同时提供便携 ZIP。不要求代码签名与公开分发验收。

- **P-06** 不提供命令行界面，全部用户操作经图形界面完成；不提供整理报告及任何形式的报告或日志导出，包括 CSV。

- **P-07** 平台支持范围仅为 Windows；构建、测试、验证和 CI 只在 Windows 上运行，不为其他平台维护测试入口、验证阶段或流水线 job。

- **P-08** 不防御处理期间的外部改动：扫描、分析、执行全程假定文件与目录不被其他程序修改、删除、改名或替换，不为此做变化检测、二次快照比对、冲突重算或并发保护。发生此类外部改动时结果不作保证，该情形不计入需求范围；本条不取消不覆盖移动、路径边界检查或程序自身必要的同步。

## 1. 递归解压（X）

本工具只做递归解压及成功原包清理，保持已有文件，不自动启动目录整理。

- **X-01** 只解压并按 X-05 清理成功原包，不去重、不删除无关用户文件、不归类、不做垃圾清理；不得为了跨目录去重或同名冲突裁决额外计算内容哈希或逐字节比较内容。自动解压只认用户意义上的归档文件，判断依据是扩展名白名单而不是引擎能否打开。白名单为 `.zip`、`.7z`、`.rar`、`.tar`、`.gz`、`.bz2`、`.xz`、`.zst`、`.lzma`、`.z`、`.tgz`、`.tbz2`、`.txz`、`.tzst`。压缩流条目（`.gz`、`.bz2`、`.xz`、`.zst`、`.lzma`、`.z`）前面允许再带一层 `.tar`（`.tar.gz`、`.tar.zst` 等），整体作为一个包处理，`.tgz` / `.tbz2` / `.txz` / `.tzst` 是这类组合的别名。扩展名匹配不区分大小写；复合扩展名按整体识别，不拆成两个包、不单独计数，中间层不留在正式位置。单文件压缩流按包内记录的成员名落盘，包内没有成员名时用去掉压缩扩展名后的文件名（`资料.txt.gz` → `资料.txt`、`备份.gz` → `备份`），冲突按 H-07 自动改名。包与分卷的范围见 X-10；白名单之外一律不碰，见 X-09。

- **X-02** 流程为一段确认：选目录 → 可选调整规则 → 点击「开始解压」→ 一次确认 → 连续解压至结束。确认说明发现的压缩包数量（限 X-01 白名单）、就地解压去向、完整成功后原包及分卷永久删除且不可恢复、已有文件保留、冲突自动改文件名且不改后缀、无法解开的包保留并记录原因。无计划审核环节，不提供删除方式或冲突策略选项。

- **X-03** 就地解压：每个压缩包解到其所在位置，不集中到统一输出目录。

- **X-04** 目标冲突固定按 H-07 自动改名：已有文件不动，新文件选择未占用的文件名，保持扩展名。即使内容相同也不得跳过新文件落盘，不按时间、大小或内容淘汰文件。不提供覆盖、跳过、保留较新、保留较大或逐次询问的冲突选项；自动改名属于正常成功结果。

- **X-05** 只有整包解码与校验成功、全部成员完整落盘后，才永久删除该原压缩包及其实际分卷；空包同样适用，嵌套包逐包判定。不经回收站，不受目录整理的全局删除方式影响；不得误删仅同主干但不属于该包的文件。失败、部分解开或取消时不启动原包删除；删除前检查取消，删除失败必须报错并保留未删除的原包或分卷，不把清理失败当成坏包隔离或报告全部成功。不承诺多卷删除事务回滚。

- **X-06** 损坏、加密、引擎不支持、分卷不全、触发防护上限或含危险条目等未能完全解开的包，移入所选目录根下的「解压失败」子目录，不删除；移动不覆盖已有文件，遇冲突保持扩展名自动改名。逐包记录原因，界面可查；隔离不等于完成解压。空间不足或用户取消不作为包损坏隔离，保留当前源包并停止本次解压任务。

- **X-07** 同次任务内避免重复处理已经处理的包；用户再次启动解压属于新任务，成功删除的原包不再重复解压。对仍在处理范围内的包不增加跨运行内容比较或按历史成功记录自动跳过的机制；已有解压结果冲突仍自动改名。默认跳过「解压失败」目录内已记录的失败包，用户补救并移出后下次自然重试；跳过及未完成事项必须明确可见。目录整理仍遵守 C-10 的幂等要求。

- **X-08** 解压防护与取消规则：
  - 继续解开嵌套压缩包，最大嵌套层数默认 16，可在规则面板调整；触及上限的包移入「解压失败」并说明未完成原因。
  - 单包条目数上限默认 100 万；最大展开比例为解出体积除以包体积，默认 10000，0 为关闭；分卷包体积按实际卷集合合计。
  - 单包与单文件展开体积默认不限，支持 TB 级资料。解压前及运行中检查磁盘剩余空间，预留默认 1 GiB，可调；不足时保留当前源包、报错并停止整个解压任务，不继续批量隔离后续正常包。
  - 路径穿越、绝对路径、符号链接条目、加密条目及无法解码的文件名必须拒绝或跳过，不得写入磁盘。
  - 先解到同卷、独立且带随机所有权标记的临时工作区；整包解码与校验成功后，以不覆盖方式合入正式位置。冲突只自动改名，不存在先删除旧目标再替换的步骤。
  - 取消在文件操作安全边界生效，不启动后续成员合入或源包删除；已落盘结果与尚未删除的原包或分卷保留，明确提示部分结果已处理。不承诺整包事务原子性或回滚；崩溃、强制中断不得报告为成功。
  - 只按本次所有权标记清理临时工作区，不递归删除用户目录或已落盘结果。

- **X-09** 白名单之外的文件完全不碰：安装资源 `.cab`，安装包 `.msi` / `.msix` / `.appx` / `.msixbundle` / `.appxbundle`，磁盘与系统镜像 `.iso` / `.img` / `.wim` / `.esd` / `.vhd` / `.vhdx`，程序与扩展包 `.jar` / `.war` / `.ear` / `.apk` / `.aab` / `.whl` / `.nupkg` / `.vsix` / `.crx` / `.xpi` / `.ipa` / `.pkg` / `.dmg`，文档与电子书容器 `.docx` / `.xlsx` / `.pptx` / `.docm` / `.xlsm` / `.pptm` / `.odt` / `.ods` / `.odp` / `.epub`，`.lz4` / `.br` / `.lz`（引擎没有对应解码器的流格式），以及 `.exe` / `.com` 等可执行与自解压文件——即使 7-Zip 能打开也不解压、不改名、不移动、不删除，不进入「解压失败」，不计入确认框的压缩包数量；它们仍作为普通文件参与目录整理。白名单外格式的分卷（`.iso.001`、`.docx.001` 等）以及无法由命名指认出白名单格式的孤立编号文件（如 `data.001`）同样完全不碰：不解压、不改名、不移动、不删除、不进入「解压失败」，不计入确认框的压缩包数量。

- **X-10** 包与分卷：一个包 = 主包文件 + 属于它的卷集。卷集是与主包同目录、同主干、编号连续的一组分卷文件，命名模式为「主包完整名 + `.NNN`」（`.7z.001`、`.zip.001`）、「主干 + `.partN.rar`」（`.part1.rar`）、老式 rar 的 `.rNN`（`.r00` 起）、老式 zip 的 `.zNN`（`.z01` 起，配 `.zip` 主包）。卷不是独立解压对象：不单独入队、不单独计入确认框的压缩包数量、不单独判定成功或失败，一组卷集只算一个包；`.7z.001` / `.part1.rar` 这类集合以编号最小的卷为包入口，存在 `.zip` / `.rar` 主包文件时以主包为入口。X-05 的删除、X-06 的隔离与「分卷不全」判定都以整包（主包 + 实际卷集）为单位，卷集是否完整以引擎解压结果为准。白名单之外的卷见 X-09。

## 2. 目录整理（C）

本工具只做去重、归类和清理；需要解压时由用户先使用递归解压工具，不自动调用解压。

- **C-01** 独立两段式流程：选目录 → 可选调整规则 → 分析 → 分页计划（逐项可勾选或取消）→ 确认执行。分析只读扫描与计算，不改动待整理资料；用户确认后才执行去重、归类和清理。

- **C-02** 去重名称关系分三类：同名与副本名默认参与，不同名默认关闭、可手动开启；副本名包括 `(1)` / `- Copy` / `副本` 后缀。只有整文件哈希一致才判定内容重复；删除前不得逐字节复核或做任何二次内容比对。同名但内容不同的文件不得自动淘汰，也不提供此类开关。

- **C-03** 重复组默认保留修改时间最新者；修改时间相同时，按相对路径长度、再按路径字典序稳定决胜。

- **C-04** 其余副本默认永久删除；可选同卷硬链接模式，必须先成功建立链接，再处理原副本，跨卷或不支持时在删除原文件前安全失败。可靠文件标识证明两个路径已指向同一个物理文件时，不再作为独立副本执行去重删除或重复建链；标识无效、退化时不得据此跳过去重，也不得额外读取内容进行二次复核。

- **C-05** 归类默认按大类（视频、文档、图片等，未匹配入「其他」），大类之下再按修改日期分「年/月」子目录；可选按扩展名、按修改日期（年/月）、按自定义扩展名规则或不归类。分类目录默认建在所选根目录下，可选统一输出目录；默认不保留原相对路径（文件直接落到大类/年/月层级），可选保留原相对路径，同名自动改名。重复执行幂等：已在正确分类位置的项原地保留，不得在原位置之上再叠一层相同的大类/年/月路径；分类目录不得嵌套自身。标准结果形态见 C-15。

- **C-06** 归类附加项默认全部关闭：大文件单独归类（默认阈值 1 GiB）、合并不同位置的同名目录、消除只有一个子项的目录层级。启用这些选项也不得破坏 C-05 的幂等与不自嵌套要求，或改变 H-06 的 Git 排除树。

- **C-07** 整理成功完成前必须按 H-05 自底向上清理实际空目录及空目录链，包括本次操作新产生的空目录；保留选定根目录和 Git 排除树，不递归删除有内容的目录。不提供关闭这一步的选项；用户取消时停止后续删除，如实报告未完成。仅运行递归解压时不执行此项整理清理。

- **C-08** 清理与文件名规则：
  - 系统附属文件清理默认开：Thumbs.db / .DS_Store / desktop.ini / __MACOSX / ._*。
  - 临时与备份清理默认关：.tmp / .temp / .bak / Office ~$。
  - 零字节文件清理默认关。
  - 副本后缀清理默认开：识别 `(1)` / `- Copy` / `副本`（含紧贴文件名的中文「副本」），`(N)` 的序号并入文件主体为 `_N`（`report (1).pdf` → `report_1.pdf`），其余形式直接移除后缀，扩展名保持不变；不限于去重后的保留者。
  - 文件名 NFC 规范化及合并连续空白默认开，不删除正常字符。
  - 按内容签名修正错误扩展名默认关，改名必须列入计划。签名不足以确定实际类型时不改名；合法的同义扩展名不强制统一；不能仅因识别到 ZIP 等外层容器，就把 Office 文档或其他容器格式文件改成压缩包后缀。此功能仅属于目录整理，不改变递归解压保留扩展名的要求。
  - 上述各项独立启停；涉及删除的项目可独立覆盖删除方式，默认跟随全局文件删除方式。

- **C-09** 「解压失败」目录中的失败包默认不参与去重、归类或文件清理，明确提示已跳过；该目录及其子目录实际为空时仍按 H-05 清理。不得把失败隔离当成已完成解压；Git 整树排除始终优先。

- **C-10** 成功完成整理后，相同规则再次整理结果幂等；用户手动改动资料、规则切换，或上次取消、失败留下未完成项时，可以重新分析产生新计划。规则或目录改变后，原计划和执行入口失效，必须重新分析。不做处理期外部变化检测，执行按分析记录进行，不得覆盖目标。用户取消不算失败、不报错，在安全边界生效；不实现断点恢复或任务重放，重新运行属于重新分析的新任务。

- **C-11** 任务状态（分析中、计划就绪、执行中、完成、失败、已取消）和计划行状态（待执行、已执行、已跳过、已取消勾选、执行失败）以中文如实显示；取消勾选后即时显示对应状态，重新勾选恢复待执行。仅计划就绪的任务可执行；翻页按钮仅在对应页真实存在时可用，切换类型筛选回到第一页。

- **C-12** 本次整理中，每个需要哈希的文件至多计算一次完整内容哈希，命中 C-13 缓存时可不计算；不做两阶段筛选哈希、采样哈希或二次哈希。候选仅由扫描获得的大小和名称关系决定，整文件哈希一次遍历完成。同尺寸是内容相同的必要条件，不得缩小 C-02 的检出范围。执行阶段不读取用户文件内容进行哈希、采样或内容复核；允许执行计划所需的移动、改名、删除、硬链接及必要的目录项、元数据操作。清理空目录必须检查是否实际为空，但不得借此恢复 P-08 排除的外部变化检测。

- **C-13** 状态目录维护跨运行哈希缓存，以文件标识、大小、修改时间为匹配依据。三者均一致时可复用上次整文件哈希，任一不同或无记录时完整重算；信任三者未变即内容未变，不防御保留时间戳修改内容的行为。文件标识退化、无法区分不同文件时不得复用。缓存只是加速，不改变去重依据或候选范围；不存在、不可读、读写失败时自动降级为正常完整哈希计算，不因缓存故障中止整理或跳过候选，也不要求用户手动修复缓存才能继续使用。

- **C-14** Git项目集合归类：归类开启时（C-05 不是「不归类」），处理范围内每个 Git 项目（定义见 H-06）整体移入本次所选根目录下的「Git项目集合」目录，不参与大类、扩展名、日期或自定义规则的逐文件归类。项目平铺在集合目录下、目录名保持不变、不保留原相对路径（`a/b/code/project-alpha` → `a/Git项目集合/project-alpha`），同名冲突按 C-05 自动改名整个项目目录。是否「已归类」只看项目是否位于本次所选根目录的「Git项目集合」下：`a/b` 单独整理后落在 `a/b/Git项目集合` 的项目，整理 `a` 时会再次移动、聚合到 `a/Git项目集合`，原目录变空后按 C-07 消失；已在本次根目录集合下的项目不再移动，保证 C-10 幂等、集合目录不自嵌套。项目只做整树平移：内部一个字节都不改写，解压、哈希去重、清理、改名、空目录清理都不进入树内。归类为「不归类」时不做任何移动，仍按 H-06 整树排除。

- **C-15** 归类结果的标准形态（默认配置）：目录层级为「大类 → 年 → 月 → 文件名」，Git 项目统一平铺在所选根目录的「Git项目集合」下。先整理子目录、再整理父目录时，子目录里已生成的分类目录与项目集合必须重组进父目录的标准形态，被搬空的原始中间目录（含上一级整理留下的分类目录与项目集合）按 C-07 全部消失；不得残留中间目录，不得重复叠加层级，也不得让集合目录自嵌套。完整示例如下。

## 3. 数据安全不变量（S）

本分区服从 H；其余具体条款冲突时，本分区优先，不扩张到非目标场景的额外防御。

- **S-01** 所有移动、改名均不得覆盖已有目标。递归解压冲突时只给新文件改名，已有文件不动，仅按本次 X-02 确认和 X-05 成功条件删除原包；目录整理只按用户已确认的计划和 C 分区规则处置文件，不能把整理授权用于解压删除。

- **S-02** 目录整理的文件删除方式只有「保留」和「永久删除」，不提供回收站或降级开关。永久删除不可由本软件恢复，两工具的破坏性确认均必须明确告知；删除前满足 S-01 / S-03 等已授权校验，取消后不继续启动删除。递归解压仅按 X-05 永久删除完整成功的原包及分卷，不提供删除选项，不删除无关用户文件；空目录清理另按 C-07 执行。

- **S-03** 内容去重以整文件哈希一致为依据，删除前不得重读文件内容逐字节复核或进行其他二次内容比对。

- **S-04** 两个工具扫描时先识别并排除 Git 目录树；默认不跟随符号链接、junction 或 reparse point，避免循环或逃出所选目录。默认覆盖所选目录内的资料，包括隐藏或系统属性的资料，不因普通目录名自动漏处理；保留用户显式调整的隐藏、系统属性开关及分号分隔 glob 排除规则（`*` 可跨多层），缩小范围时明确提示。Git 排除不受开关影响；无法读取或处理的条目如实说明，不静默跳过后宣称全部完成。

- **S-05** 不自动提权，不清除只读属性；始终拒绝整理 Windows 安装目录，不提供放开此限制的开关。

- **S-06** 整理摘要按逻辑大小报告已永久删除的项，不声称等于文件系统实际释放量；已可靠识别为同一个物理文件的硬链接，不重复计入可删除或已删除的数据量，跳过的项不得计为实际删除。

- **S-07** 不实现备份、事务回滚、断点恢复或任务重放。运行日志仅供界面审计，显示最近 300 条、最新在上，不提供导出。

- **S-08** 「最新」一律指修改时间（mtime），目录整理去重的平局规则见 C-03。递归解压不按时间或大小选择保留者，冲突一律自动改名新文件。

## 4. 规则面板（R）

- **R-01** 按当前工具显示相关分区：递归解压显示解压及安全性能项；目录整理显示去重、归类、清理及安全性能项。低频规则默认折叠进高级选项，默认配置直接可用。用户偏好仅会话内生效，不自动保存或恢复上次规则，无独立设置页和规则导入导出；允许任务库保存本次规则快照供计划一致性与审计使用，不作为下次任务的用户偏好。

- **R-02** 递归解压固定为完整成功后永久删除原包及实际分卷、既有文件保留、冲突只改新文件名且保留扩展名，不提供去重、覆盖淘汰、原包删除方式或逐次询问冲突的选项。目录整理保留：三类去重独立启停；保留者选择最新、最旧、最大、最小或最短名称；重复处置选择删除或同卷硬链接；C-05 分类方式；C-08 六类独立开关。默认值按对应 C 条目执行，不提供关闭最终空目录清理或关闭 Git项目集合归类（C-14）的选项，也不提供把 Git 树内部纳入解压、去重、清理或改名的选项。

- **R-03** 两个工具默认递归包含处理范围内全部子目录，用户可主动关闭递归，界面明确提示范围缩小；始终应用 Git 排除。哈希并行线程 1–16 可配，默认 6，机械盘建议 1；磁盘预留默认 1 GiB 可调。性能实现满足 H-01 / H-02，不以阻塞界面换取吞吐。

- **R-04** 整理规则或目录改动后，既有分析结果与执行按钮失效，必须重新分析；不允许用旧计划执行新规则。

## 5. 界面与交互（U）

- **U-01** 自绘无边框标题栏，可拖动，双击切换最大化；右上提供最小化、最大化或还原、关闭。启动居中、不默认最大化；默认 1120×720，最小 960×620。

- **U-02** 同类控件全软件复用：面板切换使用下划线页签 Tab，规则分区使用实心胶囊 Pill，窗口按钮使用 CaptionButton，进度使用 ProgressBar，不另造同类控件。

- **U-03** 总量已知时显示百分比、进度条和计数；总量未知的扫描、哈希、解压阶段显示不确定光带与实时文件数、读取量或速度，不编造百分比；空闲隐藏进度。

- **U-04** 完全不考虑无障碍（H-08）：不要求控件声明无障碍角色或标签，不要求为无障碍建立 Tab 遍历、焦点框、屏幕阅读器或辅助技术支持，不设置相关开发、维护或验收要求。普通输入、点击及必要的键盘操作仍须方便好用。

- **U-05** 布局随窗口缩放自适应，常见尺寸内不裁切、不重叠、不溢出。默认尺寸且没有提示条时，「处理规则」同屏可见 9 行；有提示条时允许减少，列表可滚动。

- **U-06** 信息使用蓝色提示条，错误使用红色提示条，均可分别关闭；用户主动取消不得显示为错误。

- **U-07** 选择目录对话框从当前已输入目录开始，不无故回到其他位置。

- **U-08** 使用 PerMonitorV2 DPI manifest；图形驱动异常时，可通过 `launch-software.cmd` 请求软件渲染。

- **U-09** 运行中关闭窗口必须弹出「停止任务并关闭」确认，始终位于其他弹窗之上。

- **U-10** 运行日志最新在上，界面仅保留最近 300 条，不提供导出。

- **U-11** 切换工具时，共用界面状态不得串用：面板页签回到该工具默认的「处理规则」，不得停留在该工具不存在的面板上。

## 6. 引擎与发布（E）

- **E-01** 构建所需 7-Zip 引擎只从官方 release 获取，固定版本并校验上游 SHA-256，不使用镜像；引擎可执行文件不进入 git，也不以独立可执行文件形式进入发布包。

- **E-02** 运行期引擎解析顺序固定：EXE 同目录的 `resources/7zip` → 已释放的内嵌副本 → 从 EXE 释放。逐文件校验后才使用，已存在文件不自动覆盖，保留引擎可替换性。

- **E-03** 发布包必须保留 `licenses/`、NOTICE 与上游源码压缩包；打包时检查独立引擎可执行文件泄漏，检查不通过不得继续发布。

- **E-04** 发布经手动触发的 CI 工作流产出安装包 EXE 与便携 ZIP 两种产物；打包中未执行的阶段必须如实标注 `NOT RUN`。

- **E-05** 构建机缺引擎时允许构建，只是不内嵌；运行期无引擎时解压必须明确报错并停止，不得静默跳过。引擎只能按 E-02 的顺序获得，不提供用户指定引擎路径的参数。
